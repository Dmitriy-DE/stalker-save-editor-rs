# ACCEPTANCE.md — спецификация приёмки переписывания S.T.A.L.K.E.R. Save Editor (C# 1.3.1 → Rust)

Источник: исходники интерфейса C# 1.3.1 (`Views/*.cs`, `ViewModels/*.cs`, `MainWindow*.cs`, `Services/*.cs`, `Styles/StalkerTheme.cs`, `i18n/ru.json`). Ядро (`StalkerSaveEditor.Core`: `EditService`, `LocalSaveReplacement`, `LocalSaveStorage`, `DraftStore`, `GameFixEngine`, `CompanionService`, Steam-адаптеры, апдейтер) в архив не входит. Всё, что происходит внутри ядра, помечено **«не определено из исходников»**.

---

## 0. Соглашения

### 0.1 Откуда брать «точный текст»

1. Ключ перевода — сам русский текст из вызова `L.T("…")`. Этот текст и есть эталон для русского интерфейса.
2. **`ru.json` в русском режиме не применяется.** `I18nService.TrIn` открывает каталог только для языка, отличного от `ru`. Поэтому в русском интерфейсе показывается ключ: «ДОКТОР ИГРЫ», а не «Доктор игры» из `ru.json`. Для приёмки русской версии эталон — ключ. Если Rust-версия применит `ru.json`, это **изменение поведения**, и его нужно согласовать отдельно.
3. Для остальных языков порядок такой: каталог языка, затем `en`, затем русский ключ. Плейсхолдеры `{0}` подставляются после перевода (`string.Format`, InvariantCulture).
4. Язык при старте выбирается так: `settings.json → language`, затем переменная `STALKER_EDITOR_LANG`, затем язык системы. Если язык системы не поддерживается — **`en`**, а не `ru`.
5. Поддерживаемые языки: ru, uk, en, de, fr, it, es, pl, cs, pt-BR, tr, ja, ko, zh-CN, zh-TW.
6. Кнопки показывают текст как есть, без смены регистра. Заголовки карточек (`StalkerTheme.Card`) выводятся как `[ ЗАГОЛОВОК ]` в верхнем регистре (`ToUpperInvariant`). Например, `Card(…, "Баланс сохранения")` даёт `[ БАЛАНС СОХРАНЕНИЯ ]`.

### 0.2 Общие правила поведения

- **Асинхронные команды** (`RelayCommand(Func<Task>)`) блокируют свою кнопку, пока выполняются. Повторный запуск невозможен. Исключение внутри команды пишется в журнал (`AppLog.Error("command failed")`) и **не показывается** пользователю, если сама команда не выставила статус.
- **Подсказки (ToolTip)** у неактивных элементов содержат причину недоступности. Тексты причин перечислены в разделах экранов.
- **Горячие клавиши.** Глобально действуют только сочетания из §1.6. Других `KeyBinding`, обработчиков `KeyDown`, `TabIndex`, `IsDefault`/`IsCancel` и явной установки фокуса в коде нет. Порядок Tab соответствует порядку построения элементов (поведение Avalonia по умолчанию). Это относится ко всем экранам: в разделах «Горячие клавиши и фокус» указаны только отличия.
- **Веб-сборка** (`HostPlatform.IsBrowser`) — отдельный режим. Где он отличается, это отмечено. Основная цель приёмки — десктоп.
- Режим «скриншот/тест» (`InteractiveApp == false`) в приёмку не входит.

## 1. Оболочка (MainWindow) и мастер первого запуска

**Назначение:** окно приложения, в котором собраны навигация, библиотека сейвов, рабочая область, глобальные действия над черновиком и строка состояния.

### 1.1 Окно

- Заголовок окна: `S.T.A.L.K.E.R. Save Editor`. Минимальный размер 940×600.
- При открытии окно занимает 94 % ширины и 92 % высоты рабочей области экрана и центрируется.
- Автомасштаб интерфейса зависит от ширины экрана в DIP: ≥3400 → 175 %, ≥2500 → 150 %, ≥1800 → 125 %, иначе 100 %.
- Сетка окна, сверху вниз: верхняя панель; полоса баннеров; средняя часть (навигация | библиотека сейвов | рабочая область); строка состояния.

### 1.2 Верхняя панель

| Элемент | Текст | Активен / виден |
|---|---|---|
| Заголовок | `S.T.A.L.K.E.R. SAVE EDITOR` | всегда |
| Бейдж издания | название игры выбранного сейва, иначе `X-Ray / S2` | скрыт, если ширина панели < 1000 |
| Кнопка | `Отменить` | `CanUndo` (в черновике есть шаг назад) |
| Кнопка | `Вернуть` | `CanRedo` |
| Кнопка | `Сбросить` | `HasDraftChanges` |
| Кнопка | `Открыть…` | всегда |
| Кнопка | `Обновить` | пока не идёт предыдущее обновление |
| Кнопка (основная) | `СОХРАНИТЬ` | `CanSave`; подсказка — `SaveDisabledReason` |

Пока идёт запись сейва (`IsSaving`), вся верхняя панель, библиотека и рабочая область неактивны.

**Подсказка кнопки `СОХРАНИТЬ` (`SaveDisabledReason`)**, проверяется по порядку:

1. Нет сейва → `Выберите сохранение для редактирования.`
2. В черновике есть правки из другой версии редактора → `В черновике есть правки из другой версии редактора, которые эта версия не понимает. Сбросьте черновик, чтобы продолжить (он сохранится рядом).`
3. Формат не позволяет такие правки → `Эта правка для формата {0} не поддерживается (см. «Возможности»).` ({0} — название игры)
4. Нет изменений → `Нет несохранённых изменений.`
5. Неверные числа → `Введены некорректные значения (проверьте введённые числа).`
6. Иначе → `Сохранить изменения в файл сейва (с созданием резервной копии).`

**Действия:**

- **Отменить / Вернуть** — переход по журналу черновика. Каждый шаг сразу записывается в хранилище черновиков на диске (`DraftStore.Save`, путь не определён из исходников). Подтверждения нет.
- **Сбросить** — без подтверждения.
  - Если в журнале есть правки, которые эта версия не понимает, черновик **откладывается рядом** (`DraftStore.SetAside`). Иначе он удаляется (`DraftStore.Remove`).
  - Поля возвращаются к значениям файла. Статус: `Черновик сброшен.`
- **Открыть…** — системный диалог `Открыть сохранение`, можно выбрать несколько файлов, фильтра нет.
  - Каждый файл разбирается в фоне. Ограничения: размер > 0 и ≤ 512 МиБ; в вебе дополнительно ≤ 256 МиБ при импорте.
  - Успех: файл добавляется в библиотеку (или заменяет запись с тем же путём) и становится выбранным.
  - Не сейв или повреждён → статус `«{0}» — не сохранение S.T.A.L.K.E.R. или файл повреждён.`
  - Ошибка ввода-вывода → `Не удалось открыть «{0}»: {1}`
  - Веб: файл копируется в `/tmp/saves/<guid12>/<имя>`.
- **Обновить** — повторное чтение папок сейвов (§1.5).
- **СОХРАНИТЬ** (то же, что Ctrl+S). Подтверждения нет.
  - Проверки до записи: `CanSave` — сейв выбран, запись не идёт, нет непонятых правок, формат разрешает **все** виды правок плана, есть изменения, ввод корректен.
  - В фоне выполняется одна транзакция: проверка черновика на непонятые правки (если есть — исключение «discard it first»); чтение файла; `EditService.PrepareEdit`; `LocalSaveReplacement.ReplaceLocal` (бэкап с журналом в папку бэкапов, атомарная замена, обратное чтение с `VerifyReadBack` по плану); удаление черновика; повторное чтение и сверка SHA-256 с квитанцией.
  - Во время записи статус `Сохранение…`.
  - Успех: `Сохранено успешно. Backup: {0}` (имя файла бэкапа), звук сохранения, обновление списка бэкапов. В вебе файл предлагается для скачивания; если скачивание не началось: `Сохранено, но скачивание не началось: ` + сообщение.
  - Ошибка: `Не удалось сохранить: {0}` (сообщение исключения, в том числе английское из ядра), звук ошибки.

### 1.3 Полоса баннеров (сверху вниз)

1. **Уведомление об отчётах** (кроме веба). Видно, пока в настройках не отмечено `reports_notice_shown`.
   - Текст: `Редактор раз в сутки и после сбоя отправляет разработчику журнал работы, чтобы находить ошибки. Пути, имена и Steam ID из него вырезаются, сейвы не отправляются. Отключить можно здесь или в Настройках → Диагностика.`
   - Кнопка `Понятно`: отправка остаётся включённой, флаг записывается в `settings.json`, затем проверяется, не пора ли отправить отчёт.
   - Кнопка `Не отправлять`: отправка выключается, флаг записывается в `settings.json`.
2. **Сбой прошлого запуска.** Виден, если есть отчёт о сбое (`CrashReporter.Pending()`).
   - Текст: `Прошлый запуск завершился ошибкой — отчёт в Настройках → Диагностика.`
   - Кнопка `Открыть` ведёт на экран «Настройки», который открывается на разделе `ОБЩИЕ`, а не на диагностике (см. §24).
3. **Доступно обновление.** Видно после проверки, нашедшей новую версию.
   - Текст: `Доступна новая версия приложения ({0})!` или `Доступна новая версия приложения!`, если номер версии пуст.
   - Кнопка `Посмотреть` открывает экран «Обновления».
   - Кнопка `×` скрывает баннер до следующей проверки.
4. **Файл изменён на диске.** Расположен над рабочей областью. Виден, если у выбранного сейва изменились размер или время модификации (проверка раз в 3 с, кроме момента записи).
   - Текст: `Файл сейва изменился после открытия (игра или другая программа). Несохранённые правки относятся к старой версии.`
   - Кнопка `Открыть заново`: **без подтверждения** сбрасывает черновик, если он есть, перечитывает файл и показывает статус `Сейв перечитан с диска.`

### 1.4 Навигация (левая колонка)

- Шапка: знак `☢`, `S.T.A.L.K.E.R.`, `РЕДАКТОР СОХРАНЕНИЙ`.
- Переключатель `☰` с подписью `Свернуть меню`. В свёрнутом виде подсказка `Развернуть меню`. Ширина колонки 236 или 58.
  - Выбор пользователя запоминается (`navigation_collapsed`).
  - При ширине средней части < 900 меню всегда свёрнуто. Пока пользователь не выбирал сам, меню свёрнуто при ширине < 1150.
- Группы и пункты (десктоп):
  - `СОХРАНЕНИЯ`: `ОБЗОР`, `ИНВЕНТАРЬ`, `ФРАКЦИИ`, `ТАЙНИКИ`, `ПЕРЕХОДЫ`, `БЭКАПЫ`, `СРАВНЕНИЕ`, `ИСТОРИЯ СОХРАНЕНИЙ`.
  - Отдельный пункт `ДОКТОР СОХРАНЕНИЯ`.
  - `ИГРЫ`: `ОБЗОР ИГР`, `ИСПРАВЛЕНИЯ ИГРЫ`, `ДОКТОР ИГРЫ`, `СРЕДА ИГРЫ`, `КОМПАНЬОН`, `ДОСТИЖЕНИЯ`.
  - `ИНСТРУМЕНТЫ`: `ОБЛАКО`, `ЭНЦИКЛОПЕДИЯ`, `ВОЗМОЖНОСТИ`, `ОБНОВЛЕНИЯ`, `НАСТРОЙКИ`.
- Веб: только группа `СОХРАНЕНИЯ` и `ИНСТРУМЕНТЫ` из двух пунктов (`ВОЗМОЖНОСТИ`, `НАСТРОЙКИ`).
- Активный пункт выделен фоном и рамкой акцентного цвета. Смена экрана сопровождается звуком.
- Хлебные крошки над рабочей областью: `<группа> / <страница>`. Для `ОБЗОР ИГР` страница называется `ИГРЫ И ИНСТРУМЕНТЫ`. Для `ДОКТОР СОХРАНЕНИЯ` группа — `СОХРАНЕНИЯ`.
- Экран строится при первом показе и дальше живёт скрытым.
- При переходе на `ДОКТОР СОХРАНЕНИЯ` с выбранным сейвом проверка запускается автоматически, если отчёта ещё нет.

### 1.5 Библиотека сохранений (средняя колонка)

- Видна только на экранах Обзор, Инвентарь, Фракции, Тайники, Переходы, Бэкапы, Сравнение, История, Доктор сохранения.
- Ширина 220 / 280 / 300 при ширине средней части < 1100 / обычной / ≥ 1900.
- Заголовок `БИБЛИОТЕКА СОХРАНЕНИЙ`, бейдж с количеством сейвов, кнопка `↻` (подсказка и имя для доступности — `Обновить`).
- Строка сейва:
  - миниатюра игры или заглушка `нет снимка` с подсказкой `Игра не сохранила снимок для этого сохранения (так бывает у автосохранений и у сохранений из облака).`;
  - имя файла (с подсказкой);
  - название игры;
  - для X-Ray — дата `dd.MM.yy HH:mm`, для S2 — `{регион} · {часы:0.#} ч`;
  - размер: `{0:F1} МБ` / `{0:F0} КБ` / `{0} Б`.
- Названия игр: `Тень Чернобыля`, `Тень Чернобыля (Enhanced Edition)`, `Чистое Небо`, `Чистое Небо (Enhanced Edition)`, `Зов Припяти`, `Зов Припяти (Enhanced Edition)`, `S.T.A.L.K.E.R. 2: Сердце Чернобыля`.

**Загрузка библиотеки (фон):**

- Источник папок: список из настроек. Если в настройках его нет — автопоиск (Steam-библиотеки, `fsgame.ltx`, Proton, EE, S2).
- Файлы `*.sav`, `*.scop`, `*.scs` ищутся рекурсивно до глубины 4. Недоступные папки и символические ссылки пропускаются. Файлы `*_ORIGINAL.*` и `*_EDITED.*` исключаются.
- Сортировка — по времени изменения, сначала новые.
- Разбор идёт параллельно, пачками. Большие файлы обрабатываются не более чем по два одновременно (ограничение по памяти).
- При первой загрузке пачки появляются сразу, а первый сейв выбирается автоматически.
- Повторная загрузка берёт из кэша файлы, у которых совпадают размер, mtime, ctime и контрольная выборка содержимого.
- Статус во время загрузки: `Чтение сохранений…` (после загрузки очищается).
- **Отмена:** новый запуск обновления прерывает старый, закрытие окна тоже. Отдельной кнопки отмены нет. Прогресс — только появление строк.
- Ошибка: `Не удалось прочитать папки сохранений: {0}`.
- Нераспознанные файлы не показываются и только пишутся в журнал.

### 1.6 Строка состояния и горячие клавиши

- Слева — `StatusMessage` (последнее сообщение любого действия оболочки и экранов сейва).
- Справа — бейдж черновика:
  - `Черновик: {0} действ.` — есть шаги;
  - `Есть несохранённые изменения` — нет шагов, но поля отличаются от файла или ввод неверен;
  - `Все изменения сохранены`.

| Сочетание | Действие |
|---|---|
| Ctrl+Z | Отменить (если `CanUndo`) |
| Ctrl+Y | Вернуть |
| Ctrl+Shift+Z | Вернуть |
| Ctrl+S | СОХРАНИТЬ (если `CanSave`) |

Сочетания привязаны к корню интерфейса и работают на любом экране, включая не связанные с сейвом. На Linux глобальные горячие клавиши компаньона перехватываются отдельно (§16).

### 1.7 Мастер первого запуска

Виден, если одновременно: мастер не пропущен в этой сессии, библиотека не загружается, сейвов 0, и открыт один из экранов Обзор / Инвентарь / Фракции / Тайники / Переходы / Бэкапы. На остальных экранах мастер не показывается. Флаг «пропущен» не сохраняется между запусками.

**Десктоп:**

- Заголовок `МАСТЕР ПЕРВОГО ЗАПУСКА`.
- Текст: `Сохранения S.T.A.L.K.E.R. не были найдены в стандартных каталогах.` + перевод строки + `Укажите папку с файлами сохранений (savedgames или SaveGames) или запустите автоматический поиск на диске.`
- Кнопка `АВТОПОИСК ПАПОК НА ДИСКЕ`: добавляет найденные папки в настройки (запись `settings.json`, если что-то добавлено) и обновляет библиотеку. Если сейвы появились, мастер закрывается.
- Разделитель `— ИЛИ УКАЖИТЕ ПУТЬ ВРУЧНУЮ —`.
- Поле с подсказкой `Путь к папке с сейвами…`.
- Кнопка `Обзор…` открывает выбор папки `Выберите папку с сохранениями`.
- Кнопка `Добавить` активна, если поле не пустое.
  - Путь обрезается по пробелам. Добавление отклоняется **молча**, если такая папка уже есть (без учёта регистра). Существование папки **не проверяется**.
  - Успех: путь сохраняется в `settings.json`, поле очищается, библиотека обновляется.
- Кнопка `Перейти в настройки`.
- Кнопка `Пропустить` скрывает мастер; появляется пустое состояние `ВЫБЕРИТЕ СОХРАНЕНИЕ`.

**Веб:** текст `Откройте файл сохранения кнопкой «Открыть…» вверху.` + перевод строки + `Файл не покидает браузер: он разбирается и изменяется здесь, а после «Сохранить» скачивается обратно.`

### 1.8 Пустые состояния оболочки

| Ситуация | Что видит пользователь |
|---|---|
| Нет сейвов, мастер не пропущен, экран группы сейвов | Мастер первого запуска |
| Нет выбранного сейва (мастер пропущен, или сейвы есть, но не выбраны) на экранах 1–2, 4–7 | `ВЫБЕРИТЕ СОХРАНЕНИЕ` / `Выберите сейв из списка слева для просмотра и редактирования.` |
| Нет установленной игры | Оболочка не меняется. Библиотека пуста, если нет сейвов. Сборка игры на «Обзоре» — `игра не найдена` |
| Нет сети | Оболочка не меняется. Тихая проверка обновлений не показывает ошибку, баннер обновления не появляется. Отправка отчёта молча не удаётся (только журнал) |
| Сейв S2 версии 1.0.x | Открывается, все правки недоступны. Причина во всех подсказках: `Сохранение записано игрой версии 1.0.x: только чтение. Загрузите его в текущей версии игры и сохраните заново.` Кнопка `СОХРАНИТЬ` неактивна (нет изменений) |
| Формат с запретом записи в UI | Причина: `Запись S.T.A.L.K.E.R. 2 выключена в UI до верификации мутаций в живой игре.` (S2) или `Запись для формата {0} выключена в UI в целях безопасности.` |
| Черновик из другой версии | Любая правка откатывается со статусом из §1.2 п.2. Сохранение невозможно до `Сбросить` |

### 1.9 Фоновые операции оболочки

| Операция | Когда | Прогресс | Отмена |
|---|---|---|---|
| Загрузка контента установленных игр, затем библиотеки | старт | статус `Чтение сохранений…` | закрытие окна |
| Поиск установок игр (для сборки и автоподстановки игры) | старт | нет | нет |
| Тихая проверка обновлений (сеть) | старт | нет (только баннер) | нет |
| Слежение за файлом выбранного сейва | каждые 3 с | баннер §1.3 п.4 | закрытие окна |
| Суточный отчёт диагностики (сеть) | старт, после ответа на уведомление | нет | нет |
| Список бэкапов (хэширование файлов) | после загрузки/записи | нет | новый запрос, закрытие окна |
| Запись сейва | `СОХРАНИТЬ` | статус `Сохранение…`, UI заблокирован | **нет** (транзакция не прерывается) |
| Фоновая музыка меню | если включена | нет | выключение в настройках |

### 1.10 Чек-лист приёмки оболочки

1. Первый запуск без сейвов и без `settings.json` → виден мастер и уведомление об отчётах. Пока не нажата `Понятно` или `Не отправлять`, отчёты не отправляются.
2. Мастер: ввести несуществующий путь → `Добавить` → путь появляется в списке папок в Настройках, сейвов 0, мастер остаётся.
3. Мастер: `Пропустить` → `ВЫБЕРИТЕ СОХРАНЕНИЕ`. После перезапуска мастер появляется снова.
4. Изменить деньги, нажать Ctrl+Z → поле вернулось, бейдж `Все изменения сохранены`. Ctrl+Y → правка вернулась, бейдж `Черновик: 1 действ.`
5. Изменить деньги и перезапустить приложение → после выбора того же сейва правка на месте (черновик сохранён на диске).
6. Ctrl+S без правок → ничего не происходит. Подсказка кнопки — `Нет несохранённых изменений.`
7. Изменить деньги → `СОХРАНИТЬ` → статус `Сохранено успешно. Backup: <имя>`; в «Бэкапах» новая запись со статусом `Проверен`.
8. Во время записи большого сейва → список сейвов, рабочая область и верхняя панель неактивны.
9. Сохранить сейв в игре, пока он открыт в редакторе → в течение ~3 с появляется баннер `Файл сейва изменился…`. `Открыть заново` → черновик сброшен, статус `Сейв перечитан с диска.`
10. `Открыть…` → выбрать текстовый файл → статус `«x.txt» — не сохранение S.T.A.L.K.E.R. или файл повреждён.`
11. Сузить окно до ширины < 900 → меню свёрнуто, кнопка разворачивания не помогает.
12. Открыть сейв S2 версии 1.0.x → все поля правки неактивны, в подсказках текст «только чтение».
13. Запустить с `STALKER_EDITOR_LANG=ru` → кнопки и меню на русском, «Доктор игры» показывается как `ДОКТОР ИГРЫ`.
14. Запустить, когда системный язык — например, финский, и язык в настройках не задан → интерфейс на английском.

## 2. Экран «ОБЗОР» (overview)

**Назначение:** только чтение — сводка по выбранному сейву и быстрое сравнение с другим сейвом или бэкапом.

**Элементы:**

- Карточка `[ ИНФОРМАЦИЯ О СОХРАНЕНИИ ]`: название игры, имя файла, полный путь.
- Карточка `[ ПАРАМЕТРЫ СТАЛКЕРА ]`, плитки:
  - `ДЕНЬГИ` — `N0 RU`, или `—`, если деньги не редактируются и равны 0;
  - `ПРЕДМЕТОВ`, `ТАЙНИКОВ`;
  - `ИГРОВОЕ ВРЕМЯ` — `dd.MM.yyyy HH:mm` для лет 1990–2100, иначе `—`;
  - `ПЕРСОНАЖ` — имя или `—`;
  - `ЗДОРОВЬЕ` — `N%`;
  - `РАНГ` — `Мастер` (≥900), `Ветеран` (≥600), `Опытный` (≥300), `Новичок`;
  - `РЕПУТАЦИЯ` — `Отличная` (≥100), `Хорошая` (≥20), `Нейтральная` (≥−20), `Плохая` (≥−100), `Очень плохая`;
  - `ЗАДАНИЯ` — `{0} выполнено · {1} активно · {2} провалено`;
  - `УБИТО` — `сталкеров {0} · мутантов {1}`;
  - `ПОГОДА` — `{текущая} → {следующая}`, названия: `ясно`, `облачно`, `дождь`, `гроза`, `туман`, иначе исходный id.
  - Любое отсутствующее значение показывается как `—`.
- Карточка `[ ЦЕЛОСТНОСТЬ И МЕТАДАННЫЕ ]`:
  - `Размер файла:`;
  - `Изменён:` (`dd.MM.yyyy HH:mm:ss`);
  - `SHA-256:`;
  - `Сборка игры:` — `{build} · проверенная`, `{build} · не проверялась: сверьте результат в игре`, `игра не найдена` или `—` (установки ещё не найдены или игра без сопоставления).
- Карточка `[ СРАВНИТЬ С ДРУГИМ СЕЙВОМ ИЛИ БЭКАПОМ ]`:
  - выпадающий список кандидатов (скрыт, если кандидатов нет);
  - строка статуса;
  - строки `параметр | было → стало`.
  - Работает так же, как экран «Сравнение» (§9), — общая модель.
- Флаг CRC (`CrcOk`) на экране **не показывается**.

**Действия:** выбор кандидата запускает чтение двух файлов в фоне (§9). На диск ничего не пишется.

**Пустые состояния:**

- Нет сейва → пустое состояние оболочки.
- Сейв 1.0.x показывается как обычно.
- Нет игры → `Сборка игры: игра не найдена`.
- Нет кандидатов → статус `Нет других сейвов этой игры или бэкапов для сравнения.`

**Горячие клавиши и фокус:** общие (§0.2).

**Фон:** сравнение (статус `Сравнение…`, отмены нет; устаревший результат отбрасывается).

**Чек-лист:**

1. Выбрать сейв ЗП → в плитках ненулевые деньги, предметы, ранг.
2. Выбрать автосейв без данных о погоде → `ПОГОДА` = `—`.
3. В «Сравнить…» выбрать бэкап этого сейва после правки денег → строка `Деньги` со старым и новым значением.
4. Единственный сейв игры без бэкапов → `Нет других сейвов этой игры или бэкапов для сравнения.`, списка нет.
5. На машине без установленной игры → `Сборка игры:` = `игра не найдена`.

## 3. Экран «ИНВЕНТАРЬ» (inventory)

**Назначение:** правка денег и предметов рюкзака (количество, прочность, размещение, апгрейды, удаление, добавление). Все правки идут в черновик.

### 3.1 Элементы

**Карточка `[ БАЛАНС СОХРАНЕНИЯ ]`:**

- `ДЕНЬГИ:` и текущее значение `N0 RU`.
- Поле (подсказка-водяной знак `RU`, имя для доступности `Деньги в сохранении`). Активно при `CanEditMoney`.
- Кнопки `+10 000`, `+50 000`, `+100 000`. Активны при `CanEditMoney`.
- Под ними текст причины, если правка недоступна.
- Подсказка при доступности: `Изменить баланс сталкера`. Иначе — причина или `Редактирование денег не поддерживается данным форматом`.

**Фильтры:**

- Поле `Поиск предметов…` (имя для доступности `Поиск предметов`) ищет по названию и ключу секции без учёта регистра.
- Кнопка `Очистить` активна при непустом поиске; подсказка — текущий текст поиска.
- Счётчик `Найдено: {0}`.
- Чипы: `ВСЕ`, `ОРУЖИЕ`, `БОЕПРИПАСЫ`, `СНАРЯЖЕНИЕ`, `РАСХОДНИКИ`, `АРТЕФАКТЫ`, `КЛЮЧИ`, `ПРОЧЕЕ`. Выбранный подсвечен акцентом.

**Список `Предметы` (счётчик):**

- Строка: значок или `◇`, название, ключ секции, бейдж размещения (кроме рюкзака), состояние `N%` или `—`, количество `× N`.
- Цвет состояния: ≥75 зелёный, ≥40 жёлтый, иначе красный, нет шкалы — серый.
- Одинаковые штучные предметы группируются в одну строку `× N`. После правки одного из них он выделяется в отдельную строку.

**Инспектор выбранного предмета:**

- `[ ВЫБРАННЫЙ ПРЕДМЕТ ]` — название и ключ.
- `[ ПРОЧНОСТЬ ]`:
  - `Состояние / прочность`, значение, ползунок 0–100, кнопки `100%`, `75%`, `50%`.
  - Ползунок и кнопки **скрыты**, если у предмета нет шкалы.
  - Неактивны при `!CanEditCondition`. Подсказка: `Изменить состояние предмета (0–100%)`, иначе `Предмет не имеет шкалы состояния / износа` или причина формата.
- `[ КОЛИЧЕСТВО ]`:
  - `Количество в пачке`; поле ввода видно только при `CanEditCount`, иначе показывается значение только для чтения.
  - Примечание: `Одинаковых предметов: {0}. Каждый — отдельный объект: число меняется кнопками «Добавить предмет» и «Удалить предмет».` или причина.
  - Причины: `Предмет не стакается (уникальный или штучный объект)`, `Редактирование количества предметов не поддерживается форматом`. При доступности: `Изменить количество предметов в пачке`.
- `[ РАЗМЕЩЕНИЕ ]`:
  - `Текущее размещение` — `Слот` / `Пояс` / `Рюкзак` / `Надето` / исходный id;
  - кнопки `Слот`, `Пояс`, `Рюкзак`. Подсказка: `Переместить предмет (слот / пояс / рюкзак)` или `Перемещение предметов не поддерживается данным форматом`.
- `[ МОДИФИКАЦИИ ]`:
  - флажки апгрейдов (`{эффект} · ур. {n}` или имя каталога); без апгрейдов — `—`.
  - Подсказка: `Установить или снять апгрейд` или `Модификации оружия и брони не поддерживаются форматом`.
- Нет выбора → `Предмет не выбран` / `Выберите предмет для редактирования характеристик`.

**Нижняя панель:**

- Бейдж черновика (как в §1.6) и `Правки остаются в черновике до нажатия «Сохранить».`
- `Удалить предмет` — красная кнопка. Активна при `CanRemoveItems` и выбранном предмете. Подсказка: `Удалить выбранный предмет из инвентаря` или `Удаление предметов не поддерживается данным форматом`.
- `+ Добавить предмет` — основная кнопка. Активна при `CanAddItems`. Подсказка: `Добавить предмет из каталога в инвентарь` или `Добавление предметов не поддерживается данным форматом`.
- Под кнопками — тексты причин недоступности.

### 3.2 Действия (все только в черновик, без подтверждения, без записи сейва)

- **Ввод денег.**
  - Допустимо целое без знака 0…2 000 000 000. Иначе `СОХРАНИТЬ` неактивна с причиной `Введены некорректные значения…`, а бейдж показывает `Есть несохранённые изменения`.
  - Каждое изменение текста — шаг черновика.
- **`+N`.**
  - Прибавляет к текущему вводу с ограничением 0…2 000 000 000.
  - Если в поле не число, кнопка ничего не делает.
- **Количество.** Допустимо 1…65535 для редактируемых пачек.
- **Прочность.** Шаг черновика пишется, только если отличие от исходного > 0,5 %.
- **Удалить предмет.**
  - Предмет помечается удалённым и исчезает из списка.
  - Выбор переходит на оставшийся предмет той же группы или на первый.
  - Ctrl+Z возвращает его.
- **+ Добавить предмет.** Открывает встроенную панель §4, которая заменяет весь экран.

### 3.3 Пустые состояния

- Нет предметов → `◇` / `Инвентарь пуст` / `В этом сохранении нет предметов.`
- Фильтр пуст → `⌕` / `Предметы не найдены` / `Измените поиск или категорию.` и кнопка `Сбросить фильтры`.
- Сейв 1.0.x или формат с запретом → все элементы правки неактивны, видны причины.
- Нет сейва → пустое состояние оболочки.

### 3.4 Горячие клавиши и фокус

Общие (§0.2). Ctrl+Z/Y работают в том числе для правок, сделанных на этом экране.

### 3.5 Фон

Нет. Значки грузятся лениво.

### 3.6 Чек-лист

1. Ввести `abc` в деньги → `СОХРАНИТЬ` неактивна, подсказка `Введены некорректные значения (проверьте введённые числа).`
2. Ввести `2000000001` → то же самое.
3. Нажать `+100 000` три раза → поле увеличилось на 300 000, бейдж `Черновик: 3 действ.`
4. Найти `медаптечка` → в списке только аптечки, счётчик `Найдено: N`. `Очистить` → полный список.
5. Чип `АРТЕФАКТЫ` при отсутствии артефактов → `Предметы не найдены`. `Сбросить фильтры` → снова `ВСЕ`.
6. Выбрать оружие → `75%` → в строке `75%` жёлтым.
7. Выбрать патроны → ввести `0` → `СОХРАНИТЬ` неактивна.
8. Выбрать предмет → `Удалить предмет` → строка исчезла. Ctrl+Z → вернулась.
9. Сейв ТЧ/ЧН/ЗП с апгрейдами → снять флажок апгрейда → `СОХРАНИТЬ` → после перечитывания флажок снят.
10. Сейв S2 → все элементы правки неактивны, причина `Запись S.T.A.L.K.E.R. 2 выключена в UI…` (или 1.0.x).
11. Предмет без шкалы износа → ползунок и кнопки `100%/75%/50%` скрыты.

## 4. Панель и окно «Добавить предмет» (AddItemDialog)

**Назначение:** выбор предмета из каталога игры и постановка его в очередь на создание в рюкзаке или тайнике.

Два варианта показа:

- (а) **Встроенная панель** на экране «Инвентарь»: карточка `[ ДОБАВИТЬ ПРЕДМЕТ ]` скрывает деньги, фильтры, список и нижнюю панель.
- (б) **Модальное окно** с экрана «Тайники» (`+ СОЗДАТЬ В ТАЙНИКЕ`): заголовок `Добавить предмет в инвентарь` (так в коде, даже для тайника), 520×560, по центру родителя.

**Элементы:**

- Поле `Поиск по названию или ключу секции…` (имя для доступности `Поиск по каталогу предметов`).
- Список каталога: локализованное имя и ключ, сортировка по имени в культуре пользователя.
- `Предметы не найдены.` — если список пуст.
- `Количество:` — поле. Целое ≥ 1; 0 превращается в 1. Верхнего предела нет. Нечисловой ввод не принимается привязкой: значение остаётся прежним, рамка ошибки — стандартная Avalonia.
- Кнопки `Добавить` (активна при выбранном элементе) и `Отмена`.
- Первый элемент списка выбирается автоматически при открытии и после каждого изменения поиска.

**Действия:**

- `Добавить` ставит в черновик запрос `(секция, количество, назначение)` и закрывает панель или окно. Статус:
  - `Предмет {0} ({1} шт.) добавлен в очередь на запись.` — рюкзак;
  - `Предмет {0} ({1} шт.) будет создан в тайнике.` — тайник.
- `Отмена` закрывает без изменений.
- На диск ничего не пишется.

**Пустые состояния:**

- Нет каталога для игры → пустой список и `Предметы не найдены.`
- Формат без добавления → кнопка входа неактивна, панель не открывается.

**Горячие клавиши и фокус:**

- Enter и Esc **не назначены**: в окне нет `IsDefault`/`IsCancel`.
- Esc модальное окно не закрывает. Закрытие — `Отмена` или крестик окна.
- В веб-сборке окно (б) не открывается: нет `IClassicDesktopStyleApplicationLifetime`.

**Фон:** нет.

**Чек-лист:**

1. Инвентарь → `+ Добавить предмет` → панель занимает экран, деньги и фильтры скрыты.
2. Ввести несуществующее слово → `Предметы не найдены.`, `Добавить` неактивна.
3. Найти предмет, количество `0` → после потери фокуса поле показывает `1`.
4. `Добавить` → панель закрылась, статус `Предмет <ключ> (1 шт.) добавлен в очередь на запись.`, бейдж черновика увеличился.
5. `СОХРАНИТЬ` → после перечитывания предмет есть в списке.
6. Тайники → `+ СОЗДАТЬ В ТАЙНИКЕ` → модальное окно `Добавить предмет в инвентарь`. `Добавить` → в карточке тайника строка `+ новый: <ключ> × 1`.

## 5. Экран «ФРАКЦИИ» (factions)

**Назначение:** просмотр группировки игрока и правка отношений с группировками (в черновик).

**Элементы:**

- `[ ГРУППИРОВКА ИГРОКА ]`:
  - `Текущая группировка игрока: {0}`; если значения нет — `Одиночки`;
  - `Группировка определяет начальные отношения и доступ к базам фракций в X-Ray.`
  - Группировка игрока **не редактируется** (в плане всегда `null`).
- `[ ОТНОШЕНИЯ С ГРУППИРОВКАМИ ]`:
  - столбцы `ГРУППИРОВКА`, `ОЧКИ`, `СТАТУС`, `БЫСТРЫЕ ДЕЙСТВИЯ`;
  - строка: имя (официальное, иначе из каталога, иначе `Группировка № {0}`), очки `+N`/`-N`/`0`;
  - статус: `Друг` (≥1000, зелёный), `Враг` (≤−1000, красный), `Нейтрал` (жёлтый);
  - кнопки `+100`, `-100`, `Друг (+1500)`, `Нейтрал (0)`, `Враг (-1500)`.
  - Кнопки активны при `CanEdit` строки. Подсказка: `Изменить отношение группировки` или причина / `Редактирование отношений фракций не поддерживается данным форматом`.

**Действия:**

- Новое значение ограничивается диапазоном каталога (по умолчанию −3000…1000) и пишется в черновик.
- **`Друг (+1500)` даёт максимум каталога** (по умолчанию 1000), а не 1500.
- Подтверждения нет, на диск ничего не пишется.

**Пустые состояния:**

- Нет каталога фракций для игры (в том числе S2) → таблица из одного заголовка. Отдельного текста нет.
- 1.0.x или запрет → все кнопки неактивны.

**Горячие клавиши и фокус:** общие. **Фон:** нет.

**Чек-лист:**

1. ЗП: у группировки с 0 нажать `+100` → `+100`, `Нейтрал`.
2. `Друг (+1500)` → значение = максимум каталога (ожидается `+1000`), статус `Друг`.
3. `Враг (-1500)` → `-1500`, `Враг`.
4. Ctrl+Z → предыдущее значение.
5. `СОХРАНИТЬ` → после перечитывания значения сохранены.
6. Сейв S2 → кнопки неактивны с причиной.

## 6. Экран «ТАЙНИКИ» (stashes)

**Назначение:** забрать предметы из тайников в рюкзак, положить предмет из рюкзака в тайник, создать новый предмет в тайнике (всё в черновик).

**Элементы:**

- `[ УПРАВЛЕНИЕ ТАЙНИКАМИ ЗОНЫ ]`: `Отмеченные галочками предметы будут перенесены из тайников в инвентарь персонажа при сохранении. Предмет из рюкзака можно положить в тайник, а новый предмет — создать прямо в тайнике.`
- Карточка на каждый тайник, заголовок `[ {ИМЯ} ({ЛОКАЦИЯ}) — {N} ПРЕДМ. ]`:
  - имя по умолчанию `Тайник 0x{handle:X4}`, локация — `Неизвестно`;
  - если внутреннее имя объекта отличается от читаемого, оно показывается мелко сверху;
  - список предметов (виртуализирован, высота до 480): значок, `имя × N`, флажок `В рюкзак`. Флажок активен при `CanEditStashes`; подсказка `Переместить предмет в инвентарь персонажа` или причина / `Перемещение из тайников не поддерживается`;
  - очередь: `← из рюкзака: {имя}`, `+ новый: {ключ} × {N}`;
  - выпадающий список `Предмет из рюкзака` (весь инвентарь, включая удалённые в черновике);
  - кнопка `В ТАЙНИК`;
  - кнопка `+ СОЗДАТЬ В ТАЙНИКЕ`.
  - Обе кнопки активны при **`CanAddItems`**, а не `CanEditStashes` (см. §24). Подсказка — причина добавления.

**Действия:**

- Флажок `В рюкзак` — шаг черновика.
- `В ТАЙНИК`:
  - без выбора в списке — ничего не происходит;
  - повторное нажатие с тем же предметом **отменяет** перенос;
  - статусы: `{0} будет перенесён в тайник «{1}».` / `Перенос {0} в тайник отменён.`
- `+ СОЗДАТЬ В ТАЙНИКЕ` — модальное окно §4.
- Подтверждений нет, на диск ничего не пишется.

**Пустые состояния:**

- В сейве нет тайников → только карточка-подсказка, без отдельного текста.
- Причина недоступности флажков: `В сохранении нет тайников` или `В сохранении нет тайников с предметами или операция не поддерживается`.
- S2: перемещение по `move_items`; 1.0.x — только чтение.

**Горячие клавиши и фокус:** общие. **Фон:** нет (виртуализация списка).

**Чек-лист:**

1. ЗП с тайниками → отметить `В рюкзак` у предмета → бейдж `Черновик: 1 действ.`
2. `СОХРАНИТЬ` → после перечитывания предмета в тайнике нет, в инвентаре есть.
3. Выбрать предмет рюкзака → `В ТАЙНИК` → строка `← из рюкзака: …`. Ещё раз `В ТАЙНИК` → строка исчезла, статус `Перенос … в тайник отменён.`
4. `В ТАЙНИК` без выбора → ничего не происходит.
5. Тайник с >2000 предметов → прокрутка без зависаний.
6. Ctrl+Z после флажка → флажок снят.

## 7. Экран «ПЕРЕХОДЫ» (transitions)

**Назначение:** только просмотр переходов между локациями (level_changer). Экспериментальный перенос персонажа к точке перехода **с немедленной записью сейва**.

**Элементы:**

- `[ ПЕРЕХОДЫ МЕЖДУ ЛОКАЦИЯМИ ]`: `Переходы между локациями, которые есть в этом сохранении.` и `Список только для просмотра: сами переходы редактор не меняет.`
- Блок переноса (виден при `CanRelocate`, то есть формат поддерживает перенос и есть точки):
  - заголовок `ПЕРЕНОС ПЕРСОНАЖА (ЭКСПЕРИМЕНТАЛЬНО)`;
  - `Только точки, куда игра сама ставит персонажа после перехода. Сохранение записывается сразу, с бэкапом. В игре это ещё не проверено.`;
  - `Сейчас: X {0:0.0} · Y {1:0.0} · Z {2:0.0} · вершина {3}` (или `Сейчас: —`);
  - список `Куда перенести` (`{уровень} · {точка}`);
  - кнопка `ПЕРЕНЕСТИ` — **всегда активна**.
- Таблица: столбцы `ПЕРЕХОД`, `ИМЯ В СОХРАНЕНИИ / ТОЧКА`, `ID В РЕЕСТРЕ`.
  - Маршрут: `откуда → куда`, `→ куда`, `откуда → …` или имя.
  - Имя: замена имени, иначе имя, иначе `Объект 0x{0:X4}`.
  - ID: `0x{h:X4} ({h})` или `—`.
  - Статус каждой строки: `Только чтение`.
- Пусто: `ТОЧКИ ПЕРЕХОДОВ ОТСУТСТВУЮТ` / `В объектах реестра данного сохранения нет записей типа level_changer.`

**Действие `ПЕРЕНЕСТИ`:**

- Проверки:
  - сейв и точка выбраны (иначе **ничего не происходит**, без сообщения);
  - если `CanSave == true` (есть сохраняемые правки) → `Сначала сохраните или отмените текущие правки, затем переносите персонажа.`
- **Подтверждения нет.**
- Запись: `XRayRelocation.Prepare`, затем `LocalSaveReplacement.ReplaceLocal` (бэкап с журналом, атомарная замена, обратное чтение: позиция и игровая вершина актёра должны совпасть с точкой). После этого сейв перечитывается.
- Выполняется в UI-потоке, `IsSaving` не выставляется.
- Успех: `Персонаж перенесён: {0}. Backup: {1}`.
- Ошибка: `Не удалось перенести персонажа: {0}`.

**Пустые состояния:**

- Нет переходов → текст выше.
- S2 и неподдерживаемые форматы → блок переноса скрыт.
- 1.0.x к S2 не относится: X-Ray-перенос зависит от `XRayRelocation.IsSupported` — не определено из исходников, для каких форматов.

**Горячие клавиши и фокус:** общие. **Фон:** нет.

**Чек-лист:**

1. ЗП → таблица переходов заполнена, у строк статус `Только чтение`.
2. Не выбирать точку → `ПЕРЕНЕСТИ` → ничего не происходит.
3. Изменить деньги → выбрать точку → `ПЕРЕНЕСТИ` → `Сначала сохраните или отмените текущие правки…`, файл не изменён.
4. Без правок → выбрать точку → `ПЕРЕНЕСТИ` → статус `Персонаж перенесён: … Backup: …`, `Сейчас:` показывает новые координаты, в «Бэкапах» новая запись.
5. Сейв ТЧ без level_changer → `ТОЧКИ ПЕРЕХОДОВ ОТСУТСТВУЮТ`.

## 8. Экран «БЭКАПЫ» (backups)

**Назначение:** список резервных копий из папки бэкапов, их проверка и восстановление.

**Элементы:**

- Заголовок `ИСТОРИЯ И РЕЗЕРВНЫЕ КОПИИ`, описание `Резервные копии создаются перед записью. Здесь можно проверить их состояние и восстановить исходную копию.`, кнопка `Обновить бэкапы`.
- Список `РЕЗЕРВНЫЕ КОПИИ` со счётчиком `Записей: {0}`.
  - Строка: имя исходного файла, дата `dd.MM.yyyy HH:mm:ss`, статус `Проверен` (зелёный) / `Отсутствует` / `Повреждён` (красный).
  - Показываются **все** бэкапы папки, не только для выбранного сейва.
- Пусто: `РЕЗЕРВНЫХ КОПИЙ ПОКА НЕТ` / `Копия появится после первой операции записи в сохранение.`
- Карточка `СВЕДЕНИЯ О КОПИИ`:
  - статус, имя;
  - `СОЗДАНА`, `ИСХОДНЫЙ ФАЙЛ`, `ФАЙЛ КОПИИ`, `ФАЙЛ ПОСЛЕ ОПЕРАЦИИ` (или `—`), `SHA-256 ИСХОДНОГО ФАЙЛА`, `SHA-256 КОПИИ` (или `—`);
  - текст ошибки (если есть);
  - причина недоступности восстановления на место;
  - кнопки `Восстановить на место` (основная) и `Восстановить в копию`.
- Без выбора: `Выберите резервную копию, чтобы посмотреть сведения и доступные действия.`
- Автовыбор: прежний, иначе первый проверенный, иначе первый.

**Доступность:**

- `Восстановить в копию` — статус `Verified`.
- `Восстановить на место` — `Verified`, в журнале операции режим `replace`/`restore`, и выходной путь совпадает с исходным.
- Причины:
  - `Файл резервной копии отсутствует; восстановление отключено.`
  - `Резервная копия повреждена; восстановление отключено.`
  - `Резервная копия не прошла проверку; восстановление отключено.`
  - `Эту резервную копию можно восстановить только в отдельную копию.`

**Действия (подтверждений нет; выполняются в UI-потоке):**

- `Обновить бэкапы` — перечитать и перехэшировать папку (фон).
- `Восстановить на место` — `LocalSaveStorage.RestoreInPlace`. Ядро создаёт страховочный бэкап текущего файла. Не проверяется, есть ли несохранённый черновик у этого сейва.
  - Успех: `Восстановлено на место. Создан страховочный бэкап: {0}` и перечитывание библиотеки.
- `Восстановить в копию` — `LocalSaveStorage.RestoreBackup` в `<папка исходника>/<имя>_restored_yyyyMMdd_HHmmss.sav` (расширение всегда `.sav`).
  - Успех: `Восстановлено в файл: {0}`. Новый файл появляется в библиотеке.
- Ошибка любого восстановления: `Ошибка восстановления: {0}`.

**Пустые состояния:** нет сейва → пустое состояние оболочки (экран требует выбранный сейв, хотя список общий). Папка бэкапов не существует → пустой список.

**Горячие клавиши и фокус:** общие.

**Фон:** список бэкапов с хэшированием. Прогресса нет; отмена — новым запросом или закрытием окна.

**Чек-лист:**

1. После первого сохранения → запись `Проверен`, `ФАЙЛ ПОСЛЕ ОПЕРАЦИИ` равен исходному, обе кнопки активны.
2. Удалить файл копии вручную → `Обновить бэкапы` → `Отсутствует`, кнопки неактивны, причина `Файл резервной копии отсутствует…`
3. Испортить байт копии → `Повреждён`.
4. `Восстановить в копию` → рядом с сейвом появляется `*_restored_<дата>.sav`, он есть в библиотеке.
5. `Восстановить на место` → сейв вернулся к копии, статус со страховочным бэкапом, в списке +1 запись.
6. Чистая папка бэкапов → `РЕЗЕРВНЫХ КОПИЙ ПОКА НЕТ`.

## 9. Экран «СРАВНЕНИЕ» (compare)

**Назначение:** только чтение — показать различия между выбранным сейвом и другим сейвом той же игры (EE и не-EE считаются одной игрой) или его бэкапом.

**Элементы:**

- Заголовок `СРАВНЕНИЕ СОХРАНЕНИЙ`, описание `Сравнивайте выбранное сохранение с другим сейвом или его резервной копией. Показаны только данные, доступные для чтения.`
- `Сравнить с`: выпадающий список с подсказкой `Выберите сохранение или резервную копию`. Сначала бэкапы (`Бэкап {дата}`), затем сейвы.
  - Список скрыт и неактивен без кандидатов; вместо него `Нет других сейвов этой игры или бэкапов для сравнения.`
- Карточки `СОХРАНЕНИЕ A` (выбранный кандидат) и `СОХРАНЕНИЕ B` (текущий сейв): имя, источник (`Резервная копия` / `Локальный файл` / `—`), путь.
- Между карточками кнопка `⇄` (подсказка `Поменять местами только отображение столбцов A и B`), активна при наличии обеих сторон.
- `[ ИТОГИ СРАВНЕНИЯ ]`: `РАЗЛИЧИЙ`, `ДОБАВЛЕНО`, `УДАЛЕНО`, `ИЗМЕНЕНО`.
- `ФИЛЬТРЫ СРАВНЕНИЯ` (видны, если есть различия):
  - `Категория`: `Все различия` / `Предметы` / `Персонаж` / `Задания` / `Другое`, с числом;
  - `Тип изменения`: `Все` / `Добавлено` / `Удалено` / `Изменено`;
  - поиск `Поиск по различиям`.
- `[ РАЗЛИЧИЯ ]`: столбцы `ТИП`, `ПАРАМЕТР / ОБЪЕКТ`, `ЗНАЧЕНИЕ A`, `→`, `ЗНАЧЕНИЕ B`, `КАТЕГОРИЯ`.
  - Задания показываются как `Задание: {0}` со значениями `нет`, `выполняется`, `выполнено`, `провалено`, `пропущено`.
  - Если видимых строк нет: статус и `Здесь отображаются только различия, возвращённые текущей моделью сравнения.`
- Кнопки `Экспорт CSV` и `Копировать список` (основная), активны при наличии видимых строк. Под ними красная строка ошибки.

**Статусы:**

- `Выберите, с чем сравнить.`
- `Сравнение…`
- `Различий нет.`
- `Различий: {0}. Показаны только данные, доступные для сравнения.`
- `Это сейвы разных игр.`
- `Не удалось прочитать: ` + сообщение

**Действия:**

- Выбор кандидата → фоновое чтение и разбор обоих файлов. Показывается только последний запрос.
- `⇄` меняет только отображение столбцов.
- `Копировать список` копирует TSV в буфер обмена. Заголовки: `ТИП	ПАРАМЕТР / ОБЪЕКТ	ЗНАЧЕНИЕ A	ЗНАЧЕНИЕ B	КАТЕГОРИЯ`, строки разделены CRLF. Копируются только видимые строки.
  - Успех ничем не отмечается. Ошибка: `Не удалось скопировать` или `Не удалось скопировать: {0}`.
- `Экспорт CSV` — диалог сохранения `Экспорт CSV`, имя по умолчанию `stalker-save-differences.csv`, UTF-8 с BOM, CSV-экранирование.
  - Отмена диалога ничего не делает. Успех ничем не отмечается.
  - Ошибки: `Не удалось выполнить действие` или `Не удалось сохранить: {0}`.
  - Веб: временный файл в `/tmp/saves/comparison-<guid>.csv` отдаётся на скачивание и удаляется.

**Пустые состояния:**

- Нет выбранного сейва → экран виден, кандидатов нет, `Нет других сейвов этой игры или бэкапов для сравнения.`
- 1.0.x сравнивается, если ядро его читает — не определено из исходников.

**Горячие клавиши и фокус:** общие.

**Фон:** чтение двух файлов. Статус `Сравнение…`, отмены нет (результат устаревшего запроса отбрасывается).

**Чек-лист:**

1. Сейв с бэкапом после правки денег → выбрать бэкап → `Различий: 1…`, строка `Изменено | Деньги`.
2. `⇄` → значения A и B поменялись местами, итоги не изменились.
3. Фильтр `Предметы` → только предметы. Поиск по имени → строки сужаются.
4. `Копировать список` → в буфере TSV с заголовком из 5 столбцов.
5. `Экспорт CSV` → файл открывается в Excel с корректной кириллицей (BOM).
6. Два одинаковых файла → `Различий нет.`, кнопки неактивны.
7. Сейв без кандидатов → список скрыт, текст про отсутствие кандидатов.

## 10. Экран «ИСТОРИЯ СОХРАНЕНИЙ» (timeline)

**Назначение:** хронологический список сейвов библиотеки с переходом к сравнению соседних по времени сейвов одной игры.

**Элементы:**

- Заголовок `ИСТОРИЯ СОХРАНЕНИЙ` и `Временная последовательность строится только по времени изменения реальных файлов.`
- Карточки, от старых к новым (без времени — в конце):
  - `{игра} · {файл}` и `{dd.MM.yyyy HH:mm:ss} · {деньги} · {X-Ray: игра · дата | S2: регион · часы}`;
  - кнопка `Сравнить с предыдущим`. Подсказка: `Откройте экран сравнения` или `Нет предыдущего сохранения с известным временем для этой игры.`
- Пусто: `Сохранения появятся после выбора папок в настройках.`

**Доступность сравнения:** у этого и предыдущего сейва той же игры есть время, предыдущий строго старше, и оба времени уникальны внутри игры.

**Действие:** выбирает текущий сейв, открывает «Сравнение» и выбирает предыдущий как кандидата. На диск ничего не пишется.

**Пустые состояния:** нет сейвов → текст выше. Выбранный сейв не нужен.

**Горячие клавиши и фокус:** общие. **Фон:** нет.

**Особенность (см. §24):** список перестраивается только при загрузке библиотеки и при открытии файла через `Открыть…`. После сохранения или восстановления строка показывает старые данные до `Обновить`.

**Чек-лист:**

1. Три сейва ЗП с разным временем → у самого старого кнопка неактивна, у двух других активна.
2. `Сравнить с предыдущим` → открыт экран «Сравнение», B — этот сейв, A — предыдущий.
3. Два сейва с одинаковым временем → у обоих сравнение неактивно.
4. Нет папок → `Сохранения появятся после выбора папок в настройках.`

## 11. Экран «ДОКТОР СОХРАНЕНИЯ» (save-doctor)

**Назначение:** структурная и квестовая проверка файла сейва и ремонт известных «сломанных» квестов с записью сейва.

**Элементы:**

- Заголовок `ДОКТОР СОХРАНЕНИЯ` и `ПРОВЕРКА ЧИТАЕМОСТИ ФОРМАТА. СЕМАНТИЧЕСКИЕ ПРАВИЛА И РЕМОНТ ДОСТУПНЫ ТОЛЬКО ПРИ НАЛИЧИИ ПРОВЕРЕННЫХ ДАННЫХ.`
- Поле пути (подсказка `Файл`) — подставляется выбранный сейв, можно ввести вручную.
- Кнопка `Открыть сохранение` — диалог выбора файла с тем же заголовком.
- Кнопка `ПРОВЕРИТЬ СОХРАНЕНИЕ` — активна при непустом пути и если проверка не идёт.
- Строка статуса.
- Кнопка `ИСПРАВИТЬ КВЕСТЫ` — **видна** только если найден сломанный квест.
- Кнопка `УСТАНОВИТЬ ИСПРАВЛЕНИЕ ИГРЫ` — видна, если для сломанного квеста есть предотвращающее исправление игры.
- Отчёт — строки `знак | имя | подробность`:
  - `✓ СТРУКТУРНАЯ ПРОВЕРКА — ФОРМАТ: {0}; ЗАПИСЕЙ ИНВЕНТАРЯ: {1}.`
  - `СТРУКТУРНАЯ ПРОВЕРКА — ФАЙЛ НЕ РАСПОЗНАН ИЛИ ПОВРЕЖДЁН: {0}`
  - `СЕМАНТИЧЕСКОЕ СОСТОЯНИЕ — НЕТ ПОДТВЕРЖДЁННЫХ ПРАВИЛ ДЛЯ КВЕСТОВ И СОСТОЯНИЯ ОБЪЕКТОВ.`
  - `СОСТОЯНИЕ КВЕСТОВ — ТЕКУЩИЙ МОДУЛЬ ЧТЕНИЯ НЕ ВЫСТАВЛЯЕТ ПРОВЕРЕННЫЕ СОСТОЯНИЯ ЗАДАНИЙ; СПИСОК НЕ ПОКАЗЫВАЕТСЯ.`
  - `РЕМОНТ СОХРАНЕНИЯ — НЕТ ВАЛИДИРОВАННОГО РЕМОНТА; ФАЙЛ НЕ МЕНЯЛСЯ.`
  - Строки квестов: `КВЕСТ: ЗАДАНИЯ ВОЛКА ПОСЛЕ ЕГО СМЕРТИ`, `КВЕСТ: ЗАДАНИЯ НАПРА НА БАРАХОЛКЕ ПОСЛЕ ЕГО СМЕРТИ`, `КВЕСТ: СЮЖЕТ НА АРМЕЙСКИХ СКЛАДАХ ПОСЛЕ СМЕРТИ КАБАНА`, `КВЕСТ: ВСТРЕЧА С КРОТОМ НА АГРОПРОМЕ ПОСЛЕ ЕГО СМЕРТИ`, `КВЕСТ: ПЛЕННЫЙ ДОЛГОВЕЦ В ТЁМНОЙ ДОЛИНЕ ПОСЛЕ ЕГО СМЕРТИ`, `КВЕСТ: КУРЬЕР СВОБОДЫ ПОСЛЕ ЕГО СМЕРТИ`, `КВЕСТ: ИНФОРМАТОР СВОБОДЫ ПОСЛЕ ЕГО СМЕРТИ`.
  - Подробности квестов:
    - `⚠ NPC МЁРТВ, НО ФЛАГ {0} НЕ ВЫДАН: ЗАДАНИЕ ЗАВИСНЕТ. ИСПРАВЛЕНИЕ ДОБАВИТ ФЛАГ.`
    - `✓ NPC ЖИВ.`
    - `✓ ФЛАГ УЖЕ ВЫДАН.`
    - `× NPC МЁРТВ БЕЗ ФЛАГА, НО СЮЖЕТ УЖЕ ПОШЁЛ ДАЛЬШЕ: ДОБАВЛЕНИЕ ФЛАГА НЕ ПОМОЖЕТ. НУЖЕН БОЛЕЕ РАННИЙ СЕЙВ.`
    - `? NPC НЕ НАЙДЕН ИЛИ НЕ ЧИТАЕТСЯ; СОСТОЯНИЕ НЕИЗВЕСТНО.`
    - Дополнение: ` ЧТОБЫ ИГРА УВИДЕЛА ФЛАГ, УСТАНОВИТЕ ИСПРАВЛЕНИЕ ИГРЫ {0}.`
- Пусто: `ВЫБЕРИТЕ ФАЙЛ СОХРАНЕНИЯ ДЛЯ ПРОВЕРКИ.`

**Действия:**

- **Проверка** (фон): чтение файла, `SaveDoctor.Analyze` и `QuestDoctor.Analyze`.
  - Если за время проверки сменился сейв, результат отбрасывается и проверка запускается заново.
  - Ошибка ввода-вывода → статус `Ошибка` и строка `× СТРУКТУРНАЯ ПРОВЕРКА — <сообщение>`.
  - Смена пути очищает отчёт.
- **ИСПРАВИТЬ КВЕСТЫ** — **без подтверждения**, черновик не проверяется.
  - В фоне: `QuestDoctor.PrepareRepair` (если нечего чинить → `НЕТ ПОДТВЕРЖДЁННЫХ СЛОМАННЫХ КВЕСТОВ.`), затем `LocalSaveReplacement.ReplaceLocal` (бэкап с журналом, атомарная замена, обратное чтение `VerifyRepair`).
  - Затем повторная проверка, статус `КВЕСТЫ ИСПРАВЛЕНЫ. Backup: {0}`, сейв перечитывается в библиотеке.
  - Ошибка: `Не удалось сохранить: {0}`.
- **УСТАНОВИТЬ ИСПРАВЛЕНИЕ ИГРЫ** — открывает «Исправления игры» с выбранным исправлением (и найденной установкой, если папка пуста). Ничего не устанавливает.

**Пустые состояния:**

- Нет сейва → текст выше. Экран доступен и без выбранного сейва.
- Нет игры → проверка работает. Кнопка исправления игры открывает экран с пустой папкой.
- Квесты 1.0.x/S2 → строки «СОСТОЯНИЕ КВЕСТОВ … НЕ ВЫСТАВЛЯЕТ…» (если ядро не даёт состояния).

**Горячие клавиши и фокус:** общие. При переходе на экран с выбранным сейвом проверка запускается автоматически.

**Фон:** проверка и ремонт. Прогресса нет, кнопки неактивны (`IsAnalyzing`), отмены нет.

**Чек-лист:**

1. Выбрать сейв → открыть экран → отчёт появился без нажатия кнопки, первая строка `✓ СТРУКТУРНАЯ ПРОВЕРКА — ФОРМАТ: …`
2. Ввести путь к несуществующему файлу → `ПРОВЕРИТЬ СОХРАНЕНИЕ` → `Ошибка` и строка `×` с сообщением.
3. Сейв ЧН с убитым Волком без флага → строка `⚠`, видна `ИСПРАВИТЬ КВЕСТЫ`.
4. `ИСПРАВИТЬ КВЕСТЫ` → `КВЕСТЫ ИСПРАВЛЕНЫ. Backup: …`, повторный отчёт `✓ ФЛАГ УЖЕ ВЫДАН.`, бэкап в «Бэкапах».
5. Сейв с состоянием `too-late` → строка `×`, кнопка ремонта появляется, только если есть другие сломанные квесты.
6. `УСТАНОВИТЬ ИСПРАВЛЕНИЕ ИГРЫ` → открыт экран «Исправления игры» с выделенным исправлением.

## 12. Экран «ОБЗОР ИГР» (games)

**Назначение:** найти установленные игры на компьютере, выбрать одну и перейти к инструментам для неё. Сам экран ничего не меняет.

**Элементы:**

- Заголовок `ИГРЫ И ИНСТРУМЕНТЫ` и `Управляйте установленными играми, исправлениями, средой и игровыми инструментами.`
- Выпадающий список игры (`GameFixes.SelectedTarget`, имя для доступности `Выбранная игра`).
- Карточка `[ МОИ ИГРЫ ]` — модель общая с «Доктором игры»:
  - заголовок `НАЙДЕННЫЕ УСТАНОВКИ` и счётчик `Найдено: {0}`;
  - кнопка `Найти установки` (имя для доступности `Найти установки игр`);
  - состояния:
    - `Поиск установок ещё не выполнялся.`
    - `Поиск установок…`
    - `●  НАЙДЕНО {n}` / `●  НЕ НАЙДЕНО`
    - ошибка: `Не удалось найти установки. Укажите папку игры вручную в Докторе игры.`
  - строки установок: игра, папка, источник (`Steam` / `GOG` / `GSC Retail` / `Heroic` / `Выбрана вручную`);
  - без строк: `Установки не выбраны` и `Если поиск ничего не нашёл, укажите папку игры в Докторе игры.`; до поиска — `Нажмите «Найти установки», чтобы проверить поддерживаемые игры на этом компьютере.`;
  - кнопка `Открыть Доктор игры`.
- Карточка `[ ВЫБРАННАЯ ИГРА ]`:
  - `Игра в каталоге` и состояние каталога исправлений (`ИСПРАВЛЕНИЙ В КАТАЛОГЕ: {0}` / `НЕТ ПРОВЕРЕННЫХ ИСПРАВЛЕНИЙ ДЛЯ ЭТОЙ ВЕРСИИ.`);
  - `Статус` (`Установка найдена` / `Не выбрана`), `Платформа`, `Номер сборки`, `Папка игры` (или `—`).
- `БЫСТРЫЕ ДЕЙСТВИЯ` — кнопки-переходы:
  - `⚒ Исправления` / `Проверить и установить вручную`
  - `⌖ Доктор игры` / `Проверить выбранную установку`
  - `⚙ Среда игры` / `Снимки, профили и конфигурация`
  - `● Компаньон` / `Состояние и управление компаньоном`
  - `★ Достижения` / `Просмотр и управление достижениями Steam`
  - Под ними `Компаньон недоступен для этой игры или издания.` или `Для S.T.A.L.K.E.R. 2 показано только экспериментальное состояние; установка выполняется отдельно по запросу.`
- `[ МОДЫ ]`: кнопка `Моды` и `Отдельный менеджер модов отсутствует; используйте профили в разделе «Среда игры».`

**Действия:**

- `Найти установки` — фоновое сканирование, только чтение.
- Остальные кнопки — переходы между экранами.
- Действие кнопки `Моды` из исходников не определено (обработчик в прочитанных строках не найден).
- На диск и в сеть ничего не пишется.

**Пустые состояния:**

- Нет игр → `●  НЕ НАЙДЕНО` и `Установки не выбраны`.
- Нет сети — не влияет.
- Сейв не нужен.

**Горячие клавиши и фокус:** общие.

**Фон:** поиск установок — текст `Поиск установок…`, кнопка неактивна, отмены нет.

**Чек-лист:**

1. Первый заход → `Поиск установок ещё не выполнялся.`
2. `Найти установки` при установленной ЗП в Steam → строка с источником `Steam`, `●  НАЙДЕНО 1`.
3. Выбрать строку → в `[ ВЫБРАННАЯ ИГРА ]` статус `Установка найдена`, номер сборки и папка.
4. На машине без игр → `●  НЕ НАЙДЕНО`.
5. `⚙ Среда игры` → открыт экран «Среда игры».

## 13. Экран «ИСПРАВЛЕНИЯ ИГРЫ» (game-fixes)

**Назначение:** установка, обновление и удаление проверенных исправлений файлов игры (Game Fix) с защитой по номеру Steam-сборки. Пресеты применяются с резервной точкой.

### 13.1 Элементы

- Заголовок `ИСПРАВЛЕНИЯ ИГРЫ`.
- `ИГРА` — выпадающий список. Каталог исправлений перестраивается при смене игры.
- Поле папки игры (подсказка `ПАПКА ИГРЫ (РУЧНОЙ ВЫБОР)`) и кнопка `Обзор…`.
- Кнопка `ПРОВЕРИТЬ СОВМЕСТИМОСТЬ` — активна, если папка существует и экран не занят.
- Строки статуса:
  - каталог: `ИСПРАВЛЕНИЙ В КАТАЛОГЕ: {0}` / `НЕТ ПРОВЕРЕННЫХ ИСПРАВЛЕНИЙ ДЛЯ ЭТОЙ ВЕРСИИ.`
  - совместимость:
    - `СНАЧАЛА ПРОВЕРЬТЕ УСТАНОВКУ И ВЕРСИЮ.`
    - `ПАПКА НЕ ПОХОЖА НА ВЫБРАННУЮ УСТАНОВКУ ИГРЫ.`
    - `ВЕРСИЯ STEAM НЕ ОПРЕДЕЛЕНА; УСТАНОВКА ИСПРАВЛЕНИЙ С ЗАЩИТОЙ ПО СБОРКЕ НЕДОСТУПНА.`
    - `НАЙДЕНА СБОРКА STEAM: {0}.`
    - `СБОРКА STEAM {0} ПОДДЕРЖИВАЕТ ВЫБРАННОЕ ИСПРАВЛЕНИЕ.` / `СБОРКА STEAM {0} НЕ ПОДДЕРЖИВАЕТ ВЫБРАННОЕ ИСПРАВЛЕНИЕ.`
    - `ОШИБКА: {0}`
  - пресет: `РЕКОМЕНДУЕМЫЙ ПРЕСЕТ ВКЛЮЧАЕТ ОБЯЗАТЕЛЬНЫЕ И РЕКОМЕНДУЕМЫЕ; ИЗМЕНЕНИЯ ТОЛЬКО ПО ЯВНОЙ КОМАНДЕ.`
  - изменения пресета: `НОВЫЕ ИСПРАВЛЕНИЯ В ПРЕСЕТЕ: {0} → {1} (каталог {2} → {3})` или пусто;
  - результат операции.
- `КАТЕГОРИИ` — только просмотр, количество по категориям: `ОБЯЗАТЕЛЬНЫЕ`, `РЕКОМЕНДУЕМЫЕ`, `НЕОБЯЗАТЕЛЬНЫЕ`, `СООБЩЕСТВО`, `ЭКСПЕРИМЕНТАЛЬНЫЕ`.
- `ДОСТУПНЫЕ ИСПРАВЛЕНИЯ` — список. Состояние строки:
  - `НЕ УСТАНОВЛЕНО`
  - `УСТАНОВЛЕНО`
  - `ФАЙЛ ИЗМЕНЁН ПОСЛЕ УСТАНОВКИ`
  - `УДАЛЕНО`
  - `ОБНОВЛЕНИЕ ДОСТУПНО` — установлено, но версия отличается.
  - Зрелость: `ПРОВЕРЕНО` / `ЭКСПЕРИМЕНТАЛЬНО` / `ИССЛЕДОВАНИЕ`.
- Детали выбранного:
  - заголовок (`ВЫБЕРИТЕ ИСПРАВЛЕНИЕ`, если ничего не выбрано) и id;
  - поля `ПРОБЛЕМА`, `ИЗМЕНЕНИЕ`, `ПОДДЕРЖИВАЕМЫЕ STEAM-СБОРКИ`, `ЗАТРАГИВАЕМЫЕ ФАЙЛЫ`, `ИСТОЧНИК` (например, `Источник: Pripyat Reclamation Patch v1.2`).
- Кнопки пресетов: `ПРИМЕНИТЬ: РЕКОМЕНДУЕМЫЕ` (основная), `ПРИМЕНИТЬ: ОБЯЗАТЕЛЬНЫЕ`, `ПРИМЕНИТЬ: ВСЕ БЕЗОПАСНЫЕ`.
- Кнопки исправления: `УСТАНОВИТЬ ВЫБРАННОЕ`, `ОБНОВИТЬ ВЫБРАННОЕ` (видна только при доступном обновлении), `УДАЛИТЬ И ВОССТАНОВИТЬ`.
- Пояснение: `ИСПРАВЛЕНИЕ ЗАПИСЫВАЕТСЯ ТОЛЬКО ПО НАЖАТИЮ КНОПКИ. ПРИ ИЗМЕНЕНИИ УПРАВЛЯЕМОГО ФАЙЛА УДАЛЕНИЕ ОСТАНОВИТСЯ, НЕ ПЕРЕЗАПИСЫВАЯ ЕГО.`

### 13.2 Условия доступности

Условия совместимости, общие для установки, обновления и пресетов:

- экран не занят;
- папка существует;
- проверка совместимости выполнена **для этой же игры и этой же папки** (с учётом символических ссылок);
- маркер установки корректен;
- номер Steam-сборки определён.

Дополнительно:

- **Установить:** совместимость выполнена; сборка входит в список поддерживаемых исправлением; состояние `НЕ УСТАНОВЛЕНО` или `УДАЛЕНО`.
- **Обновить:** совместимость выполнена; сборка поддерживается; доступна новая версия.
- **Пресет:** совместимость выполнена (кроме требования к сборке, если пресет пуст); каждое исправление пресета поддерживает сборку.
- **Удалить:** папка существует; состояние `УСТАНОВЛЕНО` или `ФАЙЛ ИЗМЕНЁН…`. **Проверка совместимости не требуется.**

### 13.3 Действия

Все выполняются в фоне. Подтверждений нет. Запись идёт в папку игры через ядро.

- `ПРОВЕРИТЬ СОВМЕСТИМОСТЬ` — `GameDoctor.Analyze` (только чтение), затем чтение состояний установленных исправлений.
- `УСТАНОВИТЬ ВЫБРАННОЕ` — `GameFixEngine.Install`. Результат: `УСТАНОВЛЕНО: {id}` / `УЖЕ УСТАНОВЛЕНО: {id}`. Ошибка: `ОШИБКА: {0}`.
- `ОБНОВИТЬ ВЫБРАННОЕ` — результат `ОБНОВЛЕНО: {id}` / `УЖЕ АКТУАЛЬНО: {id}`.
- `УДАЛИТЬ И ВОССТАНОВИТЬ` — результат `УДАЛЕНО И ВОССТАНОВЛЕНО: {id}` / `ИСПРАВЛЕНИЕ НЕ БЫЛО УСТАНОВЛЕНО: {id}`. Согласно пояснению на экране, если управляемый файл был изменён, удаление останавливается без перезаписи. Сама реализация в ядре — не определено из исходников.
- Пресеты — `ApplyFixPreset`. Перед применением ядро создаёт **резервную точку** (снимок «Среды игры»).
  - Успех: `ПРЕСЕТ {имя}: УСТАНОВЛЕНО {n}; УЖЕ АКТУАЛЬНЫХ {m}.` + ` · РЕЗЕРВНАЯ ТОЧКА: {id}`.
  - Пустой пресет: `ПРЕСЕТ НЕ СОДЕРЖИТ ПРОВЕРЕННЫХ ИСПРАВЛЕНИЙ ДЛЯ ЭТОЙ ИГРЫ.`
  - Ошибка: `ОШИБКА: {0}` + ` · РЕЗЕРВНАЯ ТОЧКА: {id}` (если точка создана). Откатывается ли установка автоматически — не определено из исходников.
- Где хранятся бэкапы исходных файлов и манифесты — не определено из исходников (`GameFixEngine`).

### 13.4 Пустые состояния

- Нет игры: папка пустая, все кнопки, кроме выбора, неактивны, статус совместимости пуст.
- Папка указана, проверка не выполнена: `СНАЧАЛА ПРОВЕРЬТЕ УСТАНОВКУ И ВЕРСИЮ.`
- Сборка не из Steam или не определена: `ВЕРСИЯ STEAM НЕ ОПРЕДЕЛЕНА…`, установка невозможна.
- Пустой каталог для игры: `НЕТ ПРОВЕРЕННЫХ ИСПРАВЛЕНИЙ ДЛЯ ЭТОЙ ВЕРСИИ.`
- Сейв не нужен. Если сейв выбран и папка пуста, экран сам подставляет его игру и первую найденную установку (только заполнение формы).

### 13.5 Горячие клавиши, фон, отмена

Горячие клавиши общие. Все операции фоновые, флаг `IsBusy` блокирует кнопки. Прогресса и отмены нет.

### 13.6 Чек-лист

1. ЗП Steam → выбрать папку → `УСТАНОВИТЬ ВЫБРАННОЕ` неактивна, статус `СНАЧАЛА ПРОВЕРЬТЕ УСТАНОВКУ И ВЕРСИЮ.`
2. `ПРОВЕРИТЬ СОВМЕСТИМОСТЬ` → `НАЙДЕНА СБОРКА STEAM: <id>.`; при выборе исправления — `…ПОДДЕРЖИВАЕТ ВЫБРАННОЕ ИСПРАВЛЕНИЕ.`
3. `УСТАНОВИТЬ ВЫБРАННОЕ` → `УСТАНОВЛЕНО: <id>`, состояние строки `УСТАНОВЛЕНО`.
4. Изменить путь папки после проверки → установка снова неактивна.
5. Указать папку другой игры → `ПАПКА НЕ ПОХОЖА НА ВЫБРАННУЮ УСТАНОВКУ ИГРЫ.`
6. Вручную изменить установленный файл → `ПРОВЕРИТЬ СОВМЕСТИМОСТЬ` → `ФАЙЛ ИЗМЕНЁН ПОСЛЕ УСТАНОВКИ`. `УДАЛИТЬ И ВОССТАНОВИТЬ` → удаление останавливается, файл не перезаписан.
7. `УДАЛИТЬ И ВОССТАНОВИТЬ` для нетронутого исправления → `УДАЛЕНО И ВОССТАНОВЛЕНО: <id>`, файлы игры совпадают с исходными (сверка SHA-256).
8. `ПРИМЕНИТЬ: РЕКОМЕНДУЕМЫЕ` → статус с `РЕЗЕРВНАЯ ТОЧКА: <id>`, в «Среде игры» появился снимок.
9. GOG-версия без номера сборки Steam → `ВЕРСИЯ STEAM НЕ ОПРЕДЕЛЕНА…`, пресеты и установка неактивны.

## 14. Экран «ДОКТОР ИГРЫ» (game-doctor)

**Назначение:** диагностика установки игры (версия, остатки модов, компаньон, исправления, последний лог падения). Для S2 — временное отключение и восстановление пользовательских модов.

### 14.1 Элементы

- Заголовок `ДОКТОР ИГРЫ`.
- `ИГРА` — выпадающий список. Кнопка `НАЙТИ УСТАНОВКИ`.
- `ОБНАРУЖЕННЫЕ УСТАНОВКИ` — выпадающий список с подсказкой `Установки не найдены — укажите папку ниже`. Выбор подставляет игру и папку.
- `ПАПКА ИГРЫ` — поле (подсказка `ПАПКА ИГРЫ (РУЧНОЙ ВЫБОР)`) и `Обзор…`.
- `ПРОВЕРИТЬ УСТАНОВКУ` — активна при непустой папке и если проверка не идёт.
- Кнопки S2 (видны только для S2 после проверки):
  - `ВРЕМЕННО ОТКЛЮЧИТЬ КАСТОМНЫЕ МОДЫ` — моды включены;
  - `ВОССТАНОВИТЬ КАСТОМНЫЕ МОДЫ` — моды отключены.
- Отчёт:
  - имена строк: `ПАПКА ИГРЫ (РУЧНОЙ ВЫБОР)`, `ВЕРСИЯ`, `МОДИФИКАЦИИ`, `МОД-КОМПАНЬОН`, `ИСПРАВЛЕНИЯ ИГРЫ`, `ПОСЛЕДНИЙ ЛОГ ИГРЫ`, знаки `✓ ⚠ × ?`;
  - таблица `МОДИФИКАЦИИ` (loose-файлы) и аудит файлов: путь, владелец, подробность, знак;
  - сводный статус — краткие итоги проверок через ` · `.
- Строка лога падения:
  - `ПАДЕНИЙ В ПОСЛЕДНЕМ ЛОГЕ НЕ НАЙДЕНО.`
  - `ПАДЕНИЕ: {0}. ИЗВЕСТНОЙ ПРИЧИНЫ В КАТАЛОГЕ НЕТ.`
  - `ИЗВЕСТНОЕ ПАДЕНИЕ {0}. {совет}`, где совет — один из:
    - `УСТАНОВИТЕ ИСПРАВЛЕНИЕ ИГРЫ {0}.`
    - `ОТКРОЙТЕ ПОСЛЕДНИЙ СЕЙВ В ДОКТОРЕ СОХРАНЕНИЯ И ИСПРАВЬТЕ КВЕСТЫ; ЗАТЕМ УСТАНОВИТЕ ИСПРАВЛЕНИЕ ИГРЫ {0}.`
    - `СЛУЧАЙНЫЙ СБОЙ: ЗАГРУЗИТЕ СЕЙВ ЕЩЁ РАЗ ИЛИ БОЛЕЕ РАННИЙ.`
    - `СЕЙВ ПОВРЕЖДЁН: ПОМОЖЕТ ТОЛЬКО БОЛЕЕ РАННИЙ СЕЙВ.`
    - `ДЕЛО В ФАЙЛАХ ИГРЫ: УБЕРИТЕ ОСТАТКИ МОДОВ ИЗ ПАПКИ GAMEDATA И ПРОВЕРЬТЕ ЦЕЛОСТНОСТЬ ФАЙЛОВ В STEAM.`
    - `ИСПРАВЛЕНО В НАРОДНЫХ ПАТЧАХ (SRP ДЛЯ ЧН, ZRP ДЛЯ ТЧ); СРЕДИ НАШИХ ИСПРАВЛЕНИЙ ЕГО НЕТ.`
- Пусто: `ВЫБЕРИТЕ ИГРУ И ПАПКУ УСТАНОВКИ ДЛЯ ПРОВЕРКИ.`

### 14.2 Действия

- `НАЙТИ УСТАНОВКИ` и `ПРОВЕРИТЬ УСТАНОВКУ` — фон, только чтение. Ошибка проверки: отчёт очищается, статус — текст исключения.
- Смена игры или папки сбрасывает отчёт.
- **Отключить или восстановить моды S2** — **без подтверждения**. Фон: `Stalker2ModToggle.Disable/Restore` (как переносятся файлы — не определено из исходников), затем повторная проверка. Статус — сообщение ядра; ошибка — текст исключения.

### 14.3 Пустые состояния, клавиши, фон

- Нет игры → `●  НЕ НАЙДЕНО`, текст пустого состояния.
- Если сейв выбран, а папка пуста, экран сам подставляет игру сейва и первую установку.
- Горячие клавиши общие.
- Фон: поиск, проверка, переключение модов. Прогресса и отмены нет, кнопки неактивны.

### 14.4 Чек-лист

1. `НАЙТИ УСТАНОВКИ` → список заполнен. Выбор подставляет папку.
2. `ПРОВЕРИТЬ УСТАНОВКУ` на чистой ЗП → строки `✓`, `ПАДЕНИЙ В ПОСЛЕДНЕМ ЛОГЕ НЕ НАЙДЕНО.` (если лог чистый).
3. Положить посторонний файл в `gamedata` → строка `МОДИФИКАЦИИ` с `⚠` и файлом в таблице.
4. Указать пустую папку → отчёт с ошибкой папки или сообщение исключения.
5. S2 с модами → видна `ВРЕМЕННО ОТКЛЮЧИТЬ КАСТОМНЫЕ МОДЫ` → нажатие → после повторной проверки видна `ВОССТАНОВИТЬ…`, моды не грузятся в игре.
6. Сменить игру после проверки → отчёт пропал, текст пустого состояния.

## 15. Экран «СРЕДА ИГРЫ» (toolkit-environment)

**Назначение:** снимки и профили управляемого состояния установки (Game Fix, Companion, user.ltx), правка известных настроек `user.ltx` и аудит файлов. Игра и папка берутся из экрана «Исправления игры».

### 15.1 Элементы

- Заголовок `СРЕДА ИГРЫ` и строка `Управляемая установка: {игра} · {папка | не выбрана}`.
- `УПРАВЛЯЕМЫЕ СНИМКИ`:
  - пояснение `Снимки включают только файлы и манифесты Game Fix, Companion и настроек, которыми владеет инструмент. Восстановление повторно применяет их через исходные провайдеры.`;
  - список `{yyyy-MM-dd HH:mm} · {игра} · исправлений: {n} · файлов: {m}`;
  - пусто: `Снимков пока нет: создайте первый кнопкой ниже.`;
  - кнопки `СОЗДАТЬ СНИМОК`, `ВОССТАНОВИТЬ ВЫБРАННЫЙ` (подсказка `Сначала выберите снимок.` / `Восстановление создаст новый резервный снимок.`), `УДАЛИТЬ СНИМОК`, `ОБНОВИТЬ СПИСОК`.
- `ПРОФИЛИ ИГРЫ`:
  - пояснение `Профиль сохраняет установленные идентификаторы Game Fix, состояние Companion и только явные настройки user.ltx, управляемые инструментом.`;
  - поле `ИМЯ ПРОФИЛЯ`;
  - список `{имя} · {игра} · исправлений: {n} · Companion: {включён|выключен}`;
  - пусто: `Профилей пока нет: введите имя и сохраните текущее состояние.`;
  - кнопки `СОХРАНИТЬ ТЕКУЩЕЕ СОСТОЯНИЕ`, `ПРИМЕНИТЬ ПРОФИЛЬ`, `УДАЛИТЬ ПРОФИЛЬ`.
- `НАСТРОЙКИ user.ltx`:
  - пояснение `Редактируются только известные настройки с явным смыслом. Отсутствующее исходное значение означает значение по умолчанию движка; остальные строки сохраняются без изменений.`;
  - поле `ПУТЬ К СУЩЕСТВУЮЩЕМУ user.ltx`, `ОБЗОР…` (диалог `ВЫБЕРИТЕ СУЩЕСТВУЮЩИЙ user.ltx`), `ЗАГРУЗИТЬ`;
  - строки настроек: `Поле зрения камеры`, `Поле зрения HUD`, `Чувствительность мыши`, `Прицел HUD`, `Дистанция отображения прицела`, `Информация HUD`, `Оружие в HUD`, `Динамический прицел`;
  - в строке:
    - `Текущее: {…|Не задано явно; действует значение игры.}`;
    - `По умолчанию: {…|Значение по умолчанию игры|Исходное значение не записано: настройка не менялась инструментом.}`;
    - метка `КОНФЛИКТ: значение изменено вне инструмента` / `ИЗМЕНЕНО ИНСТРУМЕНТОМ` / `НЕ ИЗМЕНЕНО ИНСТРУМЕНТОМ`;
    - поле `Новое значение`;
    - кнопка `ПРИМЕНИТЬ` (подсказка `Сначала разрешите конфликт изменения вне инструмента.` / `Введите значение в допустимом диапазоне.`);
    - кнопка `ПО УМОЛЧАНИЮ` (подсказка `Возвращает исходную строку или удаляет явную команду, если раньше действовало значение движка.`).
- `АУДИТ УСТАНОВКИ`:
  - кнопка `ПРОВЕРИТЬ` и пояснение об аудите (полный текст в `ToolkitEnvironmentView.cs:275`);
  - классы файлов: `ВАНИЛЬНЫЙ ФАЙЛ`, `НЕИЗВЕСТНО`, `УСТАРЕВШИЙ ФИКС ИЗ КАТАЛОГА`, `СОСТОЯНИЕ БЕЗ МАНИФЕСТА`, `УПРАВЛЯЕТСЯ ИНСТРУМЕНТОМ`, `ТРЕБУЕТ ПРОВЕРКИ`;
  - кнопка `ОЧИСТИТЬ УСТАРЕВШИЙ ФИКС` (подсказка `Восстановит файлы только при совпадении текущих и резервных SHA-256.`);
  - итог: `Проверено файлов: {0}. Безопасных устаревших фиксов: {1}. Ванильными отмечены только файлы с известным хэшем точной сборки; прочие остаются неизвестными.`

### 15.2 Условия доступности

- Создать снимок и сохранить профиль — X-Ray и выбрана установка. Для профиля ещё нужно непустое имя.
- Восстановить снимок — снимок той же игры и той же папки.
- Применить профиль — профиль той же игры и выбрана установка. Остальные условия — не определено из исходников (строка обрезана).
- Загрузить user.ltx — X-Ray и папка существует.
- Аудит — папка существует.
- Удаление — выбран элемент.

### 15.3 Действия (подтверждений нет ни у одного)

| Действие | Запись | Успех | Ошибка |
|---|---|---|---|
| СОЗДАТЬ СНИМОК | хранилище снимков (путь не определён) | `Создан снимок: {0}` | `Не удалось создать снимок: {0}` |
| ВОССТАНОВИТЬ ВЫБРАННЫЙ | файлы игры через провайдеров; перед этим новый резервный снимок (по подсказке) | сообщение ядра | `Не удалось восстановить снимок: {0}` |
| УДАЛИТЬ СНИМОК | удаление снимка | `Снимок удалён: {0}` | `Не удалось удалить снимок: {0}` |
| СОХРАНИТЬ ТЕКУЩЕЕ СОСТОЯНИЕ | хранилище профилей | `Профиль сохранён: {0}` | `Не удалось сохранить профиль: {0}` |
| ПРИМЕНИТЬ ПРОФИЛЬ | файлы игры, компаньон, user.ltx | сообщение ядра | `Не удалось применить профиль: {0}` |
| УДАЛИТЬ ПРОФИЛЬ | удаление профиля | `Профиль удалён.` | `Не удалось удалить профиль: {0}` |
| ЗАГРУЗИТЬ | — | `Загружено настроек user.ltx: {0}` / `Настройки содержат конфликт: {0}` | `Не удалось прочитать user.ltx: {0}` |
| ПРИМЕНИТЬ (строка) | user.ltx и состояние переопределений | `Настройка обновлена: {0}` | `Не удалось изменить настройку: {0}` |
| ПО УМОЛЧАНИЮ | user.ltx | `Восстановлено значение игры: {0}` | `Не удалось восстановить настройку: {0}` |
| ОЧИСТИТЬ УСТАРЕВШИЙ ФИКС | восстановление исходных байтов | `Устаревший фикс снят; восстановлено файлов: {0}.` | `Не удалось очистить фикс: {0}` |
| ПРОВЕРИТЬ (аудит) | — | итог выше | `Не удалось проверить установку: {0}` |

- Если между загрузкой и применением сменилась установка: `Выбрана другая установка: настройки нужно прочитать заново.`
- Ошибка чтения состояния при обновлении: `Не удалось прочитать управляемые данные: {0}`.

### 15.4 Пустые состояния, клавиши, фон

- Нет установки → `Управляемая установка: … · не выбрана`, кнопки создания неактивны.
- S2 → снимки, профили и user.ltx недоступны (только X-Ray); аудит доступен.
- Горячие клавиши общие.
- Фоновые операции: создание и восстановление снимка, применение профиля. Остальные выполняются синхронно в UI-потоке. Флаг `IsBusy` блокирует кнопки. Прогресса и отмены нет.

### 15.5 Чек-лист

1. Без папки в «Исправлениях игры» → `Управляемая установка: … · не выбрана`, `СОЗДАТЬ СНИМОК` неактивна.
2. С папкой ЗП → `СОЗДАТЬ СНИМОК` → `Создан снимок: <id>`, строка в списке.
3. Установить исправление → `ВОССТАНОВИТЬ ВЫБРАННЫЙ` (снимок до установки) → исправление снято, появился ещё один резервный снимок.
4. Ввести имя → `СОХРАНИТЬ ТЕКУЩЕЕ СОСТОЯНИЕ` → `Профиль сохранён: <имя>`.
5. Указать user.ltx → `ЗАГРУЗИТЬ` → 8 строк настроек. Изменить `g_fov` → `ПРИМЕНИТЬ` → в файле новое значение, остальные строки не тронуты.
6. Вручную изменить `g_fov` в файле → `ЗАГРУЗИТЬ` → `КОНФЛИКТ: …`, `ПРИМЕНИТЬ` неактивна.
7. `ПО УМОЛЧАНИЮ` → исходная строка вернулась или явная команда удалена.
8. `ПРОВЕРИТЬ` (аудит) → итог `Проверено файлов: …`

## 16. Экран «КОМПАНЬОН» (companion)

**Назначение:** установка и удаление мода-компаньона в выбранную игру, проверка связи, живой инспектор, команды S2, глобальные горячие клавиши.

### 16.1 Элементы

- Заголовок `МОД-КОМПАНЬОН` и `Меню в игре: Esc → F1 или КПК компаньона. Установка через приложение ниже.`
- `Целевая игра:` — список:
  - `S.T.A.L.K.E.R. Зов Припяти`, `S.T.A.L.K.E.R. Чистое Небо`, `S.T.A.L.K.E.R. Тень Чернобыля`;
  - `Зов Припяти (Enhanced Edition)`, `Чистое Небо (Enhanced Edition)`, `Тень Чернобыля (Enhanced Edition)`.
- `СТАТУС И СВЯЗЬ`:
  - состояние: `РАБОТАЕТ (ПОДКЛЮЧЁН)` / `УСТАНОВЛЕН (ОЖИДАНИЕ ИГРЫ)` / `НЕ УСТАНОВЛЕН` / `ОШИБКА`;
  - `Версия мода:`, `Связь / Задержка:` (`{0:F0} мс`, `Нет ответа`, `Ошибка`, или `{0:F0} сек назад` для последнего пинга), `Путь установки:`;
  - список проблем установки (если есть).
- Кнопки:
  - `УСТАНОВИТЬ / ОБНОВИТЬ` — активна, если не занято и состояние не «работает»;
  - `УДАЛИТЬ` — активна, если не занято и мод установлен;
  - `ПРОВЕРИТЬ СВЯЗЬ` — мод установлен или работает;
  - `ОБНОВИТЬ СТАТУС`.
- `ЖИВОЙ ИНСПЕКТОР`:
  - `Показываются только ответы протокола Companion: info и list_inventory.`;
  - `ПОЛУЧИТЬ ДАННЫЕ`;
  - причина недоступности: `Для живой проверки нужен установленный Companion-протокол.` / `Установите Companion для выбранной игры; живые данные доступны при запущенной игре.`;
  - блоки `Информация игрока`, `Инвентарь игрока`.
- `S.T.A.L.K.E.R. 2 — команды игры (экспериментально)` — виден, если поддерживается:
  - `Нужны S2 на ПК, UE4SS и установленный мод. Команды выполняет сама игра (XSetGodMode, XSetNoClipGSC, XSetTimeSpeed).`;
  - кнопки `Бессмертие: вкл`, `Бессмертие: выкл`, `Полёт: вкл`, `Полёт: выкл`, `Время ×5`, `Время: норма`.
- `ВСЕ ИГРЫ`:
  - таблица игр с флажками; путь или `не найдена`;
  - статус: `работает` / `мод установлен {версия}` / `ошибка: …` / `мод не установлен` / `игра не найдена`;
  - для S2 — `S.T.A.L.K.E.R. 2 (экспериментально, нужен UE4SS)` и `нет UE4SS: установите его, затем мод`;
  - кнопка `УСТАНОВИТЬ / ОБНОВИТЬ ВО ВСЕ ОТМЕЧЕННЫЕ`.
- `ПАПКА ИГРЫ (РУЧНОЙ ВЫБОР)`:
  - `Оставьте пустым для автоматического поиска через Steam. Укажите путь вручную, если папка нестандартная.`;
  - поле `/путь/к/папке/игры`, кнопка `ПРИМЕНИТЬ`.
- `ГОРЯЧИЕ КЛАВИШИ`:
  - `Приложение перехватывает сочетание и отправляет команду моду через файл-протокол. Игра должна быть запущена с установленным модом.`;
  - переключатель `Горячие клавиши`, список назначений;
  - кнопки `СОХРАНИТЬ КЛАВИШИ` и `ПО УМОЛЧАНИЮ`;
  - причина, если не поддерживается.
- Строка статуса (видна, если не пуста).

### 16.2 Действия (подтверждений нет; все асинхронные)

| Действие | Запись | Сообщения |
|---|---|---|
| Установить / обновить | файлы мода в `gamedata` игры (ядро) | `Установка компаньона в gamedata…` → `Компаньон успешно установлен!` / `Не удалось установить компаньон — убедитесь, что папка игры найдена.` / `Ошибка установки: {0}` |
| Во все отмеченные | то же для каждой игры | `Установка в «{0}»…` → `{игра}: Готово` / `{игра}: не установлен, причина — в строке игры` через `; ` + `. Перезапустите игры, которые были открыты.` |
| Удалить | удаление файлов мода | `Удаление компаньона…` → `Компаньон удалён.` / `Не удалось удалить компаньон.` / `Ошибка удаления: {0}` |
| Проверить связь | файл-протокол | `Проверка связи с модом…` → `Мод отвечает. Задержка: {0:F0} мс` (или сообщение ядра) / `Компаньон не отвечает. Убедитесь, что игра запущена.` / `Ошибка пинга: {0}` |
| Обновить статус | — | ошибка `Ошибка обновления статуса: {0}` |
| Получить данные | файл-протокол | `Чтение ответов Companion…`; ошибка `Не удалось получить данные Companion: {0}` |
| Команда S2 | файл-протокол | `Отправка в игру…` → `Игра выполнила: {0}` / `Не выполнено: {0}` |
| Применить папку | — (сохранение — не определено из исходников) | `Папка задана: {0}` / `Папка очищена, используется автообнаружение.` / `Папка не найдена: {0}` |
| Горячие клавиши вкл/выкл | — (глобальный перехват) | `Включение горячих клавиш…` → `Горячие клавиши активированы: {0}.` / `Горячие клавиши отключены.` / `Не удалось включить горячие клавиши: {0}` / `Не удалось отключить горячие клавиши: {0}` / `Ошибка горячих клавиш: {0}` |
| Сохранить клавиши | файл раскладки (путь не определён) | `Клавиши сохранены: {0}.` / `Клавиши сохранены, но перезапуск не удался: {0}` / `Клавиши не сохранены: {0}` |

### 16.3 Пустые состояния, клавиши, фон

- Нет игры → статус `НЕ УСТАНОВЛЕН`, в таблице `игра не найдена`, установка завершается сообщением о ненайденной папке.
- Игра не запущена → пинг `Нет ответа`.
- Веб → экран недоступен.
- **Горячие клавиши:** при включении приложение перехватывает сочетания глобально, вне окна. Какие сочетания назначены по умолчанию — не определено из исходников (`HotkeySummary`).
- Фон: все команды. Прогресс — только текст статуса, отмены нет. Есть ли периодический опрос статуса — не определено из исходников (таймера во ViewModel нет).

### 16.4 Чек-лист

1. Игра ЗП найдена, мод не установлен → `НЕ УСТАНОВЛЕН`, `УДАЛИТЬ` неактивна.
2. `УСТАНОВИТЬ / ОБНОВИТЬ` → `Компаньон успешно установлен!`, состояние `УСТАНОВЛЕН (ОЖИДАНИЕ ИГРЫ)`, в `gamedata` появились файлы мода.
3. Без запущенной игры `ПРОВЕРИТЬ СВЯЗЬ` → `Компаньон не отвечает. Убедитесь, что игра запущена.`, `Нет ответа`.
4. С запущенной игрой → `Мод отвечает. Задержка: N мс`, состояние `РАБОТАЕТ (ПОДКЛЮЧЁН)`, `УСТАНОВИТЬ` неактивна.
5. `ПОЛУЧИТЬ ДАННЫЕ` → заполнены `Информация игрока` и `Инвентарь игрока`.
6. `УДАЛИТЬ` → `Компаньон удалён.`, файлов мода нет.
7. Отметить две игры → `…ВО ВСЕ ОТМЕЧЕННЫЕ` → итог по каждой и `. Перезапустите игры, которые были открыты.`
8. Указать несуществующую папку → `ПРИМЕНИТЬ` → `Папка не найдена: …`

## 17. Экран «ДОСТИЖЕНИЯ» (achievements)

**Назначение:** просмотр и ручная выдача или снятие достижений Steam для игр серии.

### 17.1 Элементы

- Заголовок `ДОСТИЖЕНИЯ STEAM` и строка доступности Steam: сообщение адаптера, иначе `Steam доступен` / `Steam не запущен или недоступен.` (в вебе `Steam недоступен: host`).
- Выпадающий список, по умолчанию первый пункт:
  - `S.T.A.L.K.E.R.: Зов Припяти (41700)`
  - `S.T.A.L.K.E.R.: Чистое Небо (20510)`
  - `S.T.A.L.K.E.R.: Тень Чернобыля (4500)`
  - `S.T.A.L.K.E.R. 2: Heart of Chornobyl (1643320)`
- Поиск `Поиск по названию или описанию...` — по названию, описанию и api-имени.
- Кнопка `ОБНОВИТЬ`.
- Прогресс: `{0} из {1} получено ({2:F0}%)` и полоса.
- Строка достижения:
  - значок `🏆` / `🔒`;
  - название (или api-имя);
  - описание (или `Скрытое достижение`);
  - статус `Получено: yyyy-MM-dd HH:mm` / `Получено` / `Не получено`;
  - кнопка `СНЯТЬ` или `ПОЛУЧИТЬ`.
- Окно подтверждения (оверлей):
  - заголовок `РАЗБЛОКИРОВАТЬ ДОСТИЖЕНИЕ` / `СНЯТЬ ДОСТИЖЕНИЕ`;
  - текст `Вы действительно хотите разблокировать достижение «{0}» в Steam?` / `Вы действительно хотите снять достижение «{0}» в Steam?`;
  - кнопки `ПОДТВЕРДИТЬ`, `ОТМЕНА`.
- Нижняя строка статуса.

### 17.2 Действия

- **Смена игры** — автоматическая загрузка списка. Сообщения:
  - `Запрос достижений для {0}...` → `Загружено {0} достижений.` / `Достижения не найдены (проверьте подключение к Steam).` / `Ошибка загрузки достижений: {0}`.
- **`ОБНОВИТЬ`** — то же.
- **`ПОЛУЧИТЬ`/`СНЯТЬ`** → **подтверждение обязательно**.
  - `ПОДТВЕРДИТЬ` → `Обновление «{0}» в Steam...` → Steam API `SetAsync` (запись в сеть и аккаунт пользователя).
  - Результат: `Достижение «{0}» получено в Steam.` / `Достижение «{0}» снято в Steam.` / `Ошибка изменения достижения: {0}`.
  - Пока идёт изменение, новый запрос не принимается.
- Локальной записи и бэкапа нет.

### 17.3 Пустые состояния, клавиши, фон

- Steam не запущен или нет сети → строка доступности. После загрузки — `Достижения не найдены (проверьте подключение к Steam).`, прогресс `0 из 0 получено (0%)`.
- **При первом открытии экрана список не загружается**: начальный выбор совпадает с умолчанием 41700, поэтому событие смены не возникает. Нужно нажать `ОБНОВИТЬ` или сменить игру.
- Esc и Enter в оверлее не назначены.
- Фон: загрузка и изменение. Прогресса нет, кроме статуса. Отмены нет.

### 17.4 Чек-лист

1. Открыть экран при запущенном Steam → список пуст. `ОБНОВИТЬ` → `Загружено N достижений.`, прогресс заполнен.
2. Выбрать ЧН → список перезагружен автоматически.
3. Поиск по части описания → список сузился.
4. `ПОЛУЧИТЬ` → оверлей `РАЗБЛОКИРОВАТЬ ДОСТИЖЕНИЕ`. `ОТМЕНА` → ничего не изменилось.
5. `ПОЛУЧИТЬ` → `ПОДТВЕРДИТЬ` → `Достижение «…» получено в Steam.`, прогресс +1. В клиенте Steam достижение получено.
6. Steam закрыт → строка `Steam не запущен или недоступен.` (или сообщение адаптера).

## 18. Экран «ОБЛАКО» (cloud)

**Назначение:** список сейвов в Steam Cloud рядом с локальными. Можно скачать облачный сейв на диск или записать локальный файл в облако (с явным подтверждением).

### 18.1 Элементы

- Заголовок `СОХРАНЕНИЯ В STEAM CLOUD` и строка статуса Steam: сообщение адаптера, иначе `Steam доступен` / `Steam не запущен или недоступен.`
- Выпадающий список, по умолчанию `Все игры`:
  - `Все игры`
  - `S.T.A.L.K.E.R.: Тень Чернобыля (4500)`
  - `S.T.A.L.K.E.R.: Чистое Небо (20510)`
  - `S.T.A.L.K.E.R.: Зов Припяти (41700)`
  - `S.T.A.L.K.E.R. 2: Heart of Chornobyl (1643320)`
- Кнопка `ОБНОВИТЬ СПИСОК`.
- Список. Строка: имя файла, `{игра} • {0:F1} КБ • {yyyy-MM-dd HH:mm:ss|—}` и бейдж сравнения:
  - `Размер и время совпадают`
  - `Облачный новее`
  - `Локальный новее`
  - `Только в облаке`
  - `Только локально`
  - `Неизвестно`
- Пусто: `Сейвов в облаке не найдено. Выберите игру или нажмите «Обновить список».`
- Правая панель `ДЕЙСТВИЯ С СОХРАНЕНИЕМ`:
  - имя и удалённый путь выбранного файла;
  - кнопки `СКАЧАТЬ В ЛОКАЛЬНЫЕ`, `ЗАПИСАТЬ В ОБЛАКО...`;
  - памятка: `Безопасность Steam Cloud:` + `• Запись в облако требует явного подтверждения.` + `• Перед записью автоматически создаётся страховочный бэкап.` + `• Если статус Uncertain — автоматический повтор запрещён.`
- Карточка подтверждения (видна после `ЗАПИСАТЬ В ОБЛАКО...`):
  - `ПОДТВЕРЖДЕНИЕ ПЕРЕЗАПИСИ`;
  - `Внимание: локальный файл будет отправлен в Steam Cloud и перезапишет облачное сохранение. Резервная копия будет сохранена в бэкапы.`;
  - флажок `Я подтверждаю перезапись`;
  - кнопки `ЗАПИСАТЬ` (активна только с флажком) и `ОТМЕНА`.
- Строка статуса.

### 18.2 Доступность

- `СКАЧАТЬ В ЛОКАЛЬНЫЕ`: выбран файл, не идёт загрузка списка или запись.
- `ЗАПИСАТЬ В ОБЛАКО...`: выбран файл; локальный файл существует; не идёт загрузка или запись; Steam доступен; игра **не S2** (1643320 — запрет записи).
- Смена выбора или обновление списка отменяет начатое подтверждение.

### 18.3 Действия

- **Обновить список** — по каждой игре фильтра запрос в Steam (`ListCloudFilesAsync`). Для сопоставления передаются локальные сейвы **той же игры** из библиотеки.
  - Сообщения: `Запрос списка сохранений Steam Cloud...` → `Найдено {0} сохранений в облаке.` / `В Steam Cloud не найдено сохранений для выбранных игр.` / `Ошибка загрузки списка: {0}`.
- **Скачать в локальные** — **без подтверждения**:
  1. Чтение файла из облака.
  2. Проверка, что это сейв S.T.A.L.K.E.R. Иначе: `Файл из облака — не сохранение S.T.A.L.K.E.R. или повреждён; локальный файл не тронут.`
  3. Проверка, что сейв той же игры. Иначе: `Файл из облака — сохранение другой игры ({0}); локальный файл не тронут.`
  4. Если есть сопоставленный локальный файл, он должен быть сейвом той же игры или нечитаемым. Иначе: `Локальный файл {0} — сохранение другой игры ({1}); он не тронут.`. Затем `LocalSaveReplacement.ReplaceWithBytes`: бэкап с журналом (виден в «Бэкапах»), атомарная замена, обратное чтение должно распознать формат.
  5. Если локального файла нет: атомарная запись в `<папка бэкапов>/cloud_downloads/<имя>` с правами только для владельца.
  6. Успех: `Файл {0} успешно скачан: {1}`. Файл открывается в библиотеке, список обновляется.
  7. Ошибка: `Ошибка скачивания: {0}`.
- **Записать в облако**:
  - `ЗАПИСАТЬ В ОБЛАКО...` фиксирует **намерение**: приложение, удалённый путь, локальный путь и SHA-256 локального файла на этот момент. Затем показывается подтверждение. Ошибка чтения: `Ошибка записи: {0}`.
  - `ЗАПИСАТЬ` (с флажком):
    - повторная сверка SHA-256; если файл изменился: `Локальный файл изменился после запроса записи; подтвердите запись ещё раз.`;
    - затем `WriteCloudFileAsync` (адаптер создаёт страховочный бэкап в папку бэкапов, Steam RemoteStorage, проверка).
  - Сообщения:
    - `Запись {0} в Steam Cloud (RemoteStorage)...`
    - `Записано и проверено: {0}` (Verified)
    - `Результат записи не подтверждён (повтор не выполняется): {0}` (Uncertain)
    - `Запись отменена: {0}` (Aborted)
    - `Ошибка записи: {0}`
  - Автоматического повтора нет.
- `ОТМЕНА` — сброс намерения.

### 18.4 Пустые состояния, клавиши, фон

- Нет Steam → `Steam не запущен или недоступен.`. Список пуст, запись недоступна. Скачивание недоступно, так как список пуст.
- Нет сети → поведение адаптера, не определено из исходников. Ошибки показываются как `Ошибка загрузки списка: {0}`.
- **При первом открытии список не загружается** (по той же причине, что в §17.3). Нужно нажать `ОБНОВИТЬ СПИСОК` или сменить фильтр.
- Веб → экран недоступен.
- Esc и Enter не назначены.
- Фон: список, скачивание, запись. Прогресса нет, кроме статуса. Отмены нет.

### 18.5 Чек-лист

1. Открыть экран → список пуст, текст пустого состояния. `ОБНОВИТЬ СПИСОК` → облачные сейвы с бейджами.
2. Фильтр `Зов Припяти (41700)` → автоматически перезагружен только ЗП.
3. Выбрать файл `Облачный новее` → `СКАЧАТЬ В ЛОКАЛЬНЫЕ` → локальный файл заменён, в «Бэкапах» новая запись, статус `…успешно скачан: <путь>`.
4. Файл `Только в облаке` → скачивание кладёт файл в `<бэкапы>/cloud_downloads/`.
5. Выбрать S2 → `ЗАПИСАТЬ В ОБЛАКО...` неактивна.
6. `ЗАПИСАТЬ В ОБЛАКО...` → `ЗАПИСАТЬ` неактивна без флажка. Поставить флажок → `ЗАПИСАТЬ` → `Записано и проверено: …`
7. После `ЗАПИСАТЬ В ОБЛАКО...` изменить локальный файл → `ЗАПИСАТЬ` → `Ошибка записи: Локальный файл изменился после запроса записи; подтвердите запись ещё раз.`
8. Выбрать другой файл, когда подтверждение открыто → карточка подтверждения скрыта.

## 19. Экран «ЭНЦИКЛОПЕДИЯ» (encyclopedia)

**Назначение:** каталог предметов установленной игры (с учётом модов). Предмет можно добавить в черновик выбранного сейва или выдать в запущенную игру через компаньон.

**Элементы:**

- Заголовок `ЭНЦИКЛОПЕДИЯ ПРЕДМЕТОВ`.
- Выпадающий список игры — только игры с загруженным контентом. Названия: `Тень Чернобыля` / `Чистое Небо` / `Зов Припяти` / …
- `У каждой записи показаны имя, значок, вес, цена и секция из файлов установленной игры.`
- Статус источника: `Источник: установленные файлы игры и мод «{0}».` / `Источник: файлы выбранной установленной игры.` / `Установленный каталог предметов не загружен.`
- Строка предмета:
  - значок, имя, `Вес: {0} · Цена: {1} · Секция: {2}`, категория;
  - кнопка `В сохранение` — подсказка `Выберите совместимое сохранение с поддержкой добавления предметов.`;
  - кнопка `В игру` — подсказка `Выберите эту игру в Компаньоне и подключитесь к запущенной игре.`
- Пусто: `Нет загруженного каталога установленной игры.`

**Доступность:**

- `В сохранение` — выбранный сейв той же игры (EE приводится к базовой) с `CanAddItems`.
- `В игру` — компаньон выбран на эту игру и может выдавать предметы (`CanSpawnForGame`).

**Действия:**

- `В сохранение` — запрос в черновик: секция × 1 в рюкзак. Статус в строке состояния окна: `Предмет {0} (1 шт.) добавлен в очередь на запись.` Подтверждения нет.
- `В игру` — команда компаньону через файл-протокол. Сообщение берётся из результата компаньона, точные тексты не определены из исходников.

**Пустые состояния:**

- Нет игры → `Нет загруженного каталога установленной игры.`
- Нет сейва, другая игра или 1.0.x → `В сохранение` неактивна.
- Компаньон не подключён → `В игру` неактивна.
- Веб → экран недоступен.

**Горячие клавиши и фокус:** общие.

**Фон:** загрузка контента установленных игр при старте (§1.9), выдача через компаньон. Отмены нет.

**Чек-лист:**

1. ЗП установлена → список предметов с весом и ценой, источник — файлы игры.
2. Выбран сейв ЗП → `В сохранение` → бейдж черновика +1 → после `СОХРАНИТЬ` предмет в инвентаре.
3. Выбран сейв ТЧ → у предметов ЗП `В сохранение` неактивна, подсказка про совместимое сохранение.
4. Компаньон подключён к запущенной ЗП → `В игру` → предмет появился в игре.
5. Нет установленных игр → `Нет загруженного каталога установленной игры.`

## 21. Экран «ОБНОВЛЕНИЯ» (updates)

**Назначение:** проверка, загрузка и запуск установки новой версии приложения.

**Элементы:**

- Заголовок `ОБНОВЛЕНИЕ ПРИЛОЖЕНИЯ`.
- `ТЕКУЩАЯ ВЕРСИЯ` и `ПОСЛЕДНЯЯ ВЕРСИЯ` (пусто до проверки).
- Бейдж состояния: `У вас актуальная версия` (зелёный) / `Доступно обновление` (жёлтый) / `Обновление недоступно` (серый) / `Ошибка проверки манифеста` (красный) / `Статус неизвестен`.
- Кнопки:
  - `ПРОВЕРИТЬ ОБНОВЛЕНИЯ` — активна, если не занято;
  - `СКАЧАТЬ ОБНОВЛЕНИЕ` — доступно обновление, есть пакет для платформы, не занято;
  - `УСТАНОВИТЬ ОБНОВЛЕНИЕ` — пакет скачан и существует, не занято.
- Карточка прогресса (видна, пока занято): текст этапа и полоса 0–100 (заполняется только при скачивании с известным размером).
- Красная карточка ошибки (видна при ошибке).
- Строка статуса.

**Действия (сеть; подтверждений нет):**

- **Проверить** — запрос манифеста.
  - `Проверка наличия обновлений...` → `Доступна новая версия {0}!` (и баннер) / `Установлена последняя версия приложения.`
  - Другое состояние: ошибка `result.Error`, иначе `Не удалось проверить обновления.`; статус `Проверка завершилась с ошибкой.`
  - Исключение: ошибка — текст исключения; статус `Ошибка подключения к серверу обновлений.`
  - При тихой проверке на старте ошибки не показываются.
- **Скачать** — `Скачивание пакета обновления...`, прогресс по байтам.
  - Успех: `Пакет обновления скачан: {0}`, полоса 100.
  - Ошибка: `Ошибка скачивания: {0}`, статус `Не удалось завершить скачивание.`
  - Куда пишется пакет и как проверяется SHA-256 из манифеста — не определено из исходников.
- **Установить** — `Установка обновления...`.
  - `Обновление запущено: {0}` (успех или открыто внешним установщиком).
  - Ошибка `Установка не удалась ({0}): {1}` и статус `Ошибка установки обновления.`
  - Исключение: `Ошибка запуска установки: {0}` и статус `Не удалось запустить установку.`

**Пустые состояния:**

- Нет сети → при ручной проверке `Ошибка подключения к серверу обновлений.` + текст ошибки.
- Веб и платформа без самообновления → бейдж `Обновление недоступно`, при ручной проверке ошибка `Не удалось проверить обновления.`
- Сейв и игра не нужны.

**Горячие клавиши и фокус:** общие.

**Фон:** проверка (в том числе тихая на старте), скачивание с прогрессом, установка. **Отмены нет.**

**Чек-лист:**

1. Без сети → `ПРОВЕРИТЬ ОБНОВЛЕНИЯ` → красная карточка, статус `Ошибка подключения к серверу обновлений.`
2. Есть новая версия → бейдж `Доступно обновление`, баннер в оболочке, `СКАЧАТЬ` активна.
3. `СКАЧАТЬ ОБНОВЛЕНИЕ` → полоса растёт до 100, `Пакет обновления скачан: <файл>`, `УСТАНОВИТЬ` активна.
4. Во время скачивания все три кнопки неактивны.
5. Последняя версия → `У вас актуальная версия`, `Установлена последняя версия приложения.`
6. `×` на баннере → баннер скрыт, экран «Обновления» не изменился.

## 22. Экран «НАСТРОЙКИ» (settings)

### 22.1 Элементы

Слева — `Разделы` (кнопки категорий). Справа — содержимое. Внизу — `Сохранить настройки` и строка статуса (зелёная). При открытии экрана всегда выбран раздел `ОБЩИЕ`.

| Раздел (кнопка) | Описание под заголовком | Содержимое |
|---|---|---|
| `ОБЩИЕ` | `УПРАВЛЕНИЕ ОСНОВНЫМ ПОВЕДЕНИЕМ РЕДАКТОРА` | `[ STEAM CLOUD ]`: `Откройте экран Steam Cloud, чтобы просматривать состояние синхронизации и выполнять действия с явным подтверждением.` и кнопка `Открыть Steam Cloud` |
| `ИНТЕРФЕЙС` | `ЯЗЫК, ЗВУК И АНИМАЦИИ` | `Язык интерфейса:` (15 языков) и `Язык применится после перезапуска приложения.`; `Тема оформления:` `Зона (тёмная)` / `Чистое небо` / `День`; `Акцентный цвет:` `Янтарный` / `Бирюзовый` / `Синий` / `Ржавый`; `Масштаб интерфейса:` `По размеру экрана` / 100% / 110% / 125% / 150% / 175% / 200%; `Тема, акцент и масштаб применяются сразу и сохраняются автоматически.` |

### 22.2 Действия

- **Тема, акцент, масштаб** — применяются сразу и **сразу записываются** в `settings.json` (атомарно). Ошибка записи: `Не удалось сохранить настройки: ` + сообщение.
- **Язык** — сохраняется кнопкой `Сохранить настройки` и применяется после перезапуска.
- **Звук и музыка** — применяются только после `Сохранить настройки`.
- **Добавить папку**:
  - путь обрезается; дубликат (без учёта регистра) **молча** игнорируется; существование не проверяется;
  - статус `Папка добавлена: {0}`;
  - запись `settings.json` **со всеми текущими значениями экрана**, в том числе ещё не сохранёнными (язык, звук, папка бэкапов).
- **Удалить** — без подтверждения, статус `Папка удалена из списка.`, запись `settings.json` (то же замечание).
- **Автопоиск папок на диске** — `Автопоиск завершён. Добавлено папок: {0}.` / `Автопоиск завершён. Новых папок не найдено.`; запись `settings.json`, только если что-то добавлено.
- Изменение списка папок **не перечитывает библиотеку**. Нужна кнопка `Обновить`.
- **Папка бэкапов** — значение поля используется **сразу** для следующих записей, ещё до сохранения (см. §24). Существование папки не проверяется.
- **Сохранить настройки** — полная запись `settings.json`. Статус `Настройки сохранены.`; ошибка `Не удалось сохранить настройки: ` + сообщение.
- **Проверить окружение** — фон, статусы:
  - `Проверяю…`
  - `Всё в порядке.`
  - `Ошибок: {0}, предупреждений: {1}.`
- **Сохранить отчёт…** — диалог `Отчёт для поддержки`, имя `save-editor-report.txt.gz`. В файл пишется пакет: обезличенный журнал, сбой, окружение, логи модов S2.
  - Успех: `Отчёт сохранён: ` + путь.
  - Ошибки: `Не удалось сохранить отчёт: ` + сообщение; если выбрана папка — `Указана папка, а не файл.`
- **Отправить отчёт сейчас** — сеть, **без подтверждения и независимо от флажка отправки**.
  - Успех: `Отчёт отправлен, номер: {0}`.
  - Ошибка: `Отчёт не отправлен: {0}`.
  - Время отправки записывается в `settings.json`.
- **Скрыть ошибку** — `CrashReporter.Dismiss()` (удаление файла сбоя — не определено из исходников). Баннер сбоя скрывается.
- **Флажок отчётов** — сохраняется кнопкой `Сохранить настройки` или вместе с любой автоматической записью.
- **Кнопки-переходы** — открывают «Облако», «Обновления», «Исправления игры».

### 22.3 Пустые состояния, клавиши, фон

- Нет игры или сейвов → список папок пуст. Автопоиск: `Автопоиск завершён. Новых папок не найдено.`
- Нет сети → `Отчёт не отправлен: …`
- Без диагностики (не десктоп) → `Диагностика недоступна в этом контексте.`
- Горячие клавиши общие.
- Фон: проверка окружения (кнопка неактивна) и отправка отчёта. Отмены нет.

### 22.4 Чек-лист

1. Открыть Настройки → выбран раздел `ОБЩИЕ`.

## 24. Расхождения и вероятные дефекты C# 1.3.1

Эти пункты не нужно переносить как требования. Их надо явно решить: воспроизводить или исправлять.

1. **`ru.json` игнорируется для русского языка** (§0.1). Тексты вроде «Доктор игры», «Выберите игру и папку установки для проверки.» на экран не попадают.
2. **Плашки «Настройки → Диагностика»** ссылаются на несуществующее название: раздел называется `ИНСТРУМЕНТЫ ДЛЯ ПОДДЕРЖКИ`. Кнопка `Открыть` на плашке сбоя открывает раздел `ОБЩИЕ`.
3. **`Друг (+1500)` / `Враг (-1500)`** обрезаются диапазоном каталога (по умолчанию −3000…1000). Подпись кнопки «Друг» не совпадает с результатом.
4. **`В ТАЙНИК` и `+ СОЗДАТЬ В ТАЙНИКЕ`** включаются по `CanAddItems`, а не `CanEditStashes`.
5. **Окно создания предмета в тайнике** называется `Добавить предмет в инвентарь`.
6. **Список в «Тайниках»** предлагает и предметы, удалённые в черновике.
7. **«Достижения» и «Облако»** не загружают данные при первом открытии.
8. **Строки достижений** после `ПОДТВЕРДИТЬ` не обновляют кнопку `СНЯТЬ`/`ПОЛУЧИТЬ` и бейдж статуса до повторной загрузки (значения взяты при построении шаблона).
9. **`ПЕРЕНЕСТИ`** всегда активна. Без выбранной точки — тишина, без сообщения.
10. **Перенос, ремонт квестов, восстановление на место** не проверяют несохранённый черновик (перенос проверяет только `CanSave`). Черновик остаётся привязанным к старому SHA и при следующем открытии того же файла не подхватывается.
11. **«История сохранений»** не перестраивается после сохранения или восстановления — до `Обновить`.
12. **Папка бэкапов** применяется сразу, до `Сохранить настройки`. Добавление или удаление папки сейвов сохраняет в `settings.json` и прочие несохранённые поля экрана.
13. **Изменение списка папок сейвов** не перечитывает библиотеку автоматически.
14. **`Отправить отчёт сейчас`** работает при выключенных отчётах.
15. **Кнопка `Моды`** на «Обзоре игр»: обработчик нажатия в прочитанном коде не найден, действие не определено из исходников.
16. **Esc и Enter** нигде не назначены, в том числе в модальном окне и оверлеях подтверждения.
17. **Флаг CRC сейва** (`CrcOk`) вычисляется, но нигде не показывается.
18. **Язык по умолчанию** при неподдерживаемом системном — английский.
19. **Восстановление в копию** всегда даёт расширение `.sav`, даже для `.scop` / `.scs`.

### 0. Соглашения

1. **Тексты ошибок ядра — английские.** В UI они попадают внутрь шаблонов вида `Не удалось сохранить: {0}`, `Ошибка восстановления: {0}`, `ОШИБКА: {0}` и не переводятся. Эталон — строки ниже; их надо сохранить дословно или осознанно заменить вместе с этим документом.

### 2. Атомарная запись (`Storage/AtomicFile.cs`, `Patching/GameFileSystem.cs`)

**`DurableFile.WriteNew(path, bytes, ownerOnly)`**:

- `CreateNew` — отказ, если файл уже есть;
- `WriteThrough`, затем `Flush(flushToDisk: true)`;
- при `ownerOnly` на Unix режим `0600`;
- при ошибке созданный файл удаляется.

**`DurableFile.Move(src, dst, overwrite)`**: `File.Move`, затем fsync каталога назначения. Делается только на Linux/macOS, ошибки fsync игнорируются; на Windows не выполняется.

**`AtomicFile.WriteAllBytes`** — для собственных файлов приложения (кэши, настройки, профили):

- временный файл `.<имя>.<guid>.tmp` в той же папке;
- `WriteNew`, затем `Move(overwrite)`;
- временный файл удаляется в любом случае.

**`AtomicGameFileWriter.Write`** — для файлов игры:

- временный файл `<путь>.tmp-<guid>`;
- `WriteNew` **без** ограничения прав (файлы игры сохраняют обычные права);
- `Move`.

**Требования к Rust:**

- После прерывания процесса на любом шаге целевой файл содержит либо старые, либо новые байты целиком.
- Временные файлы при штатной ошибке не остаются.
- На Unix файлы сейвов, бэкапов, журналов и черновиков создаются с правами `0600`.

**Чек-лист:**

1. Убить процесс в момент записи `settings.json` (например, точка останова между `WriteNew` и `Move`) → `settings.json` содержит прежнюю версию; рядом может остаться `.settings.json.<guid>.tmp`, только если процесс был именно убит.
2. После любого успешного сохранения сейва на Linux → `stat -c %a` у бэкапа, `_EDITED.sav`, журнала и **самого сейва** = `600` (см. §15 п.1).

### 3. `EditService` — подготовка правки (`Editing/EditService.cs`)

**Назначение:** проверяет, разрешена ли правка для формата; превращает план правки (`EditPlan`) в новые байты сейва (`PreparedEdit`); проверяет результат.

#### 3.1 Разрешения (`CanEdit`)

- `CanEdit(releaseId)` без видов правок равносильно «можно писать `edit_money`».
- `CanEdit(releaseId, kinds)` — для каждого вида правки нужны **все** перечисленные возможности со зрелостью `experimental` или `verified`:

| Вид правки (`EditKind`) | Когда входит в план | Нужные возможности |
|---|---|---|
| Money | `Money != null` | `edit_money` |
| StackCounts | есть пачки | `edit_stacks` |
| Delete | есть удаления | `remove_items` |
| Add | есть добавления | `add_items` |
| XRayStashTransfer | есть `StashTakes` или `StashPuts` | **`add_items`** |
| Stalker2StashTransfer | задан `Stalker2StashTakeHandle` | `move_items` |
| Upgrades | есть апгрейды | `edit_upgrades` |
| Durability | есть прочность | `edit_durability` |
| Placement | есть размещения | `edit_placement` |
| Faction | есть отношения | `edit_relations` **и** `edit_player_faction` |

**Матрица возможностей** — встроенный `Capabilities/Data/capability-snapshot.json` (v = verified, e = experimental, — = unsupported):

| Возможность | ТЧ | ЧН | ЗП | ТЧ EE | ЧН EE | ЗП EE | S2 |
|---|---|---|---|---|---|---|---|
| edit_money | v | v | v | e | e | e | e |
| edit_stacks | v | v | v | e | e | e | e |
| edit_durability | e | e | e | — | — | — | e |
| edit_placement | e | e | e | — | — | — | — |
| edit_upgrades | — | e | e | — | — | — | — |
| edit_relations | e | e | e | — | — | — | — |
| edit_player_faction | e | e | e | — | — | — | — |
| move_items | e | e | e | — | — | — | — |
| add_items | v | v | v | e | e | e | — |
| remove_items | v | v | v | e | e | e | — |

**Следствия:**

- **S2 доступен для записи по ядру** (деньги, пачки, прочность) — см. поправку к `ACCEPTANCE.md` в §14.
- Сейв S2 версии 1.0.x всё равно не пишется: `Stalker2SaveReader.RequireWritableLayout` выдаёт `This save was written by game version 1.0.x. It can be read, but its layout is not supported for editing; load it in the current game and save again.`

#### 3.2 `PrepareEdit(source, plan, releaseId, catalogs)`

**Проверки до записи — по порядку, в каждом случае файл не меняется:**

1. **`ValidatePlan`.** Один и тот же предмет и удаляется, и правится (пачка, прочность, апгрейд, размещение, тайник) → `The plan both edits and removes item 0x{h:X4}; remove the item or keep the edit, not both.`
2. **Определение формата.**
   - По `releaseId` с псевдонимами `soc`, `clear_sky`, `cop`, `s2`, иначе по байтам.
   - Не удалось → `Could not detect save format for editing.`
3. **Ветка X-Ray:**
   - в плане есть передача из тайника S2 → `The plan holds a S.T.A.L.K.E.R. 2 stash transfer, which an X-Ray save cannot take.`;
   - фактический формат байтов отличается от запрошенного → `The save is '{actual}', not the requested release '{requested}'.`;
   - **стадии в фиксированном порядке:** правки на месте (деньги, пачки, тайники, апгрейды, отношения, прочность, размещение), затем удаления, затем добавления. Каждая стадия работает по результату предыдущей;
   - для добавления нужен каталог: `X-Ray edit: adding items requires the release catalog.`;
   - для апгрейдов нужен каталог апгрейдов: `X-Ray edit: upgrade edits require a release-matched upgrade catalog.`;
   - **предварительная проверка до записи:** готовые байты проходят `VerifyReadBack`. Если не проходят → `The prepared save does not match the requested edits; nothing was written. ` + причина.
4. **Ветка S2:**
   - пустой план → `S.T.A.L.K.E.R. 2 edit: EditPlan must include at least one supported S2 edit.`;
   - лишние виды правок → `S.T.A.L.K.E.R. 2 edit: EditPlan contains unsupported edit kinds for S.T.A.L.K.E.R. 2: {kinds}.`;
   - разрешены только Money, StackCounts, Durability, Stalker2StashTransfer.
5. **Прочие форматы** → `Unsupported release for editing: '{id}'.`

#### 3.3 `VerifyReadBack(data, releaseId, plan)` — что проверяется после записи

| Проверка | X-Ray | S2 |
|---|---|---|
| формат не изменился (`The replaced save changed its detected release.`) | да | да |
| деньги (`The replaced save money does not match the requested value.`) | да | да |
| пачки (`The replaced save stack 0x… does not match the requested value.`) | да | да |
| положенное в тайник лежит в тайнике (`The replaced save does not hold item 0x… in stash 0x….`) | да | — |
| взятое из тайника лежит в рюкзаке (`The replaced save does not hold item 0x… in the inventory.`) | да | — |
| прочность, апгрейды, размещение, отношения, удаление, добавление | **нет** | **нет** |

**Требование к Rust:** как минимум та же глубина проверки. Расширить её на остальные виды правок рекомендуется (§15 п.3).

#### 3.4 Чек-лист

1. План «удалить предмет 0x0042 и изменить его пачку» → исключение `The plan both edits and removes item 0x0042…`, файл не тронут.
2. Сейв ЗП с `releaseId="stalker-cs"` → `The save is 'stalker-cop', not the requested release 'stalker-cs'.`
3. План добавления без каталога → `X-Ray edit: adding items requires the release catalog.`
4. Сейв S2 1.0.x + деньги → сообщение про 1.0.x, файл не тронут.
5. `CanEdit("stalker-soc", Upgrades)` → `false`; `CanEdit("stalker-cop", Upgrades)` → `true`.
6. `CanEdit("stalker2", Money)` → `true` (по снимку возможностей 1.3.1).
7. `CanEdit("stalker-cop", XRayStashTransfer)` при `add_items = unsupported` (подменённый снимок) → `false`, даже если `move_items` доступна.

### 4. `LocalSaveReplacement` — замена сейва на диске (`Backups/LocalSaveReplacement.cs`)

**Назначение:** единственный путь записи сейва на месте. Через него идут: `СОХРАНИТЬ`, перенос персонажа, ремонт квестов, скачивание из облака поверх локального файла (`ReplaceWithBytes`).

#### 4.1 Шаги `ReplaceLocal(sourcePath, prepared, backupDir, verifyReadback)`

1. **Проверка ссылки.** Если сейв — символическая ссылка → `The save is a symbolic link; open the file it points to instead.`
2. **Сверка исходника.** Чтение сейва и сравнение SHA-256 с `prepared.SourceSha256`. Не совпало → `Source changed since analysis: expected {a}, found {b}.` (Обычно до этого не доходит: каждый писатель формата сам сверяет SHA исходника с планом и бросает `<формат> <вид> edit: Source SHA256 does not match the edit plan.`)
3. **Сверка подготовленных байтов.** SHA-256 подготовленных байтов должен совпасть с записанным → иначе `Prepared output bytes do not match their recorded SHA256.`
4. **Расположение папки бэкапов.** Если она совпадает с папкой сейва или вложена в неё → `Backup directory must be outside the selected save directory.` (тип `ArgumentException`). Папка бэкапов создаётся при необходимости.
5. **Имена артефактов.** Префикс `<stem≤64>_<yyyyMMddTHHmmssfffffffZ>_<guid32>`:
   - `<префикс>_ORIGINAL.sav` — исходные байты (бэкап);
   - `<префикс>_EDITED.sav` — новые байты (копия для восстановления);
   - `<префикс>_ORIGINAL.json` — журнал.
6. **Запись артефактов.** `WriteNew` (права владельца, без перезаписи) в порядке: бэкап, затем копия для восстановления, затем журнал со статусом `prepared`.
7. **Временный файл.** Новые байты пишутся во временный файл `.<имя>.<guid>.tmp` **в папке сейва**.
8. **Повторная сверка исходника** прямо перед заменой. Не совпало → `Source changed before replacement: expected {a}, found {b}.`
9. **Атомарная замена** сейва временным файлом.
10. **Обратное чтение.** Байты и SHA-256 должны совпасть с подготовленными → иначе `Replaced save read-back did not match the prepared output bytes.`. Затем вызывается переданная проверка `verifyReadback` (для `СОХРАНИТЬ` — `EditService.VerifyReadBack`).
11. **Фиксация.** Журнал переписывается со статусом `verified` (атомарно).
12. **Квитанция** (`receipt`): `SourcePath`, `BackupPath`, `RecoveryPath`, `JournalPath`, `OutputSha256`.

#### 4.2 Ошибки и откат

- **Ошибка на шагах 1–5:** сейв не тронут, на диске ничего не создано.
- **Ошибка на шагах 6–8:** сейв не тронут, исключение пробрасывается как есть. **Уже записанные** `_ORIGINAL.sav`, `_EDITED.sav` и журнал `prepared` **не удаляются**. В «Бэкапах» они видны как `Повреждён` с ошибкой `Journal status is not verified.` (§15 п.2).
- **Ошибка после шага 9** (сейв уже заменён): `LocalSaveReplacementException`. Текст: `The save was replaced, but read-back verification did not complete. Original backup: {backup}; edited recovery: {recovery}; journal: {journal}.`. **Автоматического отката нет.** Сейв остаётся с новыми байтами, журнал — в статусе `prepared`, восстановление из UI невозможно (запись `Повреждён`). Вернуть файл можно только вручную, скопировав `_ORIGINAL.sav`.
- Временные файлы (`*.tmp`) удаляются в любом случае; ошибка удаления не скрывает основную ошибку.
- Журнал приложения: `save written {file}: {src12} -> {out12}, read-back ok` или `save write failed {file}` с исключением.

#### 4.3 Формат журнала (JSON с отступами, ключи snake_case)

```json
{
  "version": 1,
  "status": "prepared | verified",
  "created_at": "<ISO-8601 UTC, формат O>",
  "source_path": "<полный путь сейва>",
  "source_sha256": "<sha256 исходника>",
  "output_path": "<тот же путь>",
  "output_sha256": "<sha256 результата>",
  "backup_path": "<…_ORIGINAL.sav>",
  "recovery_path": "<…_EDITED.sav>",
  "operation": { "mode": "replace", "money": <uint|null>, "stack_count": <int> }
}
```

В `operation` попадают только деньги и **количество** изменённых пачек. Остальные виды правок в журнал не пишутся.

#### 4.4 `ReplaceWithBytes(sourcePath, bytes, backupDir, verify)`

Строит `PreparedEdit.Replacing(sha256(текущий файл), bytes)` с пустым планом и вызывает `ReplaceLocal`. Журнал получает `mode = "replace"`, `money = null`, `stack_count = 0`. Такой бэкап можно восстановить на место (см. §5).

#### 4.5 Чек-лист

1. Сохранить сейв → в папке бэкапов появилась тройка `*_ORIGINAL.sav`, `*_EDITED.sav`, `*_ORIGINAL.json`; в журнале `"status": "verified"`; SHA-256 бэкапа = `source_sha256`.
2. В папке сейва после успеха нет файлов `.*.tmp`.
3. Задать в настройках папку бэкапов внутри папки сейвов → `СОХРАНИТЬ` → `Не удалось сохранить: Backup directory must be outside the selected save directory. (Parameter 'backupDirectory')`.
4. Сделать сейв символической ссылкой → `Не удалось сохранить: The save is a symbolic link; open the file it points to instead.`
5. Между открытием и сохранением перезаписать сейв в игре → `СОХРАНИТЬ` → ошибка от писателя формата ещё на этапе `PrepareEdit`, например `Не удалось сохранить: X-Ray money edit: Source SHA256 does not match the edit plan.` (префикс зависит от первой стадии: `X-Ray stack edit:`, `S.T.A.L.K.E.R. 2 money edit:` и т. п.). Новых записей в «Бэкапах» нет. Сообщение `Source changed since analysis` появляется, только если файл изменился между `PrepareEdit` и `ReplaceLocal`.
6. Подменить `verifyReadback` на бросающий исключение (тест) → сообщение `The save was replaced, but read-back verification did not complete…`; сейв содержит новые байты; журнал остался `prepared`; в «Бэкапах» запись `Повреждён`.
7. Скачать сейв из облака поверх локального → журнал с `"mode": "replace"`, `"money": null`, `"stack_count": 0`; «Восстановить на место» доступно.

### 5. `LocalSaveStorage` — список и восстановление бэкапов (`Backups/LocalSaveStorage.cs`)

#### 5.1 `ListBackups(dirs)` и `InspectBackup(journal)`

**Что сканируется.** В каждой папке (без рекурсии):

- все `*.json` как журналы;
- все `*_ORIGINAL.sav`, у которых нет журнала, — они дают запись `Corrupt` с ошибкой `Journal for this backup is missing.`

**Сортировка.** По `created_at` (новые сверху), затем по пути журнала в обратном порядке.

**Хэш при обновлении списка** берётся из кэша сессии, если размер и mtime файла не изменились. Восстановление всегда хэширует заново.

**Статусы:**

| Статус | Причина (`Error`) |
|---|---|
| `Verified` | журнал корректен, бэкап на месте, его SHA-256 = `source_sha256` |
| `Missing` | `Backup file is missing.` |
| `Corrupt` | `Backup cannot be read: {msg}` / `Backup SHA256 does not match the journal.` |
| `Corrupt` (ошибка журнала) | `Journal is missing.` / `Journal cannot be read: {msg}` / `Journal must contain a JSON object.` / `Journal is corrupt: {msg}`, где `{msg}` — одна из причин ниже |

Возможные причины в `{msg}` для `Journal is corrupt`:

- `Unsupported journal version.`
- `Journal field {f} must be a non-empty string.`
- `Journal field {f} is not a SHA256 value.`
- `Journal status is not verified.`
- `Journal operation must be an object.`

**Обязательные поля журнала:** `version` = 1, `created_at`, `source_path`, `source_sha256`, `output_path`, `output_sha256`, `backup_path`, `status` = `verified`, `operation` (объект). Относительный `backup_path` считается от папки журнала.

#### 5.2 `RestoreBackup(journal, outputPath)` — UI «Восстановить в копию»

1. Бэкап обязан быть `Verified` → иначе `Backup is not restorable ({Status}): {Error}`.
2. Цель — не сам файл бэкапа → иначе `Restore output cannot be the backup file.`
3. Цель не должна существовать → иначе `Restore output already exists: {path}.`
4. Папка цели должна существовать → иначе `Restore output directory does not exist: {dir}.`
5. Бэкап читается и хэшируется ещё раз → при расхождении `Backup changed after its last verification.`
6. Атомарная публикация: временный файл, затем `Move` **без перезаписи**.
7. Обратное чтение → при расхождении `Restored output read-back did not match its expected bytes.`
8. Квитанция: путь, бэкап, SHA. Новый журнал **не создаётся**, страхующий бэкап не нужен (новый файл).

#### 5.3 `RestoreInPlace(journal)` — UI «Восстановить на место»

Проверки по порядку:

1. Статус `Verified` (как в §5.2 п.1).
2. `operation.mode` равен `replace` или `restore` → иначе `Journal does not describe an in-place save replacement.`
3. `output_path` совпадает с `source_path` → иначе `Journal output path does not match its source save.`
4. Сейв — не символическая ссылка → иначе `Restoring a symbolic-link save is refused.`
5. Папка сейва существует → иначе `Source save directory does not exist: {dir}.`
6. Бэкап читается заново с проверкой SHA (`Backup changed after its last verification.`).
7. **Сейва нет на месте** → выполняется `RestoreBackup` прямо в путь сейва. Страхующего бэкапа нет, в квитанции `SafetyBackupPath = null`.
8. **Текущий сейв должен иметь SHA = `output_sha256` журнала**, то есть быть ровно тем, что записал редактор. Иначе — **отказ**: `Current save changed after the journaled replacement; refusing to overwrite it.` (см. §14 п.3).
9. Папка журнала (папка бэкапов) — вне папки сейва → иначе `Backup directory must be outside the save directory. (Parameter 'backupDirectory')`.

Запись:

- страхующий бэкап текущего файла: новый `<stem>_<stamp>_<guid>_ORIGINAL.sav` и его журнал `prepared` с `operation = {mode: "restore", restore_from: <бэкап>}`;
- байты бэкапа пишутся во временный файл в папке сейва;
- повторная сверка текущего файла → при расхождении `Current save changed immediately before in-place restore.`;
- атомарная замена, затем обратное чтение (`Restored save read-back did not match its expected bytes.`);
- журнал страхующего бэкапа переписывается со статусом `verified`.

После этого страхующий бэкап сам виден в списке и восстанавливается на место (`mode = restore`). Так можно отменить восстановление.

**Отката нет:** если обратное чтение после замены не сошлось, журнал остаётся `prepared`. Страхующий `_ORIGINAL.sav` лежит на диске, но в UI показывается как `Повреждён`.

#### 5.4 `ExportLocal` (в UI 1.3.1 не используется)

Запись результата правки в **новый** файл, исходник не трогается.

- Требования: цель не равна исходнику и не существует, папка цели существует, папка бэкапов — вне папки сейва.
- Тексты отказов:
  - `Export output cannot be the selected source save.`
  - `Export output already exists: …`
  - `Export output directory does not exist: …`
  - `Writing through a symbolic-link save is refused.`
  - `Source save does not exist.`
  - `Source changed since the edit was prepared.`
  - `Source changed immediately before export publication.`
  - `Export output read-back did not match its expected bytes.`
- В журнале `mode = "export"` и счётчики (`money`, `stack_count`, `detach_count`, `add_count`, остальные — 0).
- Такой бэкап можно восстановить только в копию.

#### 5.5 Чек-лист

1. Сохранить сейв, затем сразу `Восстановить на место` → сейв побайтно равен `_ORIGINAL.sav`; появилась новая запись `Проверен` (страхующая, `mode = restore`).
2. Сохранить сейв, **сохраниться в игре в тот же слот**, затем `Восстановить на место` → `Ошибка восстановления: Current save changed after the journaled replacement; refusing to overwrite it.`; файл не изменён.
3. В том же случае `Восстановить в копию` → создан `<имя>_restored_<дата>.sav`, равный бэкапу.
4. Удалить сейв, затем `Восстановить на место` → файл сейва появился, страхующей записи нет.
5. Изменить 1 байт в `_ORIGINAL.sav` → `Обновить бэкапы` → `Повреждён`, `Backup SHA256 does not match the journal.`
6. Удалить журнал у бэкапа → запись `Повреждён` с `Journal for this backup is missing.`
7. Поменять `"status"` в журнале на `prepared` → `Journal is corrupt: Journal status is not verified.`
8. Восстановить на место страхующую запись из п.1 → сейв вернулся к отредактированной версии.

### 6. `DraftStore` — черновики правок (`Editing/DraftStore.cs`)

#### 6.1 Хранение

- **Папка:** `<данные>/drafts` (или переданная явно).
- **Файл:** `<sha256 исходного сейва>.json`. Ключ проверяется регулярным выражением `^[0-9a-f]{64}$`; иначе `Draft key must be a lowercase SHA256.`
- **Лимит размера:** 2 МиБ. Если полная история не влезает, сохраняются только шаг 0 (нетронутый сейв) и текущий шаг. Если не влезает и это → `Current edit draft exceeds the storage limit.`
- **Глубина истории:** шаг 0 и последние 100 шагов (`MaximumSteps`). Более старые шаги сливаются в шаг 0.
- **Запись атомарная:** временный файл `.<sha>.<guid>.tmp`, права владельца, затем `Move`.
- **Если текущий шаг пустой** (в терминах п. 6.2) и нет непонятых правок, файл **удаляется** вместо записи.

#### 6.2 Формат (схема 2, ключи camelCase, лишние поля запрещены)

```json
{
  "index": 3,
  "plans": [ { "sourceSha256": "…", "money": 12345, "stackCounts": {"66": 30},
               "detachHandles": [17], "adds": [ … ], "stashTakes": [ … ], "stashPuts": [ … ],
               "unmappedLegacyPlan": null } ],
  "schema": 2,
  "source_sha256": "…"
}
```

**В черновик на диске пишутся только:** деньги, пачки, удаления, добавления, взятие из тайника, перенос в тайник.

**Не пишутся:** прочность, апгрейды, размещение, отношения группировок, группировка игрока, передача из тайника S2. В текущей сессии они живут в памяти, а **после перезапуска пропадают**. Черновик, в котором есть только они, на диск не попадает вовсе (§14 п.1, §15 п.4).

#### 6.3 Чтение (`Load`)

Возвращает `null`, то есть «черновика нет», **молча**, если:

- файла нет или он больше 2 МиБ;
- JSON повреждён;
- нет поля `schema`, или схема не 1 и не 2;
- набор полей корня отличается от ожидаемого;
- `source_sha256` не совпадает с ключом;
- текущий шаг пуст.

**Схема 1** — черновики Python-версии:

- читаются деньги, пачки, удаления, добавления;
- если в плане непустые `attach`, `durability`, `faction_relations`, `moves`, `placements`, `raw`, `upgrades`, строковый `player_faction`, неизвестные поля или глубокие удаления, шаг помечается как «непонятые правки» (`unmappedLegacyPlan`);
- в таком состоянии UI запрещает правку и запись (`ACCEPTANCE.md` §1.2 п.2).

#### 6.4 Удаление и «отложить рядом»

- `Remove(sha)` — `File.Delete` (если файла нет, ошибки нет).
- `SetAside(sha)` — переименование в `<sha>.json.unsupported-<yyyyMMddHHmmssfff>` (UTC); возвращает новый путь или `null`, если файла нет.
- После успешного `СОХРАНИТЬ` черновик старого SHA удаляется (`SaveEditSession`). Черновики, осиротевшие после переноса, ремонта квестов или восстановления, **не удаляются** и копятся в папке.

#### 6.5 Чек-лист

1. Изменить деньги → в `drafts/<sha>.json` поле `"money"` с новым значением; права файла `600`.
2. Отменить правку до исходного состояния (Ctrl+Z) → файл черновика удалён.
3. Изменить **только** прочность предмета, перезапустить приложение → правка прочности потеряна, файла черновика нет.
4. Изменить деньги и прочность, перезапустить → деньги восстановлены, прочность — нет.
5. Сделать 150 правок денег → в файле `plans.length` = 101; Ctrl+Z работает 100 раз.
6. Положить черновик схемы 1 с `"upgrades": ["x"]` → при открытии сейва UI показывает текст о правках из другой версии. `Сбросить` → файл переименован в `….json.unsupported-<время>`.
7. Записать в черновик битый JSON → сейв открывается без черновика, без сообщения об ошибке.

### 7. `GameFixEngine` — исправления игры (`Patching/GameFixEngine*.cs`)

#### 7.1 Каталог

- Встроенный `Patching/Data/game-fixes.json`: 148 определений, все со зрелостью `Validated`.
  - ЗП: Essential 8, Recommended 14, Community 14.
  - ЧН: Essential 28, Recommended 45, Community 2.
  - ТЧ: Essential 12, Recommended 23.
  - ТЧ EE: Essential 2.
- **Пресеты** включают только `Validated` и не `Experimental`:
  - `ОБЯЗАТЕЛЬНЫЕ` — только Essential;
  - `РЕКОМЕНДУЕМЫЕ` — Essential + Recommended;
  - **`ВСЕ БЕЗОПАСНЫЕ` — ровно то же, что `РЕКОМЕНДУЕМЫЕ`** (Community не входит) — см. §15 п.7.

#### 7.2 Состояние в папке игры

`<игра>/.save-editor-game-fixes/<fixId>/`:

- **`manifest.json`** (camelCase, с отступами):
  - `schemaVersion` = 2, `fixId`, `game`, `steamBuildId`, `version`;
  - описательные поля из каталога;
  - `installed` (true/false);
  - `files[]`: `relativePath`, `beforeSha256`, `afterSha256`, `backupPath` (`backups/file-NNNN.before`), `targetExistedBefore`.
- **`backups/file-NNNN.before`** — исходные байты каждого изменённого файла. При удалении исправления **не удаляются**: повторная установка той же версии использует их, сверив хэш.
- **`transaction.json`** — журнал незавершённой операции: `schemaVersion`, `kind` (install/uninstall), `freshState`, `files`.
- **`RECOVERY.txt`** — пишется, только если откат не удался. Содержит построчную инструкцию «какой `.before` → в какой файл игры».

#### 7.3 `Install(definition, gameDir)` — UI «УСТАНОВИТЬ ВЫБРАННОЕ»

**Проверки до записи:**

1. Определение корректно, `fixId` соответствует `^[a-z0-9][a-z0-9.-]{0,127}$`.
2. Путь к состоянию не идёт через ссылки.
3. **`RecoverInterrupted`** — сначала завершаются транзакции, прерванные ранее (§7.6).
4. Папка проходит структурную проверку игры → иначе `The selected directory does not pass the structural game check.`
5. Найденная сборка Steam входит в `supportedSteamBuildIds` → иначе `This fix does not list the detected Steam build as supported.`
6. Определение проверено на retail-файлах → иначе `Game Fix installation requires validation against the supported retail files; synthetic-test definitions are not installable.`
7. Если манифест уже есть:
   - установлена другая версия → `A different version of this fix is installed; remove it before updating.`;
   - установлено, файлы совпадают → результат `Changed = false` (UI: `УЖЕ УСТАНОВЛЕНО: {id}`);
   - установлено, файлы изменены → `A managed game file changed after the fix was installed; refusing to overwrite it.`;
   - удалено, но версия другая → `Reinstalling a removed fix requires the same fix version so its original backup remains authoritative.`
8. Папка состояния есть, а манифеста нет → `Fix state exists without a valid manifest; refusing to reuse it.`
9. Зависимости и конфликты:
   - `Required fix is not installed: {id}`;
   - `This fix conflicts with installed fix: {id}`.
10. Файл уже управляется другим активным исправлением → `Another active Game Fix manages {path}; layered transformations are not supported for this file.`
11. Пересечение с файлами компаньона запрещено (`EnsureNoCompanionOverlap`).

**Порядок записи:**

1. Журнал `install` со списком файлов (**до** первого бэкапа).
2. Для каждого файла — бэкап `.before` (атомарно, без перезаписи). Если бэкап уже есть от прежней установки, проверяется его хэш:
   - `The stored recovery file no longer matches the original hash: {path}`;
   - `The stored recovery file is missing: {path}`.
3. Для каждого файла — повторная сверка с предварительной проверкой (`A managed game file changed after preflight; refusing to overwrite it: {path}`), затем атомарная запись нового содержимого.
4. Манифест с `installed: true` пишется **последним**, затем журнал удаляется.

**Откат при ошибке:**

- Изменённые файлы возвращаются из памяти. Затем удаляются новые бэкапы и манифест (или восстанавливается прежний манифест) и журнал; пустые папки состояния удаляются.
- Тексты:
  - `Game Fix installation failed: {msg}`;
  - `Game Fix installation failed: {msg}; rollback problems: {…}`.
- Если файлы игры не удалось вернуть: состояние **не удаляется**, пишется `RECOVERY.txt`, текст `Game Fix installation failed: {msg}; the game files could not all be restored ({…}). The original files are kept in {backups}; see {RECOVERY.txt}.`

#### 7.4 `Update` и `Uninstall`

**`Update`** (UI «ОБНОВИТЬ ВЫБРАННОЕ»):

- Манифеста нет → обычная установка. Не установлено или версия та же → обычная установка.
- Версии сравниваются как числа:
  - понижение или неоднозначность → `Fix updates must use an increasing numeric version; downgrade and ambiguous version transitions are blocked.`;
  - набор файлов должен совпадать → `In-place updates that change the managed file set are not supported; the old fix must be removed and reviewed first.`;
  - каждый управляемый файл на месте и не изменён:
    - `A managed game file is missing; refusing to update: {path}`;
    - `A managed game file changed after installation; refusing to update it: {path}`.
- Бэкапы `.before` сохраняются от первой установки.
- При ошибке откат к старой версии и старому манифесту. Если манифест за это время изменился посторонним образом — `manifest changed during update rollback`.

**`Uninstall`** (UI «УДАЛИТЬ И ВОССТАНОВИТЬ»):

- Сначала `RecoverInterrupted`.
- Манифеста нет → `Changed = false`, `NotInstalled` (UI: `ИСПРАВЛЕНИЕ НЕ БЫЛО УСТАНОВЛЕНО`). Уже удалено → `Changed = false`, `Removed`.
- Есть зависимые исправления → `Remove dependent fixes first: {ids}`.
- Для каждого файла:
  - текущий хэш = `afterSha256` → иначе **отказ** `A managed game file changed after installation; refusing to restore it: {path}`;
  - бэкап совпадает с `beforeSha256` → иначе `A recovery file failed its hash check: {path}`.
- Журнал `uninstall`, затем для каждого файла повторная проверка (`…changed after removal preflight; refusing to restore it: {path}`). Если файл существовал до установки, пишется `.before`; иначе файл **удаляется**.
- Манифест переписывается с `installed: false`, журнал удаляется. **Папка состояния и бэкапы остаются.**
- При ошибке файлы возвращаются в установленное состояние, манифест восстанавливается.
  - Тексты: `Game Fix removal failed: {msg}` / `…; rollback problems: …`.

**`CheckUninstall`** — те же проверки без записи. Возвращает причину:

- `The provider manifest is missing.`
- `The manifest does not record an active fix.`
- `Remove dependent fixes first: …`
- `A managed game file is missing: …`
- `A managed game file changed after installation: …`
- `A recovery file is missing: …`
- `A recovery file failed its hash check: …`

#### 7.5 Пресеты: `ApplyPreset` и снимок-страховка

UI вызывает `ToolkitSnapshotService.ApplyFixPreset`:

1. Если сборка совместима со всеми исправлениями пресета и хотя бы одно не установлено → **создаётся снимок среды** (§8). Его id показывается в UI как `РЕЗЕРВНАЯ ТОЧКА`.
2. `GameFixEngine.ApplyPreset`:
   - пресет `Custom` запрещён (`Custom selections must be installed explicitly from the Game Fixes screen.`);
   - папки нет → `The selected directory does not exist.`;
   - в пресете есть несовместимое исправление:
     - `A preset can contain only safe fixes for the selected game.`
     - `Preset application requires fixes validated against the supported retail files.`
     - `A preset cannot contain the same fix more than once.`
     - `The selected directory does not pass the structural game check.`
     - `The detected Steam build is not supported by every selected Game Fix.`
   - есть исправление в состоянии `Modified` → `A preset fix has an externally modified managed file; review it before applying the preset: {id}`;
   - остальные устанавливаются по одному. При сбое уже поставленные в этом вызове **удаляются в обратном порядке**. Текст: `Preset application failed; newly installed fixes were rolled back: {msg}` или `Preset application failed: {msg}; rollback problems: …`.
3. Если шаг 2 бросил исключение и снимок есть → восстанавливается снимок. Тексты:
   - `Preset application failed and the previous managed state was restored: {msg}`;
   - `Preset application failed: {msg}. {сообщение восстановления}`;
   - `Preset application failed: {msg}. Automatic restore also failed: {msg2}. Safety snapshot {id} is retained.`

#### 7.6 Восстановление после прерывания (`RecoverInterrupted`)

Вызывается автоматически перед каждой установкой и удалением в этой папке игры. Для каждой папки `<fixId>` с `transaction.json`:

- **Журнал не читается** → `The Game Fix transaction journal is unreadable; restore the game files manually: {path}`.
- **Неизвестная схема или вид** → `The Game Fix transaction journal has an unknown format: {path}`.
- **Операция уже зафиксирована** (для установки `installed: true`, для удаления `installed: false`) → журнал просто удаляется.
- **Иначе** каждый файл возвращается в исходное состояние:
  - файл совпадает с `before` → ничего не делать;
  - файл совпадает с `after` → вернуть `.before` или удалить, если файла раньше не было;
  - файл не совпадает ни с тем, ни с другим → ошибка, ручное восстановление.

#### 7.7 Чек-лист

1. Установить исправление → в `.save-editor-game-fixes/<id>/` есть `manifest.json` (`"installed": true`), `backups/file-0000.before` с SHA = `beforeSha256`, нет `transaction.json`.
2. Удалить исправление → файлы игры побайтно равны `.before`; манифест `"installed": false`; бэкапы на месте.
3. Повторно установить ту же версию → бэкапы переиспользованы (хэш проверен), новых файлов `.before` нет.
4. Изменить управляемый файл вручную → `Удалить` → `ОШИБКА: Game Fix removal failed: …` или отказ `…refusing to restore it: <путь>`; файл не тронут.
5. Убить процесс во время установки (после записи части файлов) → при следующей установке или удалении любого исправления в этой папке все файлы прерванной операции возвращены к исходным, журнал удалён.
6. Испортить `transaction.json` → следующая операция: `ОШИБКА: The Game Fix transaction journal is unreadable; restore the game files manually: …`
7. Установить исправление, у которого есть зависимое, затем удалить базовое → `Remove dependent fixes first: <id>`.
8. Пресет `ВСЕ БЕЗОПАСНЫЕ` на ЗП → установлено столько же исправлений, сколько у `РЕКОМЕНДУЕМЫЕ` (22); Community не ставятся.
9. Пресет, где третье исправление падает (подменённый файл) → первые два удалены, статус содержит `rolled back` или `previous managed state was restored`.

### 8. Снимки, профили, user.ltx (кратко; используются экраном «Среда игры» и пресетами)

**Снимки** (`ToolkitSnapshotService`):

- Хранилище:
  - `<данные>/snapshots/snapshots/<id32hex>/snapshot.json` — метаданные;
  - `<данные>/snapshots/objects/<sha256>` — содержимое, хранится по хэшу и общее для всех снимков.
- **Только X-Ray**: для S2 — `Toolkit snapshots currently support X-Ray managed providers only.`
- Создание отказывает при расхождении (дрейфе):
  - `Game Fix {id} has drifted; resolve its conflict before creating a snapshot.`
  - `Managed Game Fix file changed or is missing: …`
  - `Managed user.ltx settings need review.`
- **Восстановление:**
  - сначала автоматически создаётся страховочный снимок;
  - затем исправления, компаньон и user.ltx приводятся к снимку **через своих провайдеров** (файлы из хранилища в игру не копируются);
  - после — сверка хэшей.
  - Успех: `Snapshot restored. Automatic safety snapshot: {id}.`
  - Сбой с успешным откатом: `Snapshot restore failed and the prior managed state was replayed: {msg}. Safety snapshot {id} is retained.`
  - Сбой отката: исключение `Snapshot restore failed: {msg}; automatic rollback could not finish: {msg2}. Safety snapshot {id} is retained.`
- **Удаление** — без подтверждения. Удаляется `snapshot.json`, затем объекты, на которые больше никто не ссылается (`PruneObjects`).

**Профили** (`ToolkitProfileService`):

- Хранятся в `<данные>/profiles/<id>.json`.
- Сохранение: `Toolkit profiles currently support X-Ray managed providers only.` / `Game Fix {id} has drifted; resolve it before saving a profile.`
- Применение — через `ApplyManagedState` со страховочным снимком. Успех: `Managed state applied. Automatic safety snapshot: {id}.`
- Ошибки:
  - `Choose the game this profile was created for.`
  - `Select the game's existing user.ltx before applying this profile's config overrides.`
  - `Profile change failed and the prior managed state was restored: …`
- Удаление — `File.Delete` без подтверждения.

**user.ltx** (`ManagedUserLtxSettings`):

- Правка атомарная (`AtomicGameFileWriter`).
- Исходные значения хранятся в манифесте в `<данные>/toolkit-config`.
- При ошибке файл и манифест откатываются: `Settings change failed: {msg}; rollback failed: {msg2}` (текст только если не удался и откат).
- Отказы:
  - `Choose the game's existing user.ltx file.`
  - `The selected user.ltx file does not exist.`
  - `Refusing to edit a linked user.ltx file.`
  - `The user.ltx contains more than one {key} command; no change was made.`
  - `The managed setting {key} changed outside the toolkit; review the conflict before editing.`
  - `'{key}' is not an editable, known user.ltx setting.`
  - `The value for {key} must be one token.` / `… must be 'on' or 'off'.`

**Чек-лист:**

1. Создать снимок, установить исправление, восстановить снимок → исправление удалено, в списке есть ещё один (страховочный) снимок.
2. Удалить снимок → неиспользуемые объекты из `objects/` удалены, общие с другими снимками остались.
3. Выбрать S2 → `СОЗДАТЬ СНИМОК` неактивна; при прямом вызове — `Toolkit snapshots currently support X-Ray managed providers only.`
4. Изменить `g_fov` в user.ltx вручную → применение через инструмент даёт отказ про изменение вне инструмента.

### 9. `CompanionInstaller` — мод-компаньон (`Companion/*.cs`)

#### 9.1 X-Ray (ТЧ, ЧН, ЗП и EE): `Install`

**Определение папки игры:** выбранная вручную, иначе поиск в библиотеках Steam.

**Подготовка:**

- Сначала завершается прерванная установка (`FinishInterruptedInstall` по `.save-editor-companion/transaction.json`).
- Журнал не читается → `The companion installation journal is unreadable: {path}`; неизвестный формат → `The companion installation journal has an unknown format: {path}`.
- Если манифеста нет, но файлы мода похожи на ручную установку, создаётся «ручной» манифест с бэкапами (`TryCreateManualManifest`).
- Папка состояния есть, а манифеста нет → `Cannot install companion: state directory already exists without a valid manifest: {dir}`.

**План установки:**

- файлы мода из комплекта приложения;
- хуки — правка существующих скриптов игры. Оригинал сохраняется в `.save-editor-companion/backups/<путь>.original`.

**Отказы:**

- `Cannot install Companion over an active Game Fix-managed file: {path}`
- `Refusing to overwrite an unowned game file: {path}` — файл без бэкапа, не принадлежащий моду
- `Mod asset conflicts with hook target: {path}`
- `Mod asset collides with a backed-up game file: {path}`
- `Managed hook file has no original backup: {path}`
- `Cannot create a valid backup for {path}.`

**Нет изменений** (тот же набор и хэши) → успех без записи (`Changed = false`).

**Запись:**

1. Журнал.
2. Бэкапы оригиналов (атомарно, без перезаписи).
3. Файлы мода (атомарно; совпадающие байты пропускаются).
4. Удаление устаревших файлов прежней версии мода.
5. `manifest.json` последним, затем журнал удаляется.

**Откат:** записанные файлы возвращаются, удалённые — восстанавливаются, журнал удаляется. Если откат не удался, журнал **остаётся**, и следующая операция повторит откат. Текст: `Companion installation failed: {msg}` / `… Rollback also failed: …`.

#### 9.2 X-Ray: `Uninstall`

1. Завершение прерванной установки.
2. Манифеста нет и ручной установки не найдено → успех, `Changed = false`.
3. **Предварительная проверка** без записи. Конфликты возвращаются списком, ничего не удаляется:
   - `Missing since install; left untouched: {path}`
   - `Changed since install; left untouched: {path}`
   - `Backup reference is missing; left untouched: {path}`
   - `Backup is missing or corrupt; left untouched: {path}`

   UI показывает только `Не удалось удалить компаньон.` — список конфликтов в UI **не выводится**.
4. Запись: каждый файл восстанавливается из `.original` (атомарно) или удаляется, если его не было до установки. **Журнала удаления нет.** При обрыве повторный запуск идемпотентен: уже восстановленные файлы пропускаются (`IsAlreadyUninstalled`).
5. Если `gamedata` был создан установкой и опустел, он удаляется. Иначе — сообщение `Unowned files remain under gamedata; the directory was left in place: {files}.`
6. Манифест и бэкапы удаляются.

#### 9.3 S2 (`Stalker2CompanionInstaller`)

**Причины, по которым установка невозможна:**

- `S.T.A.L.K.E.R. 2 not found in Steam libraries`
- `UE4SS is not installed in Stalker2/Binaries/Win64`
- `{target} exists but was not installed by the editor` — нет маркера `save_editor_install.json`

**Установка:**

1. Копия комплекта в `<Mods>/SaveEditorCompanion.installing`.
2. Маркер с номером сборки.
3. Старая папка переименовывается в `.previous`.
4. `.installing` переименовывается в целевую; при ошибке возвращается `.previous`.
5. `.previous` удаляется.

Отсутствует комплект → `S2 companion source is missing: {dir}`.

**Удаление** — рекурсивное удаление `<Mods>/SaveEditorCompanion` без бэкапа.

#### 9.4 Чек-лист

1. Установить на чистую ЗП → в `.save-editor-companion/` есть `manifest.json` и `backups/…original` для каждого изменённого скрипта; `transaction.json` нет.
2. Удалить → изменённые скрипты побайтно равны оригиналам; добавленные файлы удалены; `.save-editor-companion` удалена.
3. После установки вручную изменить файл мода → `УДАЛИТЬ` → `Не удалось удалить компаньон.`; ни один файл не тронут.
4. Установить исправление игры на файл, который нужен моду → установка компаньона: `Ошибка установки: Companion installation failed: …` или `Cannot install Companion over an active Game Fix-managed file: …`
5. Положить в `gamedata` посторонний файл, затем установить и удалить мод → посторонний файл остался.
6. S2 без UE4SS → строка игры `нет UE4SS: установите его, затем мод`.

### 11. Steam: запись в облако и достижения (`StalkerSaveEditor.Steam`)

Все вызовы Steam API идут через **отдельный рабочий процесс** (`SteamWorkerProcessRunner`). Таймаут одной операции 15 с (`SteamReadOnlyClient.DefaultTimeout`), запуск игровой сессии — 15–30 с. По истечении — `Steam worker exceeded the {N} second timeout.`

#### 11.1 Транзакция записи (`SteamCloudWriteTransaction.UploadAsync`)

Общая для обоих способов записи (RemoteStorage и Auto-Cloud).

**Шаги, которые ничего не меняют в облаке.** Ошибка на любом из них — исключение (в UI это будет `Ошибка записи: …`):

1. SHA-256 подготовленных байтов совпадает с записанным → иначе `Prepared output SHA256 does not match its bytes.`
2. Способ записи доступен → иначе `Cloud write is disabled before any I/O: {reason}`.
3. **Свежее чтение файла из облака** → при ошибке `Cloud read before write failed: {msg}`.
4. SHA прочитанного = `prepared.SourceSha256` → иначе `Cloud source changed after analysis: expected {a}, found {b}.`
5. **Бэкап** в переданную папку бэкапов:
   - `<stem≤80>_<stamp>_<guid>_ORIGINAL.sav` — что было в облаке;
   - `…_EDITED.sav` — что пишется.
   - Запись с `WriteThrough`, без перезаписи. **Журнал JSON не создаётся.**
   - Ошибка → `Could not create cloud backup and recovery files: {msg}`.

**Запись и результат:**

6. Запись в облако.
   - `CloudWriteNotAttemptedException` (запись точно не начиналась) → исключение `Cloud write was not attempted: {msg}`.
   - **Любая другая ошибка** → статус `Uncertain`: `WriteFile result is uncertain after request: {msg}`.
7. Синхронизация (для RemoteStorage — пустая операция) → при ошибке `Uncertain`: `Cloud sync failed after WriteFile; result is uncertain: {msg}`.
8. Ожидание флага `persisted` и совпадения размера: опрос раз в 2 с, до 120 с.
   - Не дождались → `Uncertain`: `Steam did not confirm persisted=true after WriteFile; result is uncertain.`
   - Ошибка опроса → `Uncertain`: `Persisted check failed after WriteFile; result is uncertain: {msg}`.
9. Обратное чтение из облака:
   - ошибка → `Uncertain`: `Cloud read-back failed after WriteFile; result is uncertain: {msg}`;
   - SHA не совпал → `Uncertain`: `Cloud read-back SHA256 mismatch after WriteFile; result is uncertain.`
10. Всё совпало → **`Verified`**.

**Соответствие статусам UI** (`ACCEPTANCE.md` §18):

| Ядро | UI |
|---|---|
| `Verified` | `Записано и проверено: {0}` |
| `Uncertain` + `Reason` | `Результат записи не подтверждён (повтор не выполняется): {0}` |
| исключение до шага 6 включительно (`…not attempted…`, `…changed after analysis…`, и т. п.) | в ядре статуса `Aborted` нет; перевод исключения в `Aborted` / `Запись отменена: {0}` делает хост-адаптер — **не определено из исходников** (§16) |

**Повтора нет ни в одном случае.** При `Uncertain` в папке бэкапов остаются оба файла: прежняя облачная версия и записанная.

#### 11.2 RemoteStorage (`SteamRemoteStorageCloudWriter`) — трилогия X-Ray

**Отказы до транзакции** (`SteamRemoteStorageWriteException`):

#### 11.4 Достижения (`SteamAchievementsClient`)

#### 11.5 Чек-лист

1. Записать локальный сейв ЗП в облако → статус Verified; в папке бэкапов пара `*_ORIGINAL.sav` (= прежняя облачная копия по SHA) и `*_EDITED.sav` (= локальный файл).

3. Отключить сеть сразу после начала записи → `Uncertain`, кнопка записи не повторяет операцию автоматически, оба файла бэкапа на месте.
4. Подставить путь `_appdata_/savedgames/../x.sav` (тест) → `Remote path is outside this release's save-file allow-list.`
5. Попытка записи для appId 1643320 через RemoteStorage (тест) → `RemoteStorage save writing is supported only…`
6. Steam не запущен → установка достижения: ошибка `Steam achievement operation failed: …` или `Steam worker exceeded the 15 second timeout.`

### 12. Апдейтер (`StalkerSaveEditor.Updater/UpdateService.cs`)

#### 12.1 Проверка (`CheckAsync`)

**Источники:**

- манифест `https://save-editor-downloads.save-editor.workers.dev/latest.json`, до 2 МиБ;
- подпись `latest.json.sig` рядом: ECDSA P-256 / SHA-256, формат P1363 или DER, до 1 КиБ.
- Публичный ключ встроен в `UpdateSignature.PublicKeyPem`.
- **Без валидной подписи манифест отвергается.**

**Доверенные адреса:**

- только `https`, хост `save-editor-downloads.save-editor.workers.dev`;
- без userinfo, query и fragment;
- редиректы проверяются вручную, не больше 5;
- таймаут 15 с.

**Проверка манифеста:**

- схема и канал;
- `source_commit` — lowercase SHA коммита Git;
- `published_at` — дата и время;
- для каждого артефакта:
  - `size` от 1 байта до 2 ГиБ;
  - `sha256` — lowercase;
  - `file` — простое имя без пути;
  - `kind` и `target` из допустимых;
  - URL заканчивается на `file`.

**Результаты:**

| Состояние | Когда | `Error` |
|---|---|---|
| `Current` | версия манифеста ≤ текущей | — |
| `Available` | версия манифеста больше | — |
| `Invalid` | `UpdateManifestException` | текст: `Update manifest signature is missing: …`, `Update manifest signature is invalid; the update was not trusted.`, `Unsupported update manifest schema.`, `Update URL is outside the trusted download policy.`, `No update artifact exists for {target}/{arch}/{kind}.`, … |
| `Unavailable` | сеть, таймаут, JSON, кодировка | `Update request timed out.` или `{ExceptionType}: {msg}` (например, `HttpRequestException: …`) |

**Сравнение версий** — по правилам SemVer с пререлизами. Ведущие нули в числовых идентификаторах пререлиза запрещены: `Numeric prerelease identifiers must not contain leading zeroes.`

#### 12.2 Загрузка (`DownloadAsync(artifact, destination)`)

1. Папка назначения задаётся **хостом** (§16). Если там уже лежит файл, он проверяется. Прошёл проверку → используется повторно (`Reused the verified update download.`). Не прошёл → удаляется.
2. Скачивание во временный файл `.<имя>.<guid>.part`.
   - Объявленный или фактический размер больше указанного в манифесте → `Update download is larger than the manifest size {size}.`
   - Таймаут простоя → `Update server stopped sending data.`
3. **Проверка:**
   - размер = `size`, иначе `Update artifact size mismatch: expected {a}, got {b}.`;
   - SHA-256 = `sha256` (сравнение за постоянное время), иначе `Update artifact SHA-256 mismatch.`
4. Переименование в целевой файл.
5. Любая ошибка → временный файл удаляется. Сетевые ошибки и ошибки ввода-вывода оборачиваются: `Update download failed: {msg}`.
6. Прогресс: `Downloading update.` (байты / всего), затем `Update download verified.`

#### 12.3 Установка (`InstallAsync`)

1. Тип установки определяется `UpdateInstallationDetector`:
   - Linux-пакет, если приложение лежит в `/usr/lib/stalker-save-editor`;
   - Installer / AppBundle / Portable — по манифесту упакованной сборки;
   - Development — сборка из исходников.
2. **Отказы:**
   - Development → `Update installation type is unsupported.`
   - Артефакт не соответствует типу и архитектуре установки → `Update artifact does not match the current installation.`
3. **Повторная проверка размера и SHA-256** скачанного файла непосредственно перед запуском.
4. Запуск:

| Платформа / тип | Действие | Итог |
|---|---|---|
| Windows / Installer, `.exe` | запуск `.exe`, ожидание выхода | `Succeeded` / `Failed` |
| Linux / Package, `.deb` | `pkexec apt-get install -y -- <deb>`; если нет pkexec или apt-get — `xdg-open <deb>` | `Succeeded` или `OpenedExternally`; без xdg-open → `Linux package manager handoff is unavailable (pkexec/xdg-open missing).` |
| macOS, `.dmg` | `open <dmg>` | `OpenedExternally`; без `open` → `macOS installer handoff is unavailable.` |
| Portable `.zip` / `.tar.gz` | — | `Automatic replacement of portable .zip or .tar.gz installations is not supported by this installer handoff.` |

5. **Коды выхода:**
   - 126 или 127 → `Cancelled`, `The installer authorization was cancelled.`
   - другой ненулевой → `Failed`, `Installer exited with code {n}.`
   - отмена → `Update installation was cancelled.`
   - успех → `Update installation completed.` или `The verified installer was opened.`
6. Приложение перед установкой **не закрывается**. Что делает установщик с запущенным приложением, определяет сам установщик.

**Очистка.** `CleanupStaleDownloads` удаляет во временной папке файлы, подходящие под `^SaveEditor-update-[0-9]+-.+`.

#### 12.4 Чек-лист

1. Подменить `latest.json` без `.sig` → бейдж `Ошибка проверки манифеста`, ошибка `Update manifest signature is missing: …`
2. Подменить подпись → `Update manifest signature is invalid; the update was not trusted.`
3. Артефакт с изменённым байтом → `Ошибка скачивания: Update artifact SHA-256 mismatch.`; `.part` удалён, целевого файла нет.
4. Сервер отдаёт файл больше `size` → `Update download is larger than the manifest size …`
5. Скачать, затем изменить файл на диске → `УСТАНОВИТЬ` → `Установка не удалась (Failed): Update artifact SHA-256 mismatch.`
6. Portable-сборка → установка: `Automatic replacement of portable .zip or .tar.gz installations is not supported…`
7. Linux-пакет, отмена окна pkexec → `Установка не удалась (Cancelled): The installer authorization was cancelled.`
8. Без сети → тихая проверка ничего не показывает. Ручная: `Unavailable`, текст вида `HttpRequestException: …`

### 13. Диагностика: журнал, сбой, отправка (`Diagnostics/AppLog.cs`, `DiagnosticsUploader.cs`)

**Журнал:**

- файл `<данные>/logs/save-editor.log`, ротация при 1 МиБ, хранятся 3 копии;
- в браузерной сборке журнал только в памяти.

**Сбой:**

- необработанное исключение или ненаблюдённая задача → запись в журнал и в `last-crash.txt` (обезличен, до 64 КБ);
- при закрытии приложения отмены не считаются сбоем;
- `Скрыть ошибку` удаляет `last-crash.txt`.

**Пакет отчёта** (`DiagnosticsBundle.Create`), gzip до 2 МиБ:

- заголовок с версией;
- `last-crash.txt` (до 256 КБ);
- отчёт окружения, если запускалась проверка;
- журналы (у суточного отчёта — только строки после прошлой отправки);
- хвосты логов мода S2 (до 256 КБ): `save_editor_companion.log`, `.log.old` из `%LOCALAPPDATA%/Stalker2/Saved` и из префиксов Proton.

**Обезличивание** (`AppLog.Redact`) заменяет:

- домашний каталог → `<home>`;
- `/home/<x>`, `/Users/<x>`, `C:\Users\<x>` → `<home>`;
- `drive_c/users/<x>` → `drive_c/users/<user>`;
- SteamID64 (`7656119…`) → `<steamid>`;
- `userdata/<число>` → `userdata/<id>`.

Имена файлов сейвов и пути вне домашнего каталога **не вырезаются** (§15 п.9).

**Отправка:**

- POST `https://save-editor-downloads.save-editor.workers.dev/diagnostics`, `Content-Type: application/gzip`, таймаут 30 с;
- ответ: JSON с `report_id`;
- ошибка: `report rejected: {code} {body}`.
- Суточный отчёт отправляется, если прошло ≥ 24 ч с прошлой отправки, отправок ещё не было или есть неотправленный сбой.

**Чек-лист:**

1. Вызвать сбой → после перезапуска баннер сбоя; в `last-crash.txt` нет домашнего пути.
2. `Сохранить отчёт…` → `.txt.gz` открывается; в нём `<home>` вместо домашнего пути и `<steamid>` вместо SteamID64.
3. Отправить вручную без сети → `Отчёт не отправлен: …`
4. Сервер вернул 429 → `Отчёт не отправлен: report rejected: 429 …`

### 14. Поправки к ACCEPTANCE.md

Найдены при чтении ядра. Внести в `ACCEPTANCE.md` или явно утвердить как известные расхождения.

1. **Черновик и перезапуск** (`ACCEPTANCE.md` §1.2, §1.10 п.5, §3).
   - На диске сохраняются только деньги, пачки, удаления, добавления и тайники X-Ray.
   - Прочность, апгрейды, размещение и отношения после перезапуска **пропадают молча**.
   - Чек-лист §1.10 п.5 (деньги) верен. Нужно добавить пункт «прочность после перезапуска не сохраняется» или исправить в Rust (§15 п.4).
2. **S2 не заблокирован для записи** (§1.8, §3.6 п.10, §20 п.2).
   - `CanEdit("stalker2")` = `true`; деньги, пачки и прочность S2 доступны для правки и записи (кроме 1.0.x).
   - Текст `Запись S.T.A.L.K.E.R. 2 выключена в UI…` при снимке возможностей 1.3.1 не появляется; в «Возможностях» ячейки S2 — `Эксперим.`, а не `Блок UI`.
   - Статичная подпись на экране «Возможности» `Запись сейвов S.T.A.L.K.E.R. 2 выключена…` противоречит поведению.
3. **«Восстановить на место»** (§8, §23.1 #4).
   - Работает, только пока сейв побайтно равен записанному редактором.
   - После сохранения в игре — `Ошибка восстановления: Current save changed after the journaled replacement; refusing to overwrite it.`, хотя кнопка активна.
   - Если сейва нет, восстанавливается без страховочного бэкапа.
4. **§24 п.4 — не дефект.** Перенос в тайник и из тайника X-Ray требует `add_items` (`EditService.EditCapabilities`), поэтому привязка `В ТАЙНИК` к `CanAddItems` согласована с ядром.
5. **Ошибка при изменённом файле** (§1.2, чек-лист §1.10 п.9). Если игра перезаписала сейв, ошибку даёт писатель формата: `Не удалось сохранить: X-Ray money edit: Source SHA256 does not match the edit plan.`, а не `Source changed since analysis`.
6. **Папка бэкапов внутри папки сейвов** (§22). Любая запись падает с `Backup directory must be outside the selected save directory. (Parameter 'backupDirectory')`. UI это не проверяет при вводе.
7. **Отключение модов S2** (§14, §23.3 #18) — переименование `Stalker2/Content/Paks/~mods` ↔ `Stalker2/Content/~mods.disabled`. Без копирования и удаления.
8. **Удаление исправления** (§13) оставляет бэкапы и манифест с `installed: false`. Повторная установка той же версии использует старые бэкапы.
9. **Облако** (§18):
   - каждая запись оставляет в «Бэкапах» строку `Повреждён` (бэкап без журнала);
   - EE-версии (2427410/20/30) поддерживаются ядром, но экран их не запрашивает.

### 15. Дефекты и риски ядра (решить явно при переписывании)

1. **Права сейва после записи.** `ReplaceLocal` и `RestoreInPlace` подменяют сейв временным файлом с правами `0600`. Исходные права и владелец сейва не сохраняются. Для Proton с тем же пользователем это безопасно; при другом пользователе игра потеряет доступ.
2. **Остатки неудачных записей.** Ошибка `ReplaceLocal` после создания артефактов и до замены оставляет `_ORIGINAL`, `_EDITED` и журнал `prepared`. В UI это строки `Повреждён`, очистки нет.
3. **Неполная проверка после записи.** `VerifyReadBack` не проверяет прочность, апгрейды, размещение, отношения, удаление и добавление. Проверка до записи (`PrepareEdit`) использует ту же функцию, поэтому эти правки не проверяются вообще.
4. **Черновик неполный** (§6.2). Также `HasChanges` не видит эти поля, поэтому черновик только из них удаляется.
5. **Нет автоматического отката** после замены сейва, если обратное чтение не прошло. Журнал остаётся `prepared`, UI восстановить не может.
6. **Журнал сейва** хранит только `money` и `stack_count`. Состав правки по нему не восстановить.
7. **`ВСЕ БЕЗОПАСНЫЕ` = `РЕКОМЕНДУЕМЫЕ`.** Исправления Community недоступны через пресеты.
8. **Удаление компаньона без журнала.** Корректность держится на идемпотентном повторе. Список конфликтов теряется в UI.
9. **Обезличивание неполное.** Имена файлов сейвов (`save written quicksave.sav …`) и пути вне домашней папки уходят в отчёт.
10. **Облачные бэкапы без журналов** — видны в UI как повреждённые, восстановить из UI нельзя.
11. **Загрузка обновления** пишет `.part` без fsync, а финальное переименование — обычный `File.Move` без `DurableFile`.
12. **S2 Auto-Cloud.** Готовый код не задействован. Решить: удалить или подключить.

### 16. Что не определено и после чтения ядра

Хост-адаптеры (`HostPlatform.CreateCloudService`, `CreateAchievementsService`, `CreateUpdateService`) не входят ни в архив интерфейса, ни в архив ядра. Поэтому не определены:

- как исключения ядра облака превращаются в статус `Aborted` и текст `Запись отменена: {0}`;
- какой `PreparedEdit` хост строит для записи в облако (`SourceSha256` облачной копии ожидается, но не подтверждено);
- папка, в которую хост скачивает обновления. По шаблону очистки это вероятно `<temp>/SaveEditor-update-<pid>-<файл>`, но не подтверждено;
- откуда хост берёт список облачных файлов и сравнение с локальными (`ListCloudFilesAsync`, `CloudComparison`);
- выбор `ISteamCloudWebReader` для S2 Auto-Cloud;
- формат и путь файла раскладки горячих клавиш компаньона (`Core/Hotkeys/HotkeyLayout.cs` в архиве есть, но в этот документ не разобран).

### 2. Облако (`CloudServiceAdapter`)

#### 2.1 Доступность Steam

- `IsSteamAvailable` = удалось найти `libsteam_api`. Проверка идёт через `SteamRemoteStorageCloudWriter.CheckAvailability(41700)`, результат кэшируется на 10 с.
- **Работает ли клиент Steam, не проверяется.**
- Текст статуса:
  - найдено → `Steam доступен.` (с точкой);
  - иначе → причина из ядра (`Steam libsteam_api was not found.` / `Could not locate Steam libsteam_api: …`);
  - исключение → `Steam недоступен: {msg}`.

#### 2.2 Список облачных файлов (`ListCloudFilesAsync`)

**Сопоставление с локальными сейвами.**

- На вход приходят пути сейвов **этой игры** из библиотеки.
- Связь облачного и локального файла — **по имени файла** без учёта регистра.
- Связь создаётся, только если локальный файл с этим именем **ровно один**. Если одинаковых имён два и больше (например, два профиля), связи нет. Тогда скачивание не заменит локальный файл, а положит копию в `cloud_downloads`.

**Трилогия (4500, 20510, 41700)** — RemoteStorage через рабочий процесс Steam (`SteamReadOnlyClient.ListAsync`):

- берутся только файлы `*.sav` и `*.scop`; **`*.scs` пропускаются**;
- время облачного файла — Unix-секунды; если 0, времени нет;
- **любая ошибка** (Steam не запущен, игра не куплена, таймаут) → **пустой список**, в журнал `cloud list {appId} failed: {msg}`. UI покажет `В Steam Cloud не найдено сохранений для выбранных игр.`

**S2 (1643320)** — **не облако, а локальная папка Auto-Cloud**:

- Windows: `%LOCALAPPDATA%`;
- Linux: `<библиотека Steam>/steamapps/compatdata/1643320/pfx/drive_c/users/<user>/AppData/Local` или `…/Local Settings/Application Data`;
- рекурсивно `Stalker2/**/*.sav`;
- удалённый путь — путь относительно корня, через `/`;
- нет корня или папки `Stalker2` → пустой список.

**Сравнение с локальным** (`CompareWithLocal`):

| Условие | Результат (бейдж UI) |
|---|---|
| нет единственного локального файла с таким именем | `RemoteOnly` — `Только в облаке` |
| время облака известно, \|Δt\| < 2 с и размеры равны | `Identical` — `Размер и время совпадают` |
| облако новее больше чем на 2 с | `RemoteNewer` — `Облачный новее` |
| иначе (в том числе \|Δt\| < 2 с при разном размере) | `LocalNewer` — `Локальный новее` |
| времени облака нет | `Unknown` — `Неизвестно` |
| ошибка чтения локального файла | `Unknown` |

`LocalOnly` (`Только локально`) адаптер **не выдаёт никогда**: локальные файлы без облачной пары в список не попадают.

#### 2.3 Чтение (`ReadCloudFileAsync`) — для «СКАЧАТЬ В ЛОКАЛЬНЫЕ»

- **Трилогия** — `SteamReadOnlyClient.ReadAsync(remotePath)` через рабочий процесс.
- **S2** — **чтение локального файла** `<корень Auto-Cloud>/<remotePath>`. Нет корня → `S.T.A.L.K.E.R. 2 Auto-Cloud folder was not found.`
- Для S2 «скачивание» копирует файл из папки сейвов игры поверх того же или одноимённого файла библиотеки. Правило бэкапа и замены — как в `ACCEPTANCE-CORE.md` §4.4.

#### 2.4 Запись (`WriteCloudFileAsync`) — для «ЗАПИСАТЬ»

1. **S2** → сразу `Aborted`, без чтения и записи: `Запись S.T.A.L.K.E.R. 2 в облако выключена до проверки в игре.` До этого не доходит: UI блокирует кнопку для 1643320.
2. **Трилогия:**
   1. Адаптер **сам** читает текущий облачный файл (`ReadAsync`).
   2. Строит `PreparedEdit.Replacing(sha256(облачная копия, прочитанная сейчас), локальные байты)`. План пустой; данные — локальный файл как есть, без правок.
   3. `SteamRemoteStorageCloudWriter.WriteAsync(appId, prepared, remotePath, backupDirectory)`. Ядро ещё раз читает облако и сверяет SHA (`ACCEPTANCE-CORE.md` §11.1 шаг 4).
3. **Перевод результата в UI:**

| Ядро | `CloudWriteStatus` | `Message` адаптера | Строка статуса UI |
|---|---|---|---|
| `Verified` | `Verified` | `Записано в Steam Cloud и прочитано обратно.` | `Записано и проверено: Записано в Steam Cloud и прочитано обратно.` |
| `Uncertain` | `Uncertain` | `Steam не подтвердил запись: {reason}. Повтор не выполняется, облачный бэкап: {путь ORIGINAL или —}` | `Результат записи не подтверждён (повтор не выполняется): Steam не подтвердил запись: …` |
| **любое исключение**, в том числе `SteamRemoteStorageWriteException`, ошибка чтения на шаге 2.1, таймаут рабочего процесса | `Aborted` | `Ошибка записи в Steam Cloud: {msg}` | `Запись отменена: Ошибка записи в Steam Cloud: {msg}` |
| S2 | `Aborted` | `Запись S.T.A.L.K.E.R. 2 в облако выключена до проверки в игре.` | `Запись отменена: Запись S.T.A.L.K.E.R. 2 в облако выключена до проверки в игре.` |

- Адаптер **не бросает исключений** (кроме `OutOfMemory` и проверки аргументов).
- Ветка UI `Ошибка записи: {0}` срабатывает только на проверке SHA локального файла, которую делает сам UI: `Локальный файл изменился после запроса записи; подтвердите запись ещё раз.`
- **Важно:** защита от изменения облака работает только в окне между чтением адаптера (шаг 2.1) и чтением ядра — это миллисекунды. Изменение облачной копии **после того, как пользователь открыл список и до нажатия «ЗАПИСАТЬ», не обнаруживается**: облако будет перезаписано. Прежняя облачная версия остаётся только в бэкапе `_ORIGINAL.sav` (поправка П-3).

#### 2.5 Читатель S2 Auto-Cloud

Хост **не создаёт** ни `SteamAutoCloudWriter`, ни `ISteamCloudWebReader`. Код ядра для S2 Auto-Cloud (`ACCEPTANCE-CORE.md` §11.3) в 1.3.1 недостижим из приложения.

#### 2.6 Чек-лист

1. Steam закрыт, `libsteam_api` установлен → экран «Облако»: `Steam доступен.`; `ОБНОВИТЬ СПИСОК` → `В Steam Cloud не найдено сохранений для выбранных игр.`; в журнале `cloud list 41700 failed: …`
2. Steam запущен, ЗП, `quicksave.sav` и в облаке, и локально (одна копия) → бейдж по времени; у строки виден удалённый путь `_appdata_/savedgames/quicksave.sav`.
3. Два локальных профиля ЗП с файлами `quicksave.sav` → бейдж `Только в облаке`, кнопка `ЗАПИСАТЬ В ОБЛАКО...` неактивна; скачивание кладёт файл в `<бэкапы>/cloud_downloads/quicksave.sav`.
4. В облаке ЧН есть `*.scs` → в списке его нет.
5. S2 → список — файлы из локальной папки `Stalker2`; скачивание файла, связанного с библиотекой, даёт бэкап и неизменённый файл (байты совпадают).
6. Записать в облако ЗП → `Записано и проверено: Записано в Steam Cloud и прочитано обратно.`
7. Закрыть Steam между открытием подтверждения и `ЗАПИСАТЬ` → `Запись отменена: Ошибка записи в Steam Cloud: …`; облако не изменено; бэкапа нет.
8. Изменить облачную копию с другого ПК после открытия списка, затем записать → запись **проходит**; прежняя версия есть только в `*_ORIGINAL.sav` в папке бэкапов.

### 4. Обновления (`UpdateServiceAdapter`)

#### 4.1 Создание

- `UpdateInstallationDetector.Detect()` и `new UpdateService(версия, установка)`.
- **Ошибка определения установки** (`UpdateManifestException`, `IOException`, `UnauthorizedAccessException`, `PlatformNotSupportedException`) → служба не создаётся, причина запоминается.
- **Папка загрузки:** `<временная папка>/stalker-save-editor-updates/<artifact.file>`, например `/tmp/stalker-save-editor-updates/StalkerSaveEditor-1.3.2-linux-x64.deb`.
  - Эта папка **не попадает** под шаблон очистки `^SaveEditor-update-[0-9]+-.+` (`ACCEPTANCE-CORE.md` §12.3). Скачанные пакеты не удаляются никогда. Повторная загрузка того же файла переиспользуется после проверки SHA.

#### 4.2 Методы

- **`CheckAsync`** — перевод состояния по номеру enum (`Current`, `Available`, `Unavailable`, `Invalid` — порядок совпадает) и `Error`.
- **Служба не создана** → `PlatformNotSupportedException`:
  - текст `Updates are not available: {причина}` или `Updates are not available on this platform.`;
  - тихая проверка на старте: ничего не видно;
  - ручная: ошибка `Updates are not available: …`, статус `Ошибка подключения к серверу обновлений.`, **бейдж остаётся `У вас актуальная версия`** (поправка П-6).
- **`DownloadAsync`** — `UpdateService.DownloadAsync(артефакт, папка загрузки/файл)`; прогресс пересылается в поток вызывающего.
- **`InstallAsync`** — `UpdateService.InstallAsync`; состояния `Succeeded`, `Cancelled`, `Failed`, `OpenedExternally` переводятся по номеру (порядок совпадает).

#### 4.3 Чек-лист

1. Скачать обновление → файл `<tmp>/stalker-save-editor-updates/<имя из манифеста>`, SHA = манифест.
2. Перезапуск и повторное скачивание → прогресс сразу 100 % (`Reused the verified update download.`).
3. Сборка из исходников (Development) → ручная проверка: `Updates are not available: …` / `Ошибка подключения к серверу обновлений.`
4. Через неделю после установки обновления папка `stalker-save-editor-updates` по-прежнему содержит пакет (очистки нет).

### 5. Компаньон: папка игры, выдача предмета, горячие клавиши (`CompanionServiceAdapter`, `Core/Hotkeys`)

#### 5.1 Ручная папка игры

- `SetUserGameDirectory(игра, путь)` хранит путь **только в памяти** процесса. В `settings.json` и другие файлы он **не пишется**; после перезапуска снова используется автопоиск.
- При смене папки работающие горячие клавиши этой игры останавливаются (`hotkeys off`) до запуска новых.

#### 5.2 Выдача предмета (Энциклопедия → `В игру`)

- Протокол: `give <секция> <кол-во>`, количество 1.
- Условия: мод `Installed` или `Active`; иначе — `Companion is not installed for this game.` или причина из статуса.
- Папка игры не определена → `The game directory could not be resolved.`
- Успех и текст ответа берутся из `reply.Status` и `reply.Text` мода.

#### 5.3 Раскладка горячих клавиш (`HotkeyLayout`)

- **Путь:** `<данные>/hotkeys.txt` (`HotkeyLayout.DefaultPath`).
- **Формат** — текст UTF-8, по строке на действие: `действие=Модификаторы+Буква`.
  - Пустые строки и строки, начинающиеся с `#`, пропускаются.
  - Действия: `heal`, `repair_equipped`, `mark`, `jump_last`, `quicksave`.
  - Модификаторы: `Ctrl` (или `Control`), `Alt`, `Shift`, хотя бы один.
  - Клавиша — одна буква A–Z.
- **По умолчанию** (файла нет или он повреждён — используется **молча**):

```
heal=Ctrl+H
repair_equipped=Ctrl+R
mark=Ctrl+M
jump_last=Ctrl+J
quicksave=Ctrl+S
```

- Подписи в UI:
  - `Быстрое лечение и снятие радиации`
  - `Починка экипированного оружия и брони`
  - `Поставить метку на текущем месте`
  - `Мгновенный прыжок к последней телепорт-метке`
  - `Быстрое сохранение с меткой времени`
- **Ошибки разбора** (UI: `Клавиши не сохранены: {msg}`):
  - `Hotkey line {n} must use action=Ctrl+Key syntax.`
  - `Unknown hotkey action '{a}' on line {n}.`
  - `Hotkey action '{a}' is configured more than once.`
  - `Invalid hotkey on line {n}: {причина}`
  - `Hotkey '{g}' is assigned more than once.`
  - `At least one hotkey binding is required.`
  - Причины: `Hotkey '{t}' must include a modifier and one letter.`, `Unknown hotkey modifier '{m}'.`, `Hotkey '{t}' repeats modifier '{m}'.`, `Hotkey '{t}' must end in one A-Z letter.`
- **Сохранение** — атомарно (`AtomicFile.WriteAllText`). Если клавиши этой игры активны, они перезапускаются (выключить, затем включить с новой раскладкой).

#### 5.4 Работа горячих клавиш

- Включение посылает моду `hotkeys on`, выключение — `hotkeys off`. Отказ мода → `{операция} failed: {статус} {текст}`.
- Клавиши **регистрируются, только пока на переднем плане окно игры X-Ray**: процесс или класс окна `xr_3da`, `xrengine`, `steam_app_4500`, `20510`, `41700`, `2427410`, `2427420`, `2427430`. В других программах Ctrl+S, Ctrl+R и т. п. работают как обычно. Если клавишу заняла другая программа, повторная попытка — каждые 10 проверок.
- Платформы:
  - Windows — `RegisterHotKey`;
  - Linux — X11 или XWayland через помощника.
  - Wayland без XWayland → `Горячие клавиши требуют X11 или XWayland. Сеанс Wayland без XWayland не поддерживается.`
  - Прочие → `Горячие клавиши поддерживаются только на Windows и Linux (X11/XWayland).`
- Ошибка команды мода по клавише запоминается как `Game returned {статус}: {текст}`.

#### 5.5 Чек-лист

1. Задать папку игры вручную и перезапустить → поле пустое, используется автопоиск.
2. Без `hotkeys.txt` → список клавиш показывает 5 сочетаний по умолчанию.
3. Записать в `hotkeys.txt` строку `heal=H` → UI показывает раскладку по умолчанию (файл молча игнорируется).
4. Назначить два действия на `Ctrl+H` → `Клавиши не сохранены: Hotkey 'Ctrl+H' is assigned more than once.`
5. Включить клавиши, переключиться в текстовый редактор, нажать Ctrl+S → редактор сохраняет файл, игра не реагирует.
6. Вернуться в игру, нажать Ctrl+H → лечение в игре.
7. Сеанс Wayland без XWayland → переключатель неактивен, причина про X11/XWayland.

### 7. Поправки к ACCEPTANCE.md и ACCEPTANCE-CORE.md

**П-1. ACCEPTANCE.md §18 «Облако» — S2.**

- Список S2 — локальные файлы папки `Stalker2` (Auto-Cloud), а не облако Steam.
- Бейдж обычно `Размер и время совпадают`: файл сравнивается сам с собой, если путь библиотеки совпадает. Если имя неоднозначно — `Только в облаке`.
- «Скачать» для S2 — копия локального файла поверх локального, с бэкапом.
- **Решить:** скрыть S2 в «Облаке» или подключить настоящее чтение облака.

**П-2. ACCEPTANCE.md §18.4 — статус Steam.**

- `Steam доступен.` означает только «найден `libsteam_api`». При закрытом клиенте Steam список пуст без ошибки.
- Пустое состояние `В Steam Cloud не найдено сохранений…` не отличает «нет сейвов» от «Steam недоступен».

**П-3. ACCEPTANCE-CORE.md §11.5 п.2 — неверен.**

- Изменение облака между открытием экрана и записью **не обнаруживается**: адаптер берёт базовый SHA из собственного чтения прямо перед записью.
- Правильная формулировка: «Изменение облачной копии в окне между чтением адаптера и чтением ядра → `Запись отменена: Ошибка записи в Steam Cloud: Cloud source changed after analysis…`». Вручную это не воспроизвести.
- Защиту в духе C# — SHA облачной копии, привязанный к намерению вместе с SHA локального файла — **рекомендуется добавить в Rust**.

**П-4. ACCEPTANCE.md §18 — тексты статусов** заменить точными:

- `Записано и проверено: Записано в Steam Cloud и прочитано обратно.`
- `Результат записи не подтверждён (повтор не выполняется): Steam не подтвердил запись: {reason}. Повтор не выполняется, облачный бэкап: {путь}`
- `Запись отменена: Ошибка записи в Steam Cloud: {msg}`

Вариант `Ошибка записи: {0}` после подтверждения возможен только для `Локальный файл изменился после запроса записи…`.

**П-5. ACCEPTANCE.md §18 — расширения и бейджи.**

- Файлы `*.scs` (ЧН, ЧН EE, ЗП EE) в облачный список не попадают.
- Бейджа `Только локально` в 1.3.1 не бывает.

**П-6. ACCEPTANCE.md §21 «Обновления».**

- Если тип установки не определён (сборка из исходников, неизвестная платформа), ручная проверка показывает `Ошибка подключения к серверу обновлений.` и `Updates are not available: …`, а бейдж остаётся `У вас актуальная версия`.
- Это вводит в заблуждение. Правильное поведение: состояние `Unavailable` и текст `Обновление недоступно`.

**П-7. ACCEPTANCE-CORE.md §12.3, §16.**

- Папка загрузки — `<temp>/stalker-save-editor-updates/`.
- `CleanupStaleDownloads` её не касается, пакеты копятся.

**П-8. ACCEPTANCE.md §16 «Компаньон» — «Применить папку».**

- Папка не сохраняется между запусками (раньше было «не определено»).
- Горячие клавиши действуют только при фокусе окна игры.
- Раскладка по умолчанию: `Ctrl+H`, `Ctrl+R`, `Ctrl+M`, `Ctrl+J`, `Ctrl+S`.
- Повреждённый `hotkeys.txt` молча заменяется значениями по умолчанию при чтении; сам файл не перезаписывается до «СОХРАНИТЬ КЛАВИШИ».

**П-9. ACCEPTANCE-CORE.md §11.3.** Auto-Cloud для S2 недостижим из приложения (хост его не создаёт). Пункт §15 п.12 «удалить или подключить» остаётся в силе.

**П-10. ACCEPTANCE-CORE.md §16** закрыт полностью; таблица в §6 этого документа.
