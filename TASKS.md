## Как работаем

- Постоянного закрепления каталогов, крейтов и файлов за исполнителями нет. Меняй все части репозитория,
  требуемые задачей, включая `sse-ui`, `.github/workflows/ci.yml` и `tools/`. В таблице ниже могут быть временные
  назначения отдельных задач; это не ограничение доступа к коду.
- PR проверяет и вливает локальный Claude (интегратор) — решение владельца. Исполнитель свои PR не вливает; ключи
  подписи и выпуск остаются у владельца.
- Правила работы (`AGENTS.md`, этот раздел), обязательные проверки CI и защита веток меняются только по решению
  владельца; исполнитель предлагает изменение отдельным PR и не вливает его.
- `main` защищён: только PR, зелёные `check (ubuntu-24.04)`, `check (windows-latest)`, `check (macos-14)`.
- Одна задача = одна ветка `wp/<ID>-<кратко>` от свежего `origin/main` = один PR. Не открывать дубликат для той же
  задачи; отдельно пронумерованный follow-up после влитого PR получает свою ветку и PR.
- Перед пушем: `cargo fmt --all`, `cargo clippy -D warnings` и тесты **затронутых крейтов** (`-p <крейт>`); для
  `sse-sys` ещё `cargo clippy -p sse-sys --target x86_64-pc-windows-gnu -- -D warnings`. Полный
  `cargo test --workspace` гоняет CI. На машине владельца 6,6 ГБ ОЗУ и приложение уже падало по памяти:
  `cargo -j2`, одна сборка за раз (`pgrep -a cargo` — идёт чужая, подожди), свой `CARGO_TARGET_DIR`.
- Любой запуск редактора или CLI с записью, даже на копии сейва, — с `STALKER_SAVE_EDITOR_DATA` или
  `XDG_DATA_HOME`/`XDG_CONFIG_HOME` во временной папке: общая папка резервных копий хранит 100 наборов и
  вытесняет настоящие.
- Живые проверки игры, Steam Cloud и достижений разрешены, когда их прямо разрешил владелец. Перед ними копируй
  исходное состояние, проверяй только копию и возвращай оригинал. В PR указывай, что проверено запуском, а что —
  только кодом или фикстурами.
- Нельзя трогать ключ подписи. Корневые `.md` — только README, AGENTS, PLAN, TASKS и ACCEPTANCE; витринные документы
  лежат в `docs/` (решение владельца 2026-10-10: ограничение «только пять документов» для `docs/` снято).

## Выпуск релиза (владелец или его локальный Claude с доступом к ключу)

Облачные агенты ключ не трогают. Ключ подписи — `~/.config/stalker-save-editor/update-signing-key.pem`; его
открытый ключ совпадает с `PUBLIC_KEY_PEM` в `crates/sse-update/src/signature.rs` (сверено 2026-10-06).

1. Actions → `ci` → Run workflow на нужном коммите (или тег `v<версия>`): задача `packages` даёт
   `packages-Linux` (tar.gz, deb, Windows zip) и `packages-macOS` (dmg).
2. Скачать оба артефакта в одну папку `dist/`, затем `tools/package.sh --manifest-only` → `dist/latest.json` и
   пустой `dist/latest.json.sig`.
3. Подпись (ECDSA P-256/SHA-256, DER, base64):
   `openssl dgst -sha256 -sign ~/.config/stalker-save-editor/update-signing-key.pem dist/latest.json | base64 -w0 > dist/latest.json.sig`.
   Перед первой подписью: `openssl pkey -in <ключ> -pubout` должен совпасть с `PUBLIC_KEY_PEM`.
4. Выкладка в R2 (`CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`):
   `npx wrangler r2 object put save-editor-downloads/<файл> --file dist/<файл> --remote` для каждого пакета;
   **`latest.json.sig`, затем `latest.json` — последними**. Образец всей процедуры —
   `tools/release/publish_release.py` в старом C#-репозитории.
5. Проверка: `curl -sI https://save-editor-downloads.save-editor.workers.dev/latest.json`; старая версия
   редактора должна предложить обновление.

Отчёты об ошибках пользователей лежат в том же бакете, папка `diagnostics/`.
